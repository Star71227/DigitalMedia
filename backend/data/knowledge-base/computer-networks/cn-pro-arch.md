# 网络体系结构

## 计算机网络的概念

计算机网络是由若干具有独立计算能力的结点（主机、终端、路由器等）通过通信链路互联起来，遵循共同的协议进行数据交换，从而实现资源共享与信息传递的系统。这里有两个要点必须同时满足：一是结点具有自治性，即每台主机都能独立运行自己的程序，被动从属的终端集合不构成网络；二是必须遵循事先约定的协议，否则设备即使物理相连也无法互通。从功能上，计算机网络提供连通性和共享性两大服务：连通性使上网用户可以彼此交换信息，共享性则让用户能够共用硬件、软件与数据资源。在现代网络中，互联网（Internet）是把众多异构网络通过 TCP/IP 协议族互联而成的"网络的网络"，它本身不是单一网络，而是网际互联的产物。

## 计算机网络的分类

按覆盖范围与作用域，计算机网络通常分为个人区域网（PAN，约 10 m 内）、局域网（LAN，几十米到几公里，通常为一个单位所有）、城域网（MAN，覆盖一座城市，约 5~50 km）、广域网（WAN，跨越城市与国家，几十到几千公里）。按使用者可分为公用网与专用网，专用网如军队、铁路、银行内部网络不向外部开放。按交换技术可分为电路交换网、报文交换网与分组交换网，当前互联网采用分组交换。按拓扑结构可分为总线型、星型、环型、树型与网状型，广域骨干网多采用网状拓扑以提高冗余度，局域网则普遍采用星型拓扑配合交换机。按传输技术可分为广播式网络（共享信道，需解决介质访问冲突）与点对点网络（每条链路只连接一对结点）。

## 性能指标：速率与带宽

速率指数据的传输速率，也称数据率或比特率，单位是 bit/s（比特每秒），常用 k、M、G、T 作量级前缀。在计算机网络中这些前缀按十进制计算：1 kb/s = 10³ bit/s，1 Mb/s = 10⁶ bit/s，1 Gb/s = 10⁹ bit/s，这与存储容量按 2¹⁰ 计算的习惯不同，容易出错，必须分清。带宽原本指信号具有的频带宽度，单位是赫兹；在计算机网络中带宽用来表示网络中某通道传送数据的能力，即"最高数据率"，单位也是 bit/s。因此"带宽 100 Mb/s"意味着链路在理想情况下的最高传输速率为每秒一亿比特，实际速率受协议开销、拥塞与差错等因素影响会低于该值。

## 时延的四个组成部分

时延指数据从网络一端传到另一端所需的时间，由四部分组成。发送时延（传输时延）是主机或路由器把数据帧的全部比特发送到链路上所需的时间，等于数据帧长度除以发送速率，速率越高发送时延越小。传播时延是电磁波在信道中传播一定距离所花的时间，等于信道长度除以电磁波在信道上的传播速率，铜缆与光纤中约为 2×10⁸ m/s，卫星链路则大得多。处理时延是主机或路由器收到分组后分析首部、提取数据、进行差错检验或查找转发表所花的时间。排队时延是分组在路由器输入队列与输出队列中等待处理与转发的时间，网络拥塞时排队时延会急剧增大，甚至导致分组被丢弃。总时延为四者之和。

## 时延带宽积与往返时间 RTT

时延带宽积是传播时延与带宽的乘积，表示一条链路上"正在传播中的比特"的数量，可以形象地理解为以比特为单位的链路长度。例如某链路传播时延为 20 ms、带宽为 100 Mb/s，则时延带宽积为 2×10⁶ bit，即链路上同时容纳了两百万个比特。只有当发送方连续发送足够多的数据把这条"管道"填满时，链路利用率才充分。往返时间 RTT 指从发送方发送数据开始，到发送方收到来自接收方的确认（接收方收到数据后立即发送确认）总共经历的时间，它包含往返的传播时延、中间结点的处理与排队时延以及确认分组的发送时延。RTT 是衡量交互式应用响应速度的关键指标，也是 TCP 设定超时重传时间的重要依据。

## 利用率与吞吐量

信道利用率指某信道有百分之几的时间是被利用的（即有数据通过）；网络利用率则是全网络信道利用率的加权平均值。利用率并非越高越好：根据排队论结论，若某信道空闲时的时延为 D₀，当前利用率为 U，则当前时延 D ≈ D₀/(1−U)。当利用率接近 1 时时延会趋向无穷大，因此实际网络必须留有余量，一般骨干网利用率控制在 50% 以下。吞吐量表示在单位时间内通过某个网络、信道或接口的实际数据量，单位同样是 bit/s。吞吐量受网络带宽或网络额定速率的限制，且往往由链路中最慢的一段（瓶颈链路）决定，因此瞬时吞吐量通常小于带宽。利用率与吞吐量结合，可衡量网络在"有多少容量"和"实际送出多少"两个方面的表现。

## 为什么要分层

计算机网络要解决的问题极其复杂：既要面对多种传输介质与硬件，又要支持形态各异的应用。分层的思想是把庞大而复杂的问题分解为若干较小的、易于处理的局部问题，每一层只实现一种相对独立的功能，并向上层提供服务、使用下层提供的服务。分层带来若干好处：各层之间相互独立，高层无须知道低层的实现细节；灵活性好，某层内部实现变化时只要接口不变，上下层不受影响；结构上可分割，便于各层分别设计与实现；易于实现和维护，也便于标准化，使不同厂商的设备能够互通。分层也有代价，即每层都要加上首部带来额外开销，且功能可能重复。分层应使层数适中：层太少则每层功能庞杂，层太多则系统开销大。

## OSI 七层模型

OSI（开放系统互连基本参考模型）由 ISO 提出，自下而上为物理层、数据链路层、网络层、传输层、会话层、表示层、应用层。物理层在传输介质上透明地传送比特流，解决电压、接口、同步等问题；数据链路层把物理链路改造成无差错的逻辑链路，负责成帧、差错检测与介质访问控制；网络层负责分组转发与路由选择，实现异构网络互联；传输层为两个主机中的进程提供端到端的逻辑通信，并进行复用分用、可靠传输、流量与拥塞控制；会话层管理会话的建立、维持与同步；表示层处理数据格式转换、加密与压缩；应用层直接为用户的应用进程提供服务。低三层面向通信子网，高三层面向资源子网，传输层是二者的桥梁。

## TCP/IP 四层模型与五层模型

TCP/IP 模型是互联网实际使用的体系结构，通常划分为四层：网络接口层（链路层）、网际层（IP 层）、传输层、应用层。网络接口层对应 OSI 的物理层与数据链路层，负责与硬件打交道；网际层提供无连接的分组传送服务，核心协议是 IP；传输层提供端到端的进程通信，包括 TCP 与 UDP；应用层包含 HTTP、DNS、SMTP 等具体协议。由于 OSI 的物理层与数据链路层职责差别很大，教学中常采用折中的五层模型：物理层、数据链路层、网络层、传输层、应用层。需要注意的是，TCP/IP 的应用层把 OSI 的会话层与表示层功能合并了进来，因此"应用层"并不等同于 OSI 的应用层，它包含的功能更宽。学习时应掌握五层模型，因为它既清晰又贴近实际。

## 各层功能与协议数据单元

每层交付给上层的数据单元都有专门的名称，称为该层的协议数据单元（PDU）。物理层处理的是比特（bit），PDU 为比特流；数据链路层的 PDU 是帧（frame），包含帧头、数据部分与帧尾，帧尾中通常含有差错检验字段；网络层的 PDU 是分组（packet，又称 IP 数据报），首部中含源地址、目的地址、生存时间等；传输层的 PDU 根据协议不同称为报文段（TCP segment）或用户数据报（UDP datagram）；应用层的 PDU 一般统称为报文（message）。各层功能的对应关系可概括为：物理层传比特，数据链路层传帧并做差错检测与介质访问控制，网络层负责分组转发与路由选择，传输层负责进程到进程的通信，应用层负责为用户提供具体应用服务。牢记 PDU 名称是分析封装关系的基础。

## 协议与服务

协议是控制两个对等实体进行通信的规则的集合。协议由三要素组成：语法，即数据与控制信息的结构与格式；语义，即需要发出何种控制信息、完成何种动作以及做出何种应答；同步，即事件实现顺序的详细说明。服务是由下层向上层通过层间接口提供的功能调用，它描述的是相邻两层之间的关系，是垂直方向的；而协议描述的是不同主机的对等层之间的通信规则，是水平方向的。二者关系的关键结论是：只有本层协议的实现才能保证向上层提供服务；上层使用下层提供的服务时必须遵循下层的服务规范，但上层并不知道下层是如何实现的。服务在形式上通过一组原语（如请求、指示、响应、证实）来使用，服务分为面向连接的服务与无连接的服务。

## 面向连接与无连接

面向连接的服务在通信前必须先建立连接，通信过程中数据按序传送，通信结束后释放连接，整个过程分为连接建立、数据传输、连接释放三个阶段，典型例子是 TCP 与虚电路服务。面向连接的服务又可分为可靠的和不可靠的两种：可靠服务依靠确认与重传机制保证数据无差错、不丢失、不重复且按序到达。无连接的服务不需要事先建立连接，每个分组独立选择路由并独立发送，可能沿不同路径到达、可能失序、可能丢失，典型例子是 UDP 与 IP 数据报服务。无连接服务灵活、开销小、时延小，适合实时性与短报文场景；面向连接服务可靠但开销大、时延相对高，适合文件传输等对正确性要求严格的场景。网络层选择无连接方式，把可靠性交给端系统的传输层，这是互联网设计的重要思想。

## 封装与解封装

数据自上层向下层传递时，每一层都会把上一层交下来的数据（PDU）当作本层的数据载荷，并在前面加上本层的控制信息（首部），有时还要加尾部，这一过程称为封装。应用层报文交给传输层后加上 TCP 或 UDP 首部成为报文段；交给网络层后加上 IP 首部成为 IP 数据报；交给数据链路层后加上帧首部与帧尾部成为帧；最后物理层把帧转换为电信号、光信号或电磁波发送出去。接收方则执行相反的过程，即解封装：物理层还原出比特流并交给数据链路层，数据链路层去掉帧首尾并检验差错后把数据部分交给网络层，网络层去掉 IP 首部后交给传输层，传输层去掉首部后把数据交给对应的应用进程。需要特别注意，封装过程中分组的地址在变化：帧的地址是链路层 MAC 地址，IP 数据报的地址是端到端的 IP 地址。

## 网络设备与工作层次

不同网络设备工作在体系结构的不同层次上，这是判断其功能的重要依据。工作在物理层的设备有中继器与集线器（hub）：中继器对衰减的信号进行整形放大后转发，仅扩展传输距离；集线器本质是多端口中继器，工作在共享信道模式下，所有端口处于同一冲突域与同一广播域，带宽被所有端口共享。工作在数据链路层的设备有网桥与交换机（switch）：它们根据 MAC 地址转发帧，能隔离冲突域，每个端口独享带宽，但不能隔离广播域。工作在网络层的设备是路由器（router）：根据 IP 地址选路并转发分组，能隔离广播域，实现异构网络互联。网关（gateway）工作在更高层，用于连接体系结构不同或协议差异很大的网络，需要在应用层进行协议转换。这一层次对应关系也解释了为什么"交换机能扩展网络但无法抑制广播风暴"。
