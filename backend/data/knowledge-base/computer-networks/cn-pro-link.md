# 数据链路层与差错控制

## 数据链路层的基本功能

数据链路层在物理层提供服务的基础上向网络层提供服务，其主要作用是加强物理层传输原始比特流的功能，将物理层提供的可能出错的物理连接改造为逻辑上无差错的数据链路。具体功能包括：链路管理，即数据链路的建立、维持与释放；封装成帧，把网络层交下来的分组加上帧首部与帧尾部以确定帧的边界；透明传输，使数据中出现的任何比特组合都能被正确传送而不被误认为控制信息；差错检测，通过校验码发现传输中产生的比特差错；差错控制，对检测出的差错采取丢弃或重传等措施；流量控制，协调收发双方的发送与接收速率。此外，当多个结点共享同一信道时，数据链路层还要负责介质访问控制。教材常把数据链路层的功能归纳为"成帧、差错控制、流量控制、传输管理"四个方面。

## 链路与数据链路、帧

链路（link）是一条无源的点到点的物理线路段，中间没有任何其他的交换结点；一条链路只是一条通路的一个组成部分。数据链路（data link）则除了物理线路外，还必须有通信协议来控制这些数据的传输，若把实现这些协议的硬件和软件加到链路上，就构成了数据链路。换言之，数据链路是"物理链路 + 协议"。在数据链路层上传输的数据单元称为帧（frame），它由帧首部、数据部分与帧尾部组成。帧首部通常包含目的地址与源地址，帧尾部通常包含差错检验码（如 FCS）。由于数据链路层的传输单位是帧，网络层的分组被封装在帧的数据部分中传送，因此帧的长度受最大传输单元（MTU）的限制。数据链路层协议有多种，常见的有 PPP、HDLC 以及以太网的 MAC 协议，它们在成帧方式与地址结构上各不相同。

## 封装成帧

封装成帧就是在一段数据的前后分别添加首部和尾部，这样就构成了一个帧。接收端在收到物理层交上来的连续比特流后，根据首部和尾部的标记，从比特流中识别帧的开始和结束。首部和尾部的一个重要作用就是帧定界。如果只有帧首部而没有帧尾部，接收方在收到一部分帧后无法判断帧何时结束，也就无法取出完整的数据。帧定界的方法有多种：字符计数法，在帧头用一个计数字段标明帧长，但计数字段出错会导致后续帧全部失去边界；字符填充法，用特定的控制字符作定界符；零比特填充法，用特殊的比特模式作定界符；以及物理层编码违例法，利用编码中不会出现的电平组合表示帧边界，如在以太网中用曼彻斯特编码的非法电平组合标记帧的开始。实际协议往往同时使用多种手段。

## 透明传输：字符填充

当数据部分出现的比特组合恰好与帧定界符相同时，必须采取适当措施使接收方不会将其误认为是帧边界，这就是透明传输问题。在面向字符的协议中，常用 ASCII 码中的不可打印控制字符作为定界符，例如用 SOH（0x01）表示帧开始、EOT（0x04）表示帧结束。若数据部分恰好出现了 SOH 或 EOT，接收方就会误判帧边界。解决办法是字符填充（字节填充）：在数据中出现的每个 SOH、EOT 以及转义字符 ESC（0x1B）之前，都插入一个转义字符 ESC，接收端在收到 ESC 后不将其后的字符当作控制字符解释，而是直接作为数据接收，并删除该 ESC。若数据中原本就有 ESC，则连它也要被填充为 ESC ESC，从而保证接收端能够无歧义地还原数据。这种做法保证了无论数据内容如何，都能原样传送到对端。

## 透明传输：零比特填充

在面向比特的协议（如 HDLC）中，帧的定界符是一个特定的比特模式 01111110（即 6 个连续 1，称为标志字段 F）。如果数据部分恰好出现了 6 个或更多连续 1，就会被误认为帧边界。零比特填充法（比特填充）的思路是：发送端在数据部分中每出现 5 个连续 1，就立即填入一个 0，这样数据部分永远不会出现 6 个连续 1，标志字段 01111110 在数据中就不可能被误认。接收端则执行相反的删除操作：每收到 5 个连续 1 时，若其后的比特是 0，则删除该 0 并继续接收；若其后的比特是 1，则说明这是标志字段或中止序列，不再删除。发送端与接收端必须约定相同的填充与删除规则。零比特填充法对任意比特组合都透明，实现简单可靠，是 HDLC 与 PPP 常用的成帧方式。

## 差错检测与奇偶校验

差错检测的目的是发现数据在传输过程中是否产生了比特差错，即 1 变成 0 或 0 变成 1，也称为比特差错或误码。衡量指标是误码率 BER，即传错比特数与总传输比特数之比，通常要求低于 10⁻⁹ 量级。奇偶校验是最简单的检错方法：在数据后附加一位校验位，使整个码字中 1 的个数为奇数（奇校验）或偶数（偶校验）。奇偶校验只能检测出奇数个比特出错的情况，若同时有 2 位比特出错则无法发现（检错概率约 50%）。二维奇偶校验把数据排成矩阵，对每行与每列分别计算校验位，不仅能检测出奇数位与部分偶数位错误，还能定位并纠正单个比特错误，检错能力明显提高。但奇偶校验开销随数据量增加而增大，且检错能力有限，因此实际链路协议普遍采用循环冗余校验。

## CRC 循环冗余校验的计算方法

循环冗余校验（CRC）利用模 2 除法进行检错。设数据为 k 位，生成多项式 G(x) 为 r+1 位（最高次为 r，最高位与最低位必须为 1）。计算步骤为：第一步，在数据 M 后面添加 r 个 0，得到 k+r 位被除数；第二步，用模 2 除法（即按位异或，不借位）除以 G(x) 对应的 r+1 位二进制串；第三步，取 r 位余数作为帧检验序列 FCS，附加在数据之后发送。接收端把收到的全部比特（数据 + FCS）再次除以同一个 G，若余数为 0 则认为无差错，否则认为出错并丢弃。举例：M = 101001，G(x) = x³ + x² + 1 对应 1101，r = 3，被除数为 101001000。依次做模 2 除法：前四位 1010 与 1101 异或得 0111，移入下一位得 1110，与 1101 异或得 0011，移入下一位得 0111，移入下一位得 1110，与 1101 异或得 0011，移入后两位得 1100，与 1101 异或得 0001，最终余数为 001。故 FCS = 001，发送序列为 101001001。CRC 能检测出所有奇数个比特错误、所有双比特错误以及长度不超过 r 的突发错误，检错能力很强。

## 差错控制：检错重传 ARQ

差错控制有两类基本策略：一类是自动重传请求（ARQ），即接收端检测到差错后设法通知发送端重传，直到收到正确的数据为止；另一类是前向纠错（FEC），接收端不仅能发现差错，还能确定并纠正差错，代价是需要更多冗余信息。ARQ 机制包含三个要素：差错检测，通过 CRC 等校验码判断帧是否正确；接收确认，接收端向发送端返回确认帧 ACK 表示正确收到，返回否认帧 NAK 表示出错；超时重传，发送端为每个发出的帧设置计时器，若在超时时间到达前未收到确认，就认为帧丢失并重新发送。ARQ 又可分为停止等待协议、后退 N 帧协议与选择重传协议三种。ARQ 的思想基础是：在链路质量较好时错误是偶发的，与其为每个帧加上足以纠错的大量冗余，不如偶尔重传一次，效率更高。

## 停止等待协议

停止等待协议是最简单的 ARQ 协议：发送方每发送一个数据帧就停止发送，等待接收方的确认，收到确认后再发送下一个帧。若超时未收到确认则重传该帧。为正确处理各种异常情况，协议还需解决几个问题：一是确认帧或数据帧丢失，发送方通过超时重传解决；二是确认帧迟到导致发送方重传后收到重复的确认，解决办法是为数据帧编号（0 和 1 交替）并使用累计确认；三是重复帧问题，接收方通过检查帧的序号判断是否为重复帧，若是则丢弃并重发确认。停止等待协议的优点是简单，缺点是信道利用率很低。设发送一帧所需时间为 T_D，往返传播时延为 RTT，确认帧发送时间为 T_A，则信道利用率 U = T_D/(T_D + RTT + T_A)。当带宽高、距离远时，T_D 相对 RTT 很小，利用率可能低于 1%。

## 后退 N 帧协议 GBN

后退 N 帧协议（Go-Back-N）采用流水线传输，允许发送方连续发送多个帧而不必逐个等待确认，从而大幅提高信道利用率。GBN 的规则是：发送方维持一个长度为 N 的发送窗口，窗口内的帧可以连续发送；接收方只按序接收帧，对不按序到达的帧一律丢弃，并对最后一个按序正确收到的帧发送确认。若某帧丢失或出错，发送方超时后不仅重传该帧，还要重传该帧之后所有已发送的帧，这就是"后退 N 帧"名称的由来。GBN 采用累积确认：收到对第 n 号帧的确认，表示第 n 号及以前的所有帧都已被正确接收。若采用 n 个比特编号，则发送窗口的最大值为 2ⁿ − 1，接收窗口大小固定为 1。GBN 的优点是实现简单、接收缓冲区需求小；缺点是当出现差错时可能重传大量已经正确到达的帧，在误码率较高的链路上效率下降明显。

## 选择重传协议 SR

选择重传协议（Selective Repeat）只重传真正出错或丢失的帧，从而避免 GBN 的重复传输浪费。SR 的规则是：发送方维持发送窗口，接收方也维持一个与发送窗口同样大小的接收窗口，接收方可以接收并缓存失序到达的帧，只对正确收到的帧逐个发送确认；发送方为每个已发送但未确认的帧设置计时器，某个帧超时后只重传该帧。当接收窗口内的帧全部收齐后，接收方把它们按序交付上层并把窗口向前滑动。SR 的窗口大小受序号空间的限制：若用 n 个比特编号，则必须满足发送窗口 + 接收窗口 ≤ 2ⁿ，通常取发送窗口 = 接收窗口 = 2ⁿ⁻¹。若窗口过大，新旧帧的序号会发生重叠，接收方无法区分是新帧还是重传帧。SR 的效率最高，但需要较大的缓存并能对帧排序，实现复杂度也最高。

## 滑动窗口机制

滑动窗口是 ARQ 协议实现的基础机制。发送窗口是发送方允许连续发送而无需等待确认的帧序号集合，窗口内的序号分为已发送未确认与尚未发送两类；每收到一个确认，窗口就向前滑动若干位置。接收窗口是接收方允许接收的帧序号集合，只有当收到的帧序号落在接收窗口内时才接收，否则丢弃。窗口的大小决定了流水线程度：窗口越大，允许在途的帧越多，信道利用率越高。设窗口大小为 W、发送一帧的时间为 T_D、往返时延相关开销为 RTT + T_A，则连续 ARQ 的信道利用率 U = W·T_D/(T_D + RTT + T_A)，当 W 足够大使分子不小于分母时利用率为 100%。滑动窗口机制同时实现了流量控制与可靠传输：窗口大小限制了未确认数据的最大量，从而防止接收方被淹没；序号与确认机制则保证了数据的可靠交付。

## 流量控制与可靠传输

流量控制是让发送方的发送速率不要太快，使接收方来得及接收，本质上是协调收发双方的速率匹配。数据链路层的流量控制是相邻结点之间的局部控制，接收方通过确认帧中携带的窗口值告知发送方自己还能接收多少数据，发送方据此调整发送窗口，这称为滑动窗口流量控制。可靠传输则要求数据无差错、不丢失、不重复且按序到达，它依赖三项机制共同实现：差错检测（CRC）发现比特差错，确认与重传（ACK/超时）处理丢失与出错，序号与窗口处理重复与失序。二者既有区别又有联系：流量控制解决速率匹配问题，可靠传输解决正确性问题，但都通过滑动窗口这一数据结构实现。值得注意的是，若链路本身误码率极低，也可以只在传输层实现可靠传输而让链路层"不可靠"，这正是互联网的设计思路。

## 三种协议的信道利用率比较

三种 ARQ 协议的信道利用率差异显著。在停止等待协议中，发送方每发一帧都要停下来等待确认，信道利用率 U = T_D/(T_D + RTT + T_A)，当传播时延远大于发送时延时利用率极低。例如 1 Gb/s 链路、帧长 1000 bit、单向传播时延 10 ms，则 T_D = 1 μs，RTT = 20 ms，利用率仅约 0.005%。连续 ARQ（GBN 与 SR）通过流水线把利用率提高到 U = W·T_D/(T_D + RTT + T_A)。对于 GBN，窗口 W ≤ 2ⁿ − 1；对于 SR，W ≤ 2ⁿ⁻¹。以同样的参数，若采用 3 bit 编号，GBN 的 W 最大为 7，利用率约为 0.035%；若采用 8 bit 编号，GBN 的 W 可达 255，利用率接近 100%。这说明要充分利用高带宽长时延链路（如卫星链路），必须使用足够大的窗口与足够长的序号字段。

## PPP 与 HDLC 简介

PPP（点对点协议）是目前使用最广泛的数据链路层协议之一，用于用户计算机与 ISP 之间的拨号或专线连接。PPP 由三部分组成：一个将 IP 数据报封装到串行链路的方法，链路控制协议 LCP 用于建立、配置、测试与释放数据链路连接，以及网络控制协议 NCP 用于支持不同的网络层协议。PPP 的帧格式为：标志字段 01111110、地址字段 11111111（无意义）、控制字段 00000011、2 字节协议字段、数据部分、2 字节 FCS、标志字段。PPP 使用零比特填充实现透明传输，只提供差错检测而不提供纠错与序号机制，因此是不可靠的传输服务，它不使用滑动窗口与流量控制，也不支持多点接入。HDLC（高级数据链路控制）是面向比特的协议，同样以 01111110 作标志，可工作在正常响应方式与异步平衡方式，支持连续 ARQ，比 PPP 功能更完整，但在互联网中应用较少。
