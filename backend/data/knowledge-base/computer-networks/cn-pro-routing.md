# 路由选择与路由协议

## 路由选择的基本概念

路由选择是指按照某种策略，在由路由器与链路构成的网络中为分组选择一条从源到目的的传输路径。它包含两个既相关又有区别的概念：路由选择（选路）指根据网络拓扑与状态，按照路由算法构造出路由表的过程，通常由路由协议周期性或触发式完成；分组转发指路由器收到分组后，根据转发表把分组从合适的端口送出的过程，是每个分组都要执行的快速操作。二者分离的好处是：选路过程可以较慢（秒级甚至分钟级），而转发过程必须极快（纳秒到微秒级），转发可以使用经过优化的硬件结构（如基于 Trie 的最长前缀匹配）。路由选择算法可分为静态路由选择与动态路由选择：静态路由由管理员手工配置，简单但不适应拓扑变化；动态路由通过协议自动学习，适应性强但开销较大。

## 路由表与转发表、分组转发流程

路由表由若干路由表项构成，每个表项通常包含目的网络地址、子网掩码（或前缀长度）、下一跳地址、出接口与度量值。转发表是从路由表导出的、针对具体转发硬件优化的数据结构，其内容可以是"（目的前缀，下一跳，出接口）"的映射，并且常常使用压缩算法减少存储与查找时间。路由器转发一个分组的基本流程为：从输入端口收到分组后，提取目的 IP 地址；用目的地址与转发表中各表项的前缀依次匹配，按最长前缀匹配原则选中一个表项；若表项中给出的是下一跳地址，则还需要通过 ARP 得到下一跳的 MAC 地址；随后重新封装成帧并从相应输出端口发送出去；若没有任何表项匹配且存在默认路由则按默认路由转发，否则丢弃分组并向源主机发送 ICMP 终点不可达差错报告。转发过程中，IP 首部的源地址与目的地址不变，而 TTL 减 1、首部检验和重算、帧的源与目的 MAC 地址被改写。

## 路由器结构

路由器由两大部分构成：路由选择部分（控制部分）与分组转发部分（数据部分）。路由选择部分也叫控制部分，其核心是路由选择处理机，它根据选定的路由协议构造出路由表，并定期与相邻路由器交换路由信息以更新和维护路由表。分组转发部分由三部分组成：交换结构（交换组织），根据转发表把分组从一个输入端口转移到合适的输出端口，其性能直接决定路由器的吞吐量，常见实现有通过存储器交换、通过总线交换与通过互连网络交换；输入端口，从物理链路接收信号、还原成帧、去掉帧头与帧尾、进行查表与转发决策，并设有缓存以应对交换结构暂时忙碌；输出端口，把分组重新封装成帧并发送到物理链路上，同样需要缓存以吸收交换结构速率与链路速率之间的差异。当输入速率之和超过交换结构速率或输出链路速率时，缓存会溢出导致分组丢失，这是路由器拥塞的直接原因。

## 距离向量算法

距离向量算法（Bellman-Ford 思想）的基本原理是：每个路由器维护一张路由表，表中给出到每个目的网络的最短距离与下一跳；路由器周期性地把自己的整张路由表发送给所有相邻路由器；收到邻居的路由表后，按照"我到邻居的距离 + 邻居到目的网络的距离"计算经由该邻居到达各目的网络的距离，若比当前记录的更小则更新表项（下一跳改为该邻居），否则保持。经过若干轮迭代，各路由器的表项会收敛到最短路径。距离向量算法的优点是实现简单、开销小、无需了解全网拓扑；缺点是坏消息传播得慢（计数到无穷问题），当某条链路断开时，错误的路由信息可能在邻居之间来回传递，距离值逐步增大到无穷大才被认定为不可达。为缓解该问题，常用措施包括：定义最大距离（如 16 表示不可达）、水平分割（不把从某邻居学来的路由再通告给该邻居）、毒性逆转（把从某邻居学来的路由以距离无穷大通告回去）与触发更新。

## 链路状态算法

链路状态算法（Dijkstra 最短路径思想）的基本原理是：每个路由器通过"问候"分组发现相邻路由器并测量到邻居的开销，然后把包含自己所有链路状态（邻居标识与链路开销）的链路状态分组洪泛到全网，使每个路由器都获得全网的拓扑与链路开销信息，从而建立一致的链路状态数据库；随后每个路由器以自己为根，用 Dijkstra 算法计算到所有目的网络的最短路径，据此构造路由表。链路状态算法的优点是收敛快、不会出现计数到无穷问题、每个路由器掌握全网拓扑因而便于实施流量工程与等开销多路径；缺点是洪泛会带来一定开销、需要较多存储与计算资源、实现较为复杂。与距离向量算法相比，链路状态的每个路由器只向全网发布与自己直连链路的状态（局部信息），而距离向量算法向邻居发布自己的整张路由表（全局但间接的信息）。

## 距离向量与链路状态的比较

两种算法在多个维度上存在差异。在信息交换内容上，距离向量交换的是"我到各目的网络的距离"（整张路由表的摘要），链路状态交换的是"我的各条直连链路的状态"（局部拓扑）。在交换对象上，距离向量只与直接相邻的路由器交换，链路状态向全网所有路由器洪泛。在交换时机上，距离向量按固定周期（如 30 秒）交换，链路状态在链路状态变化时触发并辅以周期性刷新。在算法上，距离向量使用 Bellman-Ford 迭代计算，链路状态使用 Dijkstra 集中式计算但基于分布式的数据库。在收敛性上，链路状态通常收敛更快且无环路风险，距离向量在拓扑变化时可能出现路由环路与计数到无穷。在资源需求上，距离向量对 CPU 与内存要求低，链路状态要求较高。典型协议对应关系：RIP 使用距离向量算法，OSPF 与 IS-IS 使用链路状态算法，BGP 则使用路径向量算法。

## RIP 协议

RIP（路由信息协议）是一种基于距离向量算法的内部网关协议，适用于小型网络。RIP 以"跳数"作为度量，即经过的路由器个数，直连网络的距离定义为 1；RIP 规定一条路径最多只能包含 15 个路由器，距离等于 16 时即视为不可达，这限制了 RIP 只能用于小型互联网。RIP 的要点包括：每个路由器只与相邻路由器交换信息；交换的信息是自己的路由表，即"到所有已知目的网络的距离与下一跳"；按固定时间间隔交换，默认每 30 秒发送一次，RIP 还支持触发更新，即拓扑变化时立即通告。RIP 使用 UDP 传送报文，端口号为 520，因此 RIP 报文是被封装在 UDP 用户数据报中再封装进 IP 数据报的，属于应用层协议。RIP 报文分为请求与响应两类，一条 RIP 报文最多可携带 25 个路由表项，若表项更多则需用多个报文传送。RIP 的优点是配置简单、无环路风险较小；缺点是收敛慢、跳数限制严格且未考虑带宽与延迟。

## RIP 的距离向量计算与坏消息传播慢

RIP 中路由器收到相邻路由器 X 的报文后的处理规则是：先把报文中各表项的"下一跳"字段改为 X，并把所有"距离"字段的值加 1；然后对每个表项，若自己的路由表中没有该目的网络，则添加该表项；若有且下一跳也是 X，则用新表项替换（因为网络状态可能已变化）；若有但下一跳不是 X，则只有当新距离小于原距离时才更新。举例说明坏消息传播慢：网络 A—B—C 串联，B 到 A 的距离为 1，C 到 A 的距离为 2。若 A 与 B 之间链路断开，B 首先把到 A 的距离改为 16；但在 B 发出更新之前，C 可能先把自己"到 A 距离为 2"的报文发给 B，B 误以为可以通过 C 到达 A，于是把到 A 的距离改为 3、下一跳改为 C；随后 C 又从 B 得知距离为 3 而改为 4，如此反复，距离逐步增大直到 16 才被判定不可达。这个过程称为计数到无穷，是距离向量算法的固有缺陷，采用水平分割与毒性逆转可以避免大部分此类问题。

## OSPF 协议

OSPF（开放最短路径优先）是一种基于链路状态算法的内部网关协议，用于较大规模的自治系统内部。OSPF 的三个要点是：第一，使用分布式的链路状态协议，向本自治系统中的所有路由器洪泛链路状态信息；第二，发送的信息是与本路由器相邻的所有路由器的链路状态，且只在链路状态发生变化时才发送；第三，只有当链路状态发生变化时才洪泛，并周期性（默认每 30 分钟）刷新一次链路状态。OSPF 的度量不再使用跳数，而是可以基于带宽、时延、费用等多种因素设定链路开销，因而更合理。OSPF 报文直接封装在 IP 数据报中传送，协议字段值为 89（不使用 TCP 或 UDP）。OSPF 共定义了五种分组：问候分组，用来发现和维持邻站的可达性；数据库描述分组，向邻站给出自己链路状态数据库中所有链路状态项目的摘要信息；链路状态请求分组，向对方请求发送某些链路状态项目的详细信息；链路状态更新分组，用洪泛法向全网更新链路状态；链路状态确认分组，对链路状态更新分组进行确认。

## OSPF 的分区与 LSA 类型

为适应大规模网络，OSPF 把一个自治系统划分为若干个更小的区域（area），每个区域有一个 32 位的区域标识符。划分区域的好处是把利用洪泛法交换链路状态信息的范围局限于每一个区域而不是整个自治系统，从而减少了整个网络上的通信量。区域的划分有一个主干区域（area 0.0.0.0），其他区域都必须与主干区域相连，区域之间的路由信息由区域边界路由器汇总后通告给主干区域。OSPF 路由器按角色分为内部路由器、区域边界路由器、主干路由器与自治系统边界路由器。OSPF 的链路状态通告（LSA）类型包括：类型 1 为路由器 LSA，由每个路由器产生，描述本路由器链路状态；类型 2 为网络 LSA，由指定路由器产生，描述本网段链路状态；类型 3 为网络汇总 LSA，由区域边界路由器产生；类型 4 为自治系统边界路由器汇总 LSA；类型 5 为自治系统外部 LSA。此外 OSPF 支持等开销多路径负载均衡、身份鉴别与可变长度子网掩码。

## BGP 协议

BGP（边界网关协议）是不同自治系统的路由器之间交换路由信息的协议，属于外部网关协议。由于互联网规模巨大，且不同自治系统对路由的偏好策略各异（涉及政治、经济与安全因素），寻找最佳路由并不现实，因此 BGP 力求寻找一条能够到达目的网络且无环路的较好路由，而非最优路由。BGP 交换的是网络可达性信息，即"要到达某个网络所要经过的一系列自治系统"，这种路径向量信息可以有效避免环路。BGP 使用 TCP 连接交换路由信息，端口号为 179，这保证了报文的可靠传输并简化了协议设计。BGP 分为外部 BGP（eBGP），用于不同自治系统的边界路由器之间交换信息；内部 BGP（iBGP），用于同一自治系统内部的不同边界路由器之间传递从外部学到的路由。BGP 的四种报文是：打开报文，用来与相邻的另一个 BGP 发言人建立关系；更新报文，用来通告某一路由的信息以及列出要撤销的多条路由；保活报文，用来周期性地证实邻站的连通性；通知报文，用来发送检测到的差错。

## BGP 的路径属性与选路

BGP 在通告路由时携带一系列路径属性，路由器据此进行路由决策。主要属性包括：ORIGIN，说明路由的来源（IGP、EGP 或不完整）；AS_PATH，列出该路由经过的自治系统序列，是防止环路的依据（若收到的 AS_PATH 中包含本自治系统的编号则拒绝该路由），也是选路时比较路径长度的依据；NEXT_HOP，指明到达目的网络的下一跳 IP 地址；LOCAL_PREF，本地优先级，值越大越优先，是自治系统内部用于选择出口的重要属性，通常只在本自治系统内传递；MED（多出口鉴别符），用于向相邻自治系统提示进入本自治系统的优选入口，值越小越优先，通常只传给直接相邻的自治系统；COMMUNITY，用于给路由打标签以便批量实施策略。BGP 的选路决策过程依次考察权重（厂商私有）、LOCAL_PREF、本地始发路由、AS_PATH 长度、ORIGIN、MED、eBGP 优先于 iBGP、到 NEXT_HOP 的 IGP 度量最小等准则，直到选出唯一路由。

## 自治系统与路由层次

自治系统（AS）是在单一技术管理下的一组网络与路由器，它们使用同一种内部路由选择协议和共同的度量，对外表现出统一的、一致的路由选择策略。每个自治系统被分配一个全球唯一的自治系统号。互联网的路由选择划分为两个层次：自治系统内部的路由选择称为域内路由选择，使用内部网关协议（IGP），如 RIP、OSPF；自治系统之间的路由选择称为域间路由选择，使用外部网关协议（EGP），目前主要是 BGP。采用分层路由的原因在于规模：互联网中路由器数量极其庞大，若所有路由器都运行同一种全局路由协议，路由表将庞大到无法处理，且不同管理域的策略需求无法统一表达。分层的另一个好处是自治系统内部拓扑变化对外部影响较小，只需边界路由器通告汇总后的可达性信息。

## 路由聚合与路由环路

路由聚合在路由协议中的意义在于压缩路由表规模。以 RIP 与 OSPF 为例，一个自治系统内部有许多连续的子网，若逐个通告将产生大量表项，边界路由器可以把它们聚合为一条较短前缀的路由再通告出去，这就是 CIDR 的实际应用。例如把 172.16.0.0/24 到 172.16.7.0/24 八个连续地址块聚合为 172.16.0.0/21 一条路由。聚合带来的问题是可能把不属于本自治系统的地址块也包含进去，形成"路由黑洞"或引起流量绕行，解决办法是为特殊情况配置更具体的路由，利用最长前缀匹配保证准确性。路由环路是另一个重要问题：距离向量算法在收敛过程中可能出现环路，BGP 通过 AS_PATH 检测环路（拒绝包含本地 AS 号的路由），OSPF 通过链路状态数据库的一致性保证无环，静态路由配置不当同样会产生环路。为防止环路导致分组在网络中永远循环，IP 首部的 TTL 字段提供了最后一道防线。

## IPv6 基本特点

IPv6 是为解决 IPv4 地址耗尽等问题而设计的新一代 IP 协议，其主要特点包括：地址长度为 128 位，地址空间极大，可满足未来长期需求；首部长度固定为 40 字节，取消了 IPv4 的可变可选字段与首部检验和，把可选功能放到扩展首部中，使路由器处理更快；支持地址自动配置，主机可以通过邻居发现协议自行获得地址，无需 DHCP 服务器；首部中的地址字段为源地址与目的地址各 128 位；取消了首部检验和，差错检测交给数据链路层与传输层完成；路由器不再分片，分片只能由源主机进行；使用冒号十六进制记法表示地址，如 2001:0db8:85a3:0000:0000:8a2e:0370:7334，允许用双冒号 :: 压缩连续的一段零（在地址中只能出现一次）；地址类型分为单播、多播与任播，不再有广播地址；邻居发现协议（NDP）取代了 ARP；流标签字段可用于标识特定的流以便提供特殊处理。

## IPv6 地址与过渡技术

IPv6 地址的若干特殊形式需要掌握：未指定地址为 ::（全零），用于主机尚未配置地址时；环回地址为 ::1；链路本地地址前缀为 fe80::/10，用于同一链路上的通信，路由器不转发。IPv6 的单播地址包括全球单播地址（通常以 2000::/3 开头）与链路本地地址等。由于互联网上大量设备仍只支持 IPv4，向 IPv6 的过渡必须是渐进的，主要过渡技术有两类。双协议栈：主机同时运行 IPv4 与 IPv6 两套协议栈，根据目的地址类型选择使用哪种协议，或者对 DNS 查询返回的地址类型做出判断。隧道技术：当两台 IPv6 主机之间的路径上有 IPv4 网络时，把 IPv6 数据报封装在 IPv4 数据报中传送，即把 IPv6 数据报作为 IPv4 的数据部分，这种做法称为 IPv6 over IPv4 隧道（如 6to4、Teredo）。此外还有 NAT 与协议转换技术，用 NAT64/DNS64 实现纯 IPv6 主机与纯 IPv4 主机之间的通信。
