# 内存管理与分页分段

## 内存管理的基本功能
内存是处理机可以直接访问的存储部件，程序必须装入内存才能运行。内存管理的主要功能包括：内存空间的分配与回收，为进程分配所需内存并在进程结束时回收；地址转换，把程序中的逻辑地址转换为内存中的物理地址；内存空间的扩充，借助虚拟存储技术从逻辑上扩充内存容量；内存保护，保证各进程只在自己的内存区域内工作，互不干扰；内存共享，允许多个进程访问同一段内存（如共享库、共享内存）。存储管理的核心问题是提高内存利用率与访问速度，同时保证安全性与隔离性。

## 逻辑地址与物理地址
逻辑地址（相对地址、虚地址）是程序经过编译链接后形成的地址空间中的地址，从 0 号单元开始编址，同一程序装入内存的不同位置时其逻辑地址不变。物理地址（绝对地址）是内存单元在内存空间中的实际地址，由内存物理单元的编号构成。用户程序中使用的是逻辑地址，CPU 执行指令时也必须先取得逻辑地址，再由硬件（MMU）在访存时把它转换为物理地址。这种转换称为地址重定位。编译链接后生成的目标代码中，模块内部使用的是相对地址。

## 地址重定位：静态与动态
静态重定位在程序装入内存时一次性把逻辑地址全部转换为物理地址，程序运行期间不能移动。优点是实现简单、无需硬件支持；缺点是程序一旦装入就不能再移动，难以实现内存共享与虚拟内存，且要求程序装入时必须一次性分配连续内存。动态重定位在程序运行时由硬件在每次访存时进行地址转换：设置一个重定位寄存器保存程序在内存中的起始地址，物理地址 = 逻辑地址 + 重定位寄存器的值。优点是程序可灵活移动、便于内存共享与虚拟存储；缺点是需要硬件支持，且转换带来额外开销（可由快表缓解）。

## 内存保护
内存保护防止一个进程越界访问其他进程或操作系统的区域。常用方法有两种。设置上下界寄存器：CPU 访存时检查地址是否满足下界 ≤ 地址 < 上界，越界则产生异常，缺点是上下界寄存器需随进程切换而更新，且不利于分区共享。设置基址寄存器与限长寄存器：基址寄存器保存进程起始物理地址，限长寄存器保存进程长度，先检查逻辑地址是否小于限长，越界则陷入异常，否则再与基址相加得到物理地址，从而同时完成地址转换与保护。在分页与分段系统中，还可通过页表项或段表项中的存取控制位（读、写、执行）实现更细粒度的保护。

## 单一连续分配
单一连续分配把内存分为系统区和用户区两部分，系统区供操作系统使用（通常位于低地址），用户区只能装入一道用户程序，整个用户区由该程序独占。这种方式实现简单、无需复杂的地址转换与保护机制，但内存利用率极低，内存中仅有一道程序，CPU 会因程序等待 I/O 而大量空闲，且用户程序可能覆盖操作系统。它只适用于单用户单任务的早期系统，是已被淘汰的方式，但它是理解后续多道程序设计的基础。

## 固定分区分配
固定分区分配把用户内存划分为若干固定大小的分区，每个分区装入一道作业，分区大小可在系统启动时确定，分区大小可以相同，也可以不同。为实现分配，系统维护一张分区说明表，记录每个分区的起始地址、大小和状态（是否已分配）。分配时按作业大小查找能满足要求且未分配的分区。优点是实现简单、无外部碎片、可用硬件实现地址转换。缺点是会产生内部碎片（分区大于作业的部分被浪费），且内存利用率低；分区大小在运行期固定，无法适应作业大小变化；同时上述方法均要求程序整体连续装入，限制了并发道数。

## 动态分区分配
动态分区分配又称可变分区分配，不预先划分分区，而是在作业装入时根据其实际大小动态建立分区，分区大小与个数随作业装入和撤销而变化。系统维护空闲分区表或空闲分区链，分配时按算法从空闲分区中找出足够大的分区，若有剩余则划分出新的小空闲分区；回收时把释放的分区并入相邻空闲区（合并以缓解碎片）。常用算法有首次适应、最佳适应、最坏适应和邻近适应。动态分区分配比固定分区灵活，但会产生外部碎片；分区大小可变，且需要更复杂的管理数据结构。

## 基于顺序搜索的动态分区分配算法
首次适应算法（FF）：空闲分区按地址递增次序链接，分配时从链首开始找第一个满足大小的分区，优点是无须对分区排序、倾向于使用低地址空间从而保留高地址大空闲区，缺点低地址被不断切碎、每次从链首查找开销大。最佳适应算法（BF）：空闲分区按容量递增链接，分配时取第一个满足大小者，能保留大空闲区但会留下大量难以利用的极小碎片。最坏适应算法（WF）：空闲分区按容量递减链接，总是分配最大的分区，使剩余部分仍足够大而可再分配，缺点是快速消耗大分区，不利于大作业。邻近适应算法（NF）：从上次分配结束位置继续搜索，使空闲区分布更均匀，但可能导致高地址大空闲区也被切碎。

## 内部碎片、外部碎片与紧凑
内部碎片指分配给进程的分区中未被利用的部分，它出现在分区内部，仅在固定分区、分页等按固定单位分配的方案中产生，因为分配单位必须整除且不可分割。外部碎片指内存中由于反复分配与回收而形成的大量不连续、难以利用的小空闲区，它出现在分区之间，在动态分区分配中产生。解决外部碎片的办法是紧凑（拼接）：移动进程在内存中的位置，把分散的空闲区合并为一个大空闲区，但紧凑需要动态重定位支持（程序运行时可以移动），并且需要移动大量数据、开销大，移动过程中还必须暂停相关进程。

## 分页存储管理的基本原理
分页存储管理把进程的逻辑地址空间分成若干大小相等的页（页面），把内存空间分成与页大小相等的物理块（页框、存储块），页与块从 0 开始编号。进程装入时，其各页可以离散地装入内存中任意空闲块，并通过页表记录页号到块号的映射。逻辑地址结构为"页号 + 页内偏移"，若页面大小为 2^k 字节，则逻辑地址的低 k 位为页内偏移，高位为页号。分页的优点是没有外部碎片、内存利用率高，便于内存分配与回收；缺点是进程的最后一页会产生内部碎片，且页面划分对用户不可见，一页内的程序逻辑（如子程序）可能被拆散。

## 页表与基本地址变换
页表是页号到物理块号的映射表，每个进程一张，由页表寄存器（PTR）指出页表在内存中的始址与页表长度。地址变换过程为：由逻辑地址分离出页号 P 与页内偏移 W；比较 P 与页表长度，若 P ≥ 页表长度则产生越界中断；用 P 作为索引查页表得到物理块号 b；物理地址 E = b × 页面大小 + W。由于页表存放在内存中，一次访存需要两次访问内存（第一次查页表、第二次取数据），使访问速度降低约一半，因此引入快表来加速。

## 具有快表的地址变换
快表（TLB，转换检测缓冲区）是一组具有并行查找能力的高速缓存寄存器，存放最近访问过的页表项（页号与物理块号）。地址变换时先查快表：若命中（页号匹配）则直接取出物理块号，无需访问内存中的页表；若未命中则再访问内存中的页表，同时把该页表项装入快表（若快表已满则按某种置换算法换出）。引入快表后，有效访问时间 = 命中率 ×（快表访问时间 + 一次访存时间）+ (1 − 命中率) ×（快表访问时间 + 两次访存时间）。此外还可在页表项中设置访问位与修改位，供置换算法使用。

## 分页地址变换示例
若页面大小为 4KB，则逻辑地址的低 12 位为页内偏移、高位为页号。设页表项 page_table[2] = 5，表示第 2 页已装入物理块 5，则逻辑地址 0x2123 的页号为 2、页内偏移为 0x123，对应物理地址为 5 × 0x1000 + 0x123 = 0x5123。地址变换过程中必须进行两项检查：页号是否超过页表长度（越界则产生越界中断），以及页表项是否有效（无效则产生缺页中断）。

```c
/* 分页地址变换：逻辑地址 -> 物理地址，含越界检查与缺页判断 */
#include <stdio.h>

#define PAGE_SHIFT  12                      /* 页面大小 4KB = 2^12 字节 */
#define PAGE_SIZE   (1u << PAGE_SHIFT)
#define NPAGES      16
#define PTE_INVALID (-1)                     /* 页表项无效：该页不在内存 */

static int page_table[NPAGES];               /* 页号 -> 物理块号 */

/* 返回 0 成功；-1 越界；-2 缺页 */
static int translate(unsigned logical, unsigned *physical) {
    unsigned p = logical >> PAGE_SHIFT;              /* 页号：高位部分 */
    unsigned w = logical & (PAGE_SIZE - 1);          /* 页内偏移：低 12 位 */
    if (p >= NPAGES) return -1;                      /* 越界中断 */
    int b = page_table[p];
    if (b == PTE_INVALID) return -2;                 /* 缺页中断 */
    *physical = ((unsigned)b << PAGE_SHIFT) | w;     /* 物理地址 = 块号×页面大小 + 偏移 */
    return 0;
}

int main(void) {
    for (int i = 0; i < NPAGES; i++) page_table[i] = PTE_INVALID;
    page_table[2] = 5;                               /* 第 2 页装入物理块 5 */
    unsigned logical = 2u * PAGE_SIZE + 0x123u;      /* 0x2123 */
    unsigned physical = 0;
    int r = translate(logical, &physical);
    if (r == 0) printf("逻辑 0x%X -> 物理 0x%X\n", logical, physical);
    return 0;
}
```

## 两级页表与多级页表
当逻辑地址空间很大时，页表本身会占据大量内存且要求连续存放。解决办法是对页表再分页，形成两级页表：把页表划分为若干页，并为它们建立一张外层页表（页目录），每个进程的页表寄存器指向外层页表。逻辑地址结构变为"一级页号 + 二级页号 + 页内偏移"，地址变换需先查外层页表找到页表所在块，再查页表找到数据所在块，因此未命中快表时一次访存需要三次访问内存。当逻辑地址空间更大时可采用三级甚至四级页表（如 32 位 Linux 用两级、64 位用四级），多级页表能显著节省页表所占内存，但增加了访存次数，需靠快表弥补。多级页表还支持页表按需调入，即页表本身也可以不完全常驻内存。

## 分段存储管理
分段存储管理按程序的逻辑结构把地址空间划分为若干段，如主程序段、子程序段、数据段、栈段，每段有段名（段号）并从 0 开始编址，各段长度不同。逻辑地址结构为"段号 + 段内偏移"，段表项包含段长与段基址。地址变换时先由段号查段表，若段内偏移 ≥ 段长则产生越界中断，否则物理地址 = 段基址 + 段内偏移。分段的优点是以逻辑结构为单位便于程序模块化、便于共享与保护（可对不同的段赋予不同的存取权限）、便于动态链接与增长；缺点是要为每段分配连续内存，容易产生外部碎片，且段长受内存可用空间限制。分段对用户是可见的。

## 段页式存储管理
段页式存储管理是分页与分段的结合：先把用户程序按逻辑结构分成若干段，再把每段划分成若干页面，内存按页框划分，每段离散装入内存。为实现地址变换，每个进程建立一张段表，每个段建立一张页表，段表项中存放该段页表的始址与页表长度。逻辑地址结构为"段号 + 段内页号 + 页内偏移"。地址变换过程为：由段号查段表得页表始址；由页内页号查页表得物理块号；物理地址 = 块号 × 页面大小 + 页内偏移。段页式兼具分段的逻辑优势与分页的无外部碎片优势，但需要三次访存（段表、页表、数据），同样依赖快表加速，管理开销与硬件复杂度最高。

## 分页与分段的比较
目的方面：分页是为了提高内存利用率、消除外部碎片，满足系统管理需要；分段是为了满足用户编程需要，便于程序模块化与共享保护。信息共享方面：页是物理单位，一个完整的逻辑功能可能被拆散在多个页中，共享不便；段是逻辑单位，一个完整的功能模块可单独共享。大小方面：页大小固定，由硬件或系统决定；段大小不固定，由用户程序逻辑结构决定。地址空间方面：分页的地址空间是一维的，只需一个整数即可表示；分段的地址空间是二维的，需要给出段号和段内偏移。碎片方面：分页只在最后一页产生内部碎片，无外部碎片；分段会产生外部碎片，无内部碎片。
