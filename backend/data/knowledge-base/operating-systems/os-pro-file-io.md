# 文件系统与 I/O 管理

## 文件与文件系统
文件是具有文件名的一组相关信息的集合，是文件系统进行存储与管理的基本单位。文件系统是操作系统中负责管理和存储文件信息的软件机构，其主要功能包括：按名存取，用户只需给出文件名即可访问文件而无需知道其物理位置；文件的组织与存储，包括逻辑结构与物理结构的建立；目录管理，支持高效的按名检索与属性维护；文件的读/写管理与存取控制，保证文件的共享与安全；存储空间管理，负责磁盘空闲块的分配与回收。从用户角度看，文件系统实现了"按名存取"这一最核心的抽象。

## 文件的逻辑结构
文件的逻辑结构指从用户观点出发看到的文件组织形式，与存储介质无关，分为无结构文件和有结构文件。无结构文件（流式文件）由字符流构成，如文本文件、源程序，其长度以字节为单位，管理简单、灵活。有结构文件（记录式文件）由若干记录组成，又分：顺序文件，记录按某种顺序排列，可顺序存取也可在定长记录时随机存取，顺序存取效率最高；索引文件，为变长记录建立索引表，支持按关键字快速随机检索，但索引表本身占用空间；索引顺序文件，把记录分组、每组建立一个索引项，是顺序文件与索引文件的折中；此外还有直接文件和散列文件，可通过哈希直接定位记录。

## 文件目录与目录结构
文件目录用于实现按名存取，目录项包含文件名、文件属性与物理位置等信息。目录结构经历了从单级目录、两级目录到树形目录的演变。单级目录把全部文件放在一张目录表中，不允许重名，多用户环境下冲突严重。两级目录为每个用户建立独立的用户文件目录，不同用户可用相同文件名，但缺乏灵活性。树形目录（多级目录）允许目录嵌套，便于文件分类与保护，是当前主流，但按路径名查找需多次访存。为解决树形目录查找效率问题，可引入索引结点并以文件名哈希组织目录项，还可以设置当前目录减少路径检索长度。

## 文件控制块与索引结点
文件控制块（FCB）是操作系统为管理文件而设置的数据结构，是文件存在的标志，通常包含文件名、文件物理位置、文件逻辑结构、物理结构、存取控制信息和使用信息。目录项即由 FCB 构成。在检索目录时，只需用到文件名即可，为减少磁盘 I/O 次数、提高检索速度，引入索引结点（inode）：把文件名与文件描述信息分开，目录项只保留文件名与索引结点编号，文件的其余描述信息都放在索引结点中。这样目录项很短，一个磁盘块可存放更多目录项，检索时只需读入少量块即可找到目标文件。UNIX/Linux 是这一结构的典型代表。

## 文件的物理结构：连续分配
连续分配要求为每个文件分配一组相邻接的磁盘块，文件的逻辑块号与物理块号一一对应，顺序为 0, 1, 2, …。其优点是：支持顺序访问与随机访问，且访问速度快，因为磁头移动距离小，寻道时间与旋转延迟都较小。缺点是：要求连续的存储空间，易产生外部碎片，磁盘空间利用率低；文件长度必须事先确定，难以动态增长，插入或删除数据需要移动大量数据；此外，反复的创建与删除会造成大量难以利用的空洞，需用紧凑（整理）解决，代价很大。连续分配常用于一次性写入的介质（如 CD-ROM）和早期系统。

## 链接分配
链接分配把文件存放在不连续的磁盘块中，通过指针把各块按逻辑顺序链接起来。隐式链接中，每个磁盘块都包含指向下一块的指针，目录项只需给出首块指针与末块指针；其优点是消除了外部碎片、文件可动态增长，缺点是只适合顺序访问，随机访问需从头遍历，且指针占用空间，一旦指针损坏会导致数据丢失。显式链接把用于链接的指针集中存放在内存的文件分配表（FAT）中，FAT 表项记录下一块号，因此查找可在内存中进行，支持随机访问且减少了访存次数，但 FAT 需常驻内存、占用空间较大，适用于小容量磁盘（如 FAT32）。

## 索引分配与混合索引
索引分配为每个文件建立一张索引表，表中存放该文件各逻辑块对应的物理块号，目录项给出索引表的地址。优点是支持随机访问、文件可动态增长且无外部碎片；缺点是索引表本身占用空间，小文件也必须为其建立索引表，浪费空间。解决办法是采用混合索引（多级索引）结构：例如 UNIX 的 inode 中设置 10 个直接地址项、1 个一级间接项、1 个二级间接项和 1 个三级间接项，小文件用直接地址即可满足，大文件逐级使用间接索引，从而兼顾小文件的访问效率与大文件的容量扩展需求。这种结构使文件的最大长度可达数 GB 甚至更大。

## 文件的共享：硬链接与软链接
硬链接（基于索引结点的共享）让多个目录项指向同一个索引结点，索引结点中设置链接计数，每增加一个链接计数加 1，删除一个链接计数减 1，只有计数为 0 时才真正删除文件。硬链接的优点是共享效率高、访问速度快，不能跨文件系统且不能为目录建立硬链接，因为可能破坏目录的树形结构。软链接（符号链接）创建一个新的文件（链接文件），其内容是另一文件的路径名，访问时需按路径重新检索。软链接可跨文件系统、可指向不存在的文件（悬空链接），但访问开销大且需占用一个索引结点。此外还有利用索引结点中的共享指针实现同一文件被多进程共享的方式。

## 文件保护与访问控制
文件保护用于防止文件被非法访问与破坏，主要手段包括：口令保护，为文件设置口令，用户提供正确口令才可访问，实现简单但口令易泄露且不便于共享管理；加密保护，对文件内容加密，安全性高但增加开销；访问控制，为每个文件设置访问控制表（ACL），按用户或用户组规定其可执行的操作（读、写、执行、删除、列表等）。UNIX 采用精简的访问权限模型：把用户分为文件主、同组用户和其他用户，每类用户具有读、写、执行三位权限，共九位；此外还可设置 setuid、setgid 等特殊权限位，以及文件的属主与属组信息。

## 空闲空间管理
空闲空间管理负责记录磁盘中未被使用的块。位示图（位图）用一位表示一个磁盘块的空闲状态（0 表示空闲、1 表示已分配），优点是可用位运算快速定位空闲块、便于查找连续空闲块，缺点是位图本身占用空间（如每块 1KB、1TB 磁盘即位图约 32MB）。空闲链表把空闲块链成链表，实现简单但查找效率低。成组链接法把一个大型空闲链表分组管理：每组记录若干空闲块号，组内最后一块记录下一组的块号与数量，UNIX 采用此方法，兼顾了空闲表与空闲链表的优点，既便于分配回收又能减少管理信息占用。此外还有空闲表法，为连续空闲区建立表项。

## 文件系统的层次结构与虚拟文件系统
文件系统通常分为若干层次：用户接口层（提供系统调用如 open、read、write）、文件目录层（管理目录与逻辑结构）、文件组织模块（把逻辑块号映射为物理块号）、基本文件系统（管理磁盘块缓冲与块分配）、I/O 控制层（设备驱动与中断处理）。为在同一个操作系统上支持多种具体文件系统（ext4、NTFS、FAT 等），引入虚拟文件系统（VFS）作为抽象层：VFS 定义统一的接口（如 vnode/inode 操作集、目录操作集），各具体文件系统实现这些接口，从而为用户提供统一的文件访问界面。文件系统还需经"挂载"才能被访问，挂载把某个文件系统的根目录附加到已有目录树的某个目录上。

## I/O 控制方式：查询、中断、DMA 与通道
程序查询方式（轮询）：CPU 不断读取设备状态寄存器，直到设备就绪才传送数据，实现简单但 CPU 完全被 I/O 占用，效率极低。中断驱动方式：CPU 发出 I/O 命令后转去执行其他程序，设备完成时以中断通知 CPU，由中断服务程序完成数据传送，减少了等待时间，但每传送一个字节都要中断一次，只适合低速设备。DMA 方式：由 DMA 控制器直接控制设备与内存之间的成块数据传送，CPU 只需预设内存始址、传送字数与方向，传送完成时收到一次中断，数据不经过 CPU，适合高速块设备。通道方式：通道有自己的指令系统，可执行由若干通道指令组成的通道程序，独立控制一组设备的 I/O 操作，CPU 只需发出启动指令，干预最少、并行度最高，形成主机—通道—设备控制器—设备四级连接结构。四种方式对 CPU 的干预程度依次降低，而硬件复杂度与成本依次升高。

## 缓冲技术与 SPOOLing
缓冲技术用于缓和 CPU 与 I/O 设备速度不匹配的矛盾、减少中断次数、提高 CPU 与设备的并行性，常见的有单缓冲、双缓冲、循环缓冲和缓冲池。单缓冲下处理一块数据的时间约为 max(输入时间, 处理时间) + 传送时间；双缓冲下可实现输入与处理并行，时间约为 max(输入时间, 处理时间)；缓冲池由多个缓冲区组成，按空闲、装满、正在处理等状态组织，支持多进程共享，并需用信号量实现同步互斥。SPOOLing（假脱机）技术用磁盘上的输入井与输出井模拟脱机输入输出，再配合内存缓冲区与井管理程序，把独占设备改造为共享设备，最典型的应用是打印机的共享。

## 设备分配与设备独立性
设备分配需考虑设备的固有属性（独占、共享、虚拟）与分配算法。独占设备采用静态分配（作业开始前一次分配到位，可能降低利用率）或动态分配（申请时才分配，但必须防止死锁）。共享设备由多个进程交替使用，分配的是"使用时间"而非设备本身。虚拟设备通过 SPOOLing 把独占设备变成逻辑上的共享设备。设备独立性（设备无关性）指用户程序使用逻辑设备名而非物理设备名申请设备，由系统把逻辑设备映射到某台具体的物理设备，这样当物理设备更换时无须修改程序，提高了系统的灵活性与可扩展性，映射关系由逻辑设备表（LUT）维护。

## 磁盘的结构与访问时间
磁盘由盘面、磁道、扇区构成，多个盘面上半径相同的磁道组成柱面，磁盘地址由柱面号、磁头号（盘面号）、扇区号确定。磁盘访问时间由三部分组成：寻道时间 Ts，指磁头移动到指定磁道所需的时间，可表示为启动磁臂时间 s 与移动 n 条磁道所需时间之和，即 Ts = s + m×n，是三者中最主要的部分；旋转延迟 Tr，指指定扇区旋转到磁头下方所需的时间，若磁盘转速为 r（转/秒）则平均旋转延迟约为 1/(2r)；传输时间 Tt，指读写数据所经历的时间，若每磁道有 N 字节、要读写 b 字节，则 Tt = b/(r×N)。可见提高磁盘访问速度的关键是减少寻道时间，这正是磁盘调度算法的目标。

## 磁盘调度算法：FCFS 与 SSTF
先来先服务（FCFS）按访问请求到达的先后次序服务，公平、简单，不会产生饥饿，但当请求分散时磁头反复往返、寻道时间长，性能较差。最短寻道时间优先（SSTF）优先服务距离当前磁头位置最近的请求，平均寻道时间较短、性能优于 FCFS，但可能导致较远的请求长期得不到服务（饥饿），且磁头移动的局部性较强。举例：请求队列为 98、183、37、122、14、124、65、67，磁头初始在 53，磁道范围 0~199。FCFS 的磁头移动总量为 640 个磁道，而 SSTF 按 53→65→67→37→14→98→122→124→183 的顺序服务，移动总量为 236 个磁道。

## 磁盘调度算法：SCAN、C-SCAN 与 LOOK
扫描算法（SCAN，电梯算法）要求磁头沿一个方向移动并沿途服务请求，到达该方向最边缘的磁道后反转方向再沿途服务，从而避免 SSTF 中磁头在局部来回摆动的问题，且不会饥饿。循环扫描算法（C-SCAN）规定磁头只在一个方向上服务请求，到达端点后快速返回起点且返回途中不服务任何请求，使各磁道等待时间更均匀，适合访问均匀分布的场景。LOOK 算法是 SCAN 的改进：磁头只需移动到该方向上最远的请求处即可反向，不必到达磁盘端点；C-LOOK 同理。NStepSCAN 与 FSCAN 把请求队列分成若干个长度为 N 的子队列并按 SCAN 处理，可避免磁臂粘着现象。

```c
/* 磁盘调度：FCFS / SSTF / SCAN / C-SCAN 的移动磁道数统计
 * 请求序列与磁头初始位置取自经典例子，磁道范围 0~199 */
#include <stdio.h>
#include <stdlib.h>

#define N 8
static int req[N] = {98, 183, 37, 122, 14, 124, 65, 67};
static int start = 53;

static int abs_i(int x) { return x < 0 ? -x : x; }

int fcfs(int head) {                      /* 先来先服务 */
    int total = 0;
    for (int i = 0; i < N; i++) {
        total += abs_i(req[i] - head);
        head = req[i];
    }
    return total;
}

int sstf(int head) {                      /* 最短寻道时间优先 */
    int done[N] = {0}, total = 0;
    for (int k = 0; k < N; k++) {
        int best = -1, bestd = 1 << 30;
        for (int i = 0; i < N; i++) {
            if (done[i]) continue;
            int d = abs_i(req[i] - head);
            if (d < bestd) { bestd = d; best = i; }
        }
        total += bestd;
        head = req[best];
        done[best] = 1;
    }
    return total;
}

int scan(int head) {                      /* 电梯算法：先向磁道号增大方向，再到端点 199 */
    int total = 0, maxr = req[0], moved = 0;
    for (int i = 1; i < N; i++) if (req[i] > maxr) maxr = req[i];
    /* 递增方向服务所有大于 head 的请求 */
    for (int cur = head; cur <= maxr; cur++) {
        for (int i = 0; i < N; i++) if (req[i] == cur) { total += cur - head; head = cur; moved = 1; }
    }
    total += abs_i(199 - head);           /* 移动到端点 */
    head = 199;
    /* 反向服务剩余请求（按递减顺序） */
    for (int cur = 199; cur >= 0; cur--) {
        for (int i = 0; i < N; i++) if (req[i] == cur && cur < 53) { total += head - cur; head = cur; }
    }
    (void)moved;
    return total;
}

int main(void) {
    printf("FCFS = %d\n", fcfs(start));
    printf("SSTF = %d\n", sstf(start));
    printf("SCAN = %d\n", scan(start));   /* 331 */
    return 0;
}
```

## 磁盘管理与提高 I/O 速度的方法
磁盘管理包括磁盘格式化（低级格式化划分扇区并写入校验信息，分区，高级格式化建立文件系统）、引导块管理（磁盘启动块中存放引导程序）、坏块处理（用扇区备用技术或把坏块登记在文件分配表中以避免使用）。提高磁盘 I/O 速度的常用方法有：磁盘高速缓存（把常用数据保留在内存缓冲区中，按 LRU 等算法置换）；提前读与延后写（利用局部性一次读入多块、把写操作先写入缓冲区再异步写回）；优化物理块布局（把同一文件的块放在同一柱面或相邻柱面以减少寻道）；使用磁盘阵列（RAID）通过数据分条、镜像与奇偶校验提高吞吐量与可靠性，常见级别包括 RAID0 分条、RAID1 镜像、RAID5 分布式奇偶校验；此外还有固态盘（SSD）等新型存储介质，其无机械寻道、随机访问快，但存在写放大与寿命限制。
