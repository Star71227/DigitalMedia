# 虚拟内存与页面置换

## 局部性原理
虚拟存储技术的理论基础是程序执行的局部性原理，包括时间局部性和空间局部性。时间局部性指程序中的某条指令或数据一旦被执行或访问，不久后可能再次被执行或访问，典型原因是程序中存在大量循环。空间局部性指程序一旦访问了某个存储单元，不久后其附近的存储单元也将被访问，典型原因是程序顺序执行、数组按行存放并按序访问。局部性原理说明程序在一段时间内只使用其地址空间的一小部分，因此可以把当前需要的部分调入内存，其余留在外存，从而在逻辑上扩充内存容量。

## 虚拟内存的定义与特征
虚拟内存是指具有请求调入功能和置换功能，能从逻辑上对内存容量加以扩充的一种存储器系统，其逻辑容量由内存容量与外存容量之和决定，运行速度接近内存而每位成本接近外存。虚拟内存有三个主要特征：多次性，一个作业被分成多次调入内存运行，无需在运行时一次性全部装入；对换性，作业运行时允许在内存与外存之间换入换出；虚拟性，从逻辑上扩充了内存容量，用户看到的内存远大于实际内存。虚拟内存的实现方式有请求分页、请求分段和请求段页式三种。

## 请求分页的页表机制
请求分页系统在基本分页的基础上扩充页表项，除页号与物理块号外还增加若干字段：状态位（存在位），指示该页是否已调入内存；访问位（引用位），指示该页在最近一段时间内是否被访问过，供置换算法参考；修改位（脏位），指示该页调入后是否被修改，若未修改可直接丢弃、若已修改则必须写回外存；外存地址，指出该页在外存上的存放位置（如对换区地址或文件地址）。缺页中断机构依据状态位判断访问的页是否在内存中，若不在则产生缺页中断。

## 缺页中断与地址变换
缺页中断是一种特殊的中断：它在指令执行期间而非一条指令执行完毕后产生，属于内部异常，且一条指令在执行过程中可能产生多次缺页中断（如跨页的指令或跨页的数据访问）。缺页中断的处理过程为：保留 CPU 现场；由硬件查出缺页的逻辑地址；若内存中还有空闲块则直接分配，否则按置换算法选择一页淘汰，若该页被修改过则先写回外存；从外存把所需页调入内存；修改页表项；恢复现场并重新执行引起缺页的那条指令。地址变换在基本分页的基础上增加了"检查存在位"与"缺页处理"两个环节。

## 具有快表和缺页处理的地址变换
完整的访存过程为：先查快表，命中则直接形成物理地址访问；未命中则查内存中的页表，若页表项状态位为 1（已在内存）则把该页表项送入快表并按块号访问内存，若状态位为 0 则产生缺页中断。由于每个进程有自己的页表，进程切换时必须更换页表寄存器内容并使快表失效（或给快表项加上进程标识 ASID）。由于存在缺页与置换，同一进程对同一逻辑地址的两次访问，其物理地址可能不同，这也是虚拟内存"对用户透明"的重要体现。有效访问时间的计算需分别考虑快表命中、页表命中与缺页三种情形及其概率。

## 最佳置换算法 OPT
最佳置换算法选择以后永不使用、或在最长时间内不再被访问的页面淘汰，它能保证获得最低的缺页率，但由于需要预知未来的访问序列而无法实现，仅作为衡量其他算法优劣的标准（理论下界）。例如对访问串 7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1，当分配 3 个页框时 OPT 发生 9 次缺页，FIFO 发生 15 次、LRU 发生 12 次，可见 OPT 明显最优。OPT 与 LRU 都属于堆栈类算法，不会出现 Belady 异常。

## 先进先出置换算法 FIFO
FIFO 总是淘汰最先进入内存的页面，即选择在内存中驻留时间最久的页面淘汰，实现简单，只需把调入内存的页面按先后次序链成队列。其缺点是它只考虑页面驻留时间而不考虑页面的使用情况，可能淘汰经常被访问的页面，因而性能较差。更严重的是 FIFO 可能出现 Belady 异常：分配的页框数增多时缺页次数反而增加。典型例子是访问串 1,2,3,4,1,2,5,1,2,3,4,5，用 3 个页框时缺页 9 次，用 4 个页框时缺页 10 次。产生该异常的根本原因是 FIFO 算法不满足堆栈算法的性质。

## 最近最久未使用算法 LRU
LRU 选择最近最久未使用的页面予以淘汰，它以"最近的过去"作为"最近的将来"的近似，认为过去一段时间内不曾被使用的页面在将来也不会被立即使用。对上述访问串，3 个页框时 LRU 的缺页次数为 12 次，优于 FIFO 的 15 次。LRU 属于堆栈类算法，不会出现 Belady 异常，性能接近 OPT，但实现代价高：需要为每个页面记录访问时间戳或维护访问栈，硬件上通常需要寄存器或计数器，且每次访存都要更新，开销大。因此实际系统多采用其近似算法如 CLOCK。

```c
/* LRU 页面置换的简化模拟：用访问计数器的相对大小近似"最近最久未使用" */
#include <stdio.h>
#include <limits.h>

#define FRAMES 3
#define NPAGES 20

int frames[FRAMES];      /* 页框中的页号，-1 表示空闲 */
int last_used[FRAMES];   /* 各页框最近一次被访问的时刻 */
int clock_tick = 0;

int access_page(int page) {           /* 返回 1 表示发生缺页 */
    for (int i = 0; i < FRAMES; i++) {
        if (frames[i] == page) {      /* 命中：更新访问时刻 */
            last_used[i] = ++clock_tick;
            return 0;
        }
    }
    int victim = 0;                   /* 未命中：找最久未使用的页框 */
    for (int i = 0; i < FRAMES; i++) {
        if (frames[i] == -1) { victim = i; break; }        /* 优先使用空闲块 */
        if (last_used[i] < last_used[victim]) victim = i;
    }
    frames[victim] = page;
    last_used[victim] = ++clock_tick;
    return 1;                         /* 缺页，淘汰 frames[victim] 的旧页 */
}
```

## CLOCK 置换算法与改进型
CLOCK（最近未用 NRU）算法为每页设置一个访问位，把内存中的页面通过链接指针链成循环队列。需要淘汰时检查指针所指页面的访问位：若为 0 则淘汰该页；若为 1 则把它清 0 并让指针后移，继续检查下一页。该算法是 LRU 的近似，开销小、实现简单。改进型 CLOCK 算法同时考虑访问位 A 与修改位 M，按 (A, M) 分为四类，淘汰顺序依次为 (0,0) 未访问未修改（最佳淘汰对象，无需写回）、(0,1) 未访问已修改（需写回）、(1,0)、(1,1)；扫描过程中把遇到的访问位清 0 以便下一轮扫描，最多扫描四轮即可找到可淘汰页。

## 置换算法的比较与选择
从缺页率看，OPT 最优但不可实现，LRU 与 OPT 接近，CLOCK 略逊于 LRU，FIFO 最差且可能出现 Belady 异常。从实现开销看，FIFO 最简单，CLOCK 次之，LRU 需要额外硬件支持、开销最大。从是否满足堆栈性质看，OPT 与 LRU 是堆栈类算法，不会出现 Belady 异常；FIFO 与 CLOCK 不是堆栈类算法，理论上可能出现异常（CLOCK 的异常情况在实践中极为罕见）。实际系统常把 LRU 近似算法与页面的访问位、修改位结合，并借助硬件提供的引用位与脏位实现。

## 缺页率与影响缺页率的因素
缺页率 f = 缺页次数 / 总访问次数。影响缺页率的因素包括：页面大小，页面过小则页表项多、缺页频繁且 I/O 次数多，页面过大则产生较多内部碎片且局部性变差，需折中；分配给进程的页框数，页框越多缺页率越低，但多道程序度会下降；页面置换算法，算法越好缺页率越低；程序本身的局部性，局部性好则缺页率低；程序编制方法，如数组按行存放却按列访问会显著恶化空间局部性。有效访问时间 = (1 − f) × 访存时间 + f × 缺页处理时间，由于缺页处理时间通常是访存时间的数万倍，因此必须把缺页率控制得极低。

## 抖动与工作集
抖动（颠簸）是指刚被换出的页面很快又要被访问，于是再次调入，如此频繁地换入换出，使系统把大部分时间花在页面调度上而几乎不能完成有效工作。产生抖动的根本原因是分配给进程的页框数少于其运行所需的页面数，直接诱因往往是多道程序度过高。解决办法包括：采用局部置换策略限制抖动波及范围；引入工作集模型，为进程分配不小于其工作集的页框数；调整多道程序度，必要时挂起部分进程以腾出内存。工作集指某段时间间隔 Δ（工作集窗口）内进程实际访问的页面集合，记为 W(t, Δ)，其大小随 Δ 增大而增大并趋于稳定，系统应保证分配页框数略大于工作集大小。

```c
/* 工作集窗口模拟：统计窗口内出现过的不同页面数，用于判断是否发生抖动 */
#define WINDOW 5
#define NPAGES 20

int in_window[NPAGES];     /* 标记页面是否在当前窗口内 */
int queue[WINDOW];         /* 按时间顺序保存最近 WINDOW 次访问 */
int qhead = 0, qcount = 0, wss = 0;

void on_reference(int page) {
    if (!in_window[page]) {          /* 新页面进入窗口，工作集增大 */
        in_window[page] = 1;
        wss++;
    }
    if (qcount == WINDOW) {          /* 窗口已满：移出最老的访问记录 */
        int old = queue[qhead];
        int still = 0;
        for (int i = 0; i < qcount; i++) {              /* 检查是否仍在窗口内 */
            int idx = (qhead + 1 + i) % WINDOW;
            if (qcount > 1 && queue[idx] == old) { still = 1; break; }
        }
        if (!still) { in_window[old] = 0; wss--; }
    } else {
        qcount++;
    }
    queue[qhead] = page;
    qhead = (qhead + 1) % WINDOW;
    /* 若 wss 持续接近或超过分配的页框数，说明进程分到的内存偏少，可能抖动 */
}
```

## 页面分配策略与调入策略
页面分配策略分为固定分配与可变分配：固定分配为每个进程分配固定数目的页框，运行期间不变；可变分配则根据缺页情况动态调整。置换范围分为局部置换与全局置换：局部置换只在本进程的页面中选页淘汰，不会影响其他进程，但难以反映各进程的真实需求；全局置换可从系统中任选一页淘汰，能动态调节各进程的页框数，但可能把其他进程急需的页面换出。常把两者组合使用：固定分配局部置换（实现简单但难以确定合适页框数）、可变分配全局置换（易实现但可能降低其他进程性能）、可变分配局部置换（根据缺页率动态增减页框，性能最好但实现复杂）。

## 调入页面的时机与写回策略
调入页面的时机有两种：预调页策略，根据局部性原理在进程运行前或运行中成批调入若干相邻页面，一次调入多页可减少 I/O 次数，但预测不准会浪费内存；请求调页策略，仅在访问到不在内存的页面时才调入，内存利用率高但每次都产生一次缺页中断与磁盘 I/O。实际系统常把二者结合，如进程首次创建时预调入一批页面。页面写回也有两种策略：系统为每页设置修改位，被修改过的页面在被淘汰时必须写回外存；另一种做法是不设修改位，凡被淘汰的页面一律写回，实现简单但增加 I/O 次数。

## 写时复制与内存映射文件
写时复制（COW）是虚拟内存的重要应用：fork 创建子进程时不复制父进程的地址空间，而是让父子进程共享同一组物理页面，并把它们标记为只读；当任一进程试图写入某页时触发保护异常，内核此时才为该进程复制一页并改为可写。这样避免了大量无用的复制，显著提高了 fork 的效率。内存映射文件把文件或设备的一段内容映射到进程的地址空间，进程对内存的读写等价于对文件的读写，由缺页机制按需把文件页调入内存、由页面置换机制写回，简化了文件 I/O 编程，也便于多个进程共享文件内容。此外，页面置换与写回策略共同决定了系统的 I/O 负载，需与文件系统缓冲区管理协同。

## 请求分段存储管理
请求分段在基本分段的基础上增加请求调入与置换功能：段表项中增加存在位、访问位、修改位、外存始址以及存取权限等字段。当访问的段不在内存时产生缺段中断，操作系统检查内存中是否有足够大的连续空闲区：若有则调入；若空闲区总容量够但不连续则可拼接或淘汰若干段；若容量不够则需先淘汰部分段再调入。由于段的长度不等，段的置换比页面置换复杂，而且段在内存中必须连续存放，容易产生外部碎片。请求分段同样可以实现虚拟存储，其优点是便于以逻辑模块为单位共享与保护，缺点是实现与管理开销较大。
