# 信号量与经典同步问题

## 整型信号量
信号量是 Dijkstra 提出的一种用于解决进程同步与互斥的工具。整型信号量被定义为一个整型变量 S，仅能通过两个原子操作访问：wait(S)（又称 P 操作）执行 S = S − 1，若 S < 0 则继续测试；signal(S)（又称 V 操作）执行 S = S + 1。当 S ≤ 0 时表示资源已分配完，进程必须等待。整型信号量的主要缺陷是：当 S < 0 时进程仍不断测试，处于忙等待（自旋）状态，违背了同步机制的"让权等待"原则，浪费处理机时间。

## 记录型信号量
为克服忙等待，引入记录型信号量，其数据结构除整型值 value 外，还包含一个进程等待队列（PCB 链表）L。P 操作先令 value 减 1，若仍大于等于 0 表示尚有资源可用，进程可继续；否则执行 block 原语，把进程插入等待队列 L 并放弃处理机。V 操作令 value 加 1，若加后 value ≤ 0，说明等待队列中仍有进程在等待，于是执行 wakeup 原语唤醒队首进程。此时 value 的绝对值等于因等待该信号量而阻塞的进程数目，且 value ≤ 0 表示仍有进程在等待。

```c
/* 记录型信号量：value 为资源数目，L 为等待队列（此处用抽象原语表示） */
typedef struct {
    int value;          /* 可用资源数；为负时其绝对值等于等待进程数 */
    struct pcb *L;      /* 指向等待队列队首 */
} semaphore;

void wait(semaphore *S) {          /* P 操作：申请资源 */
    S->value--;
    if (S->value < 0) {
        /* 资源不足：把当前进程插入 S->L 队尾，并阻塞，放弃处理机 */
        block(S->L);
    }
}

void signal(semaphore *S) {        /* V 操作：释放资源 */
    S->value++;
    if (S->value <= 0) {
        /* 仍有进程在等待：唤醒队首进程，将其插入就绪队列 */
        wakeup(S->L);
    }
}
```

## P、V 操作的语义与使用要点
P 操作代表申请一个资源，V 操作代表释放一个资源，二者必须配对出现，且在同一进程中通常遵循"先申请后释放"的顺序，但同步信号量与互斥信号量的配对方式不同。P、V 操作本身是原语，其执行不可中断。使用要点包括：P 操作可能引起阻塞，因此不能放在临界区内；对互斥信号量，P 操作必须在进入临界区之前、V 操作必须在退出临界区之后；多个信号量的 P 操作顺序不当会造成死锁（例如两个进程分别先申请不同资源），而 V 操作的顺序一般不影响正确性。信号量的初值具有明确物理含义：互斥信号量初值为 1，同步信号量初值通常为 0 或资源的初始数量。

## 用信号量实现互斥
为每个临界资源设置一个互斥信号量 mutex，初值为 1，取值范围为 (−1, 0, 1]。进程在进入临界区前执行 wait(mutex)，退出临界区后执行 signal(mutex)，从而保证互斥访问。由于 mutex 初值为 1，第一个执行 P 操作的进程把其减为 0 并进入临界区；第二个进程执行 P 后 mutex 变为 −1 而被阻塞，其含义是有一个进程在等待。当第一个进程执行 V 操作后 mutex 变为 0 并唤醒等待者。若 mutex 初值大于 1，则表示该资源有多个副本（如打印机数量、缓冲区槽位数），可实现"每次允许 N 个进程访问"的计数信号量语义。

```c
#include <pthread.h>
/* 用互斥信号量保护共享计数器：临界区只有加一，属于短临界区 */
static pthread_mutex_t mutex = PTHREAD_MUTEX_INITIALIZER;   /* 相当于初值为 1 的信号量 */
static int shared = 0;

void *worker(void *arg) {
    (void)arg;
    for (int i = 0; i < 1000; i++) {
        pthread_mutex_lock(&mutex);     /* P(mutex) */
        shared++;                       /* 临界区：访问临界资源 */
        pthread_mutex_unlock(&mutex);   /* V(mutex) */
    }
    return NULL;
}
```

## 用信号量实现同步（前趋关系）
若要求进程 P1 中语句 S1 执行完后，进程 P2 中的语句 S2 才能执行，则称 S1 与 S2 存在前趋关系。实现方法是设置一个初值为 0 的同步信号量 S，在 P1 中 S1 之后执行 signal(S)，在 P2 中 S2 之前执行 wait(S)。由于初值为 0，P2 若先到达则会被阻塞，直到 P1 完成 S1 后执行 V 操作把它唤醒。对于更复杂的前趋图，可为每条有向边设置一个信号量，边的起点执行 V，终点执行 P。这种"前趋图 + 每条边一个信号量"的模式是同步问题建模的基本方法。

## 生产者-消费者问题
生产者-消费者问题是最经典的同步问题：一组生产者进程向缓冲区投放产品，一组消费者进程从缓冲区取走产品，缓冲区容量为 n。需要正确处理三种关系：任何时刻只允许一个进程访问缓冲区（互斥关系，用 mutex 初值 1）；缓冲区未满时生产者才能投放（同步关系，用 empty 初值 n 表示空缓冲区数）；缓冲区非空时消费者才能取走（同步关系，用 full 初值 0 表示产品数）。其中 empty + full = n 恒成立。解决即是在生产者中先 P(empty) 再 P(mutex)，投放后 V(mutex) 再 V(full)；消费者中先 P(full) 再 P(mutex)，取出后 V(mutex) 再 V(empty)。

```c
/* 生产者-消费者：缓冲区容量 n，互斥访问 + 双向同步 */
#include <pthread.h>
#define N 8
static int buf[N], in = 0, out = 0;
static pthread_mutex_t mutex = PTHREAD_MUTEX_INITIALIZER;
static sem_t empty, full;              /* POSIX 信号量，等价于记录型信号量 */

void *producer(void *arg) {
    for (int i = 0; i < 20; i++) {
        int item = i;
        sem_wait(&empty);              /* P(empty)：等待空缓冲区，必须放在 P(mutex) 之前 */
        pthread_mutex_lock(&mutex);    /* P(mutex)：互斥访问缓冲区 */
        buf[in] = item;
        in = (in + 1) % N;
        pthread_mutex_unlock(&mutex);  /* V(mutex) */
        sem_post(&full);               /* V(full)：产品数加一 */
    }
    return NULL;
}

void *consumer(void *arg) {
    for (int i = 0; i < 20; i++) {
        sem_wait(&full);               /* P(full)：等待产品 */
        pthread_mutex_lock(&mutex);
        int item = buf[out];
        out = (out + 1) % N;
        pthread_mutex_unlock(&mutex);
        sem_post(&empty);              /* V(empty)：空缓冲区加一 */
        (void)item;
    }
    return NULL;
}

void setup(void) {
    sem_init(&empty, 0, N);            /* 初值 n：空缓冲区个数 */
    sem_init(&full, 0, 0);             /* 初值 0：产品个数 */
}
```

## 生产者-消费者问题的错误分析
常见错误有三类。其一，交换 P 操作的顺序：若生产者先执行 P(mutex) 再执行 P(empty)，当缓冲区已满时，生产者持有互斥锁后阻塞在 empty 上，消费者因无法获得 mutex 而不能取走产品，双方形成死锁。因此互斥信号量的 P 操作必须放在资源信号量 P 操作之后。其二，遗漏 V 操作：若生产者忘记 V(full)，消费者最终会永久阻塞；若忘记 V(empty)，缓冲区最终会"虚假占满"。其三，把 V 操作也放入临界区内：虽然不影响正确性，但可能造成不必要的唤醒延迟，一般建议 V(mutex) 放在资源 V 操作之前、并把释放资源的 V 放在临界区外。

## 读者-写者问题
读者-写者问题描述对共享数据的访问：允许多个读者同时读，但不允许多个写者同时写，也不允许读者与写者同时访问。这与生产者-消费者的显著区别是读者之间不互斥，因此需要用一个整型变量 count 记录当前读者数目，并用互斥信号量 mutex 保护 count 的修改；读写互斥由信号量 rw 实现，第一个读者进入时 P(rw)，最后一个读者离开时 V(rw)。读者优先方案中，只要不断有读者到来，写者就可能一直等待（写者饥饿）。

## 写者优先与公平策略
为缓解写者饥饿，可采用写者优先策略：增加信号量 w，当有写者到达时先 P(w) 阻止后续读者进入，待已有读者全部离开后写者开始写，写完后 V(w) 释放。另一种常用做法是使用信号量队列，让读者与写者按到达顺序排队，实现读写公平。还可以用"最多允许 RN 个读者同时读"的信号量方案限制并发读者数。需要注意的是，写者优先可能导致读者饥饿，实际系统（如读写锁）通常根据应用特征选择策略，许多实现还提供读写锁的升级与降级操作。

## 哲学家进餐问题
哲学家进餐问题描述五位哲学家围坐圆桌，两两之间放一根筷子，哲学家需要同时拿起左右两根筷子才能进餐，进餐完毕放下筷子继续思考。若每个哲学家都先拿左边筷子再等右边筷子，当五人同时拿起左边筷子时，每人都在等待右边筷子，系统进入死锁。解决方法包括：至多允许四位哲学家同时拿筷子（用初值为 4 的信号量控制）；仅当左右两根筷子都可用时才允许拿（AND 型信号量或互斥地拿筷子）；采用奇偶编号策略，奇数号哲学家先拿左再拿右、偶数号反之，从而打破循环等待条件。

## AND 型信号量与信号量集
AND 型信号量（同时型信号量）把一次申请多个资源作为一个原子操作，其 P 操作形如 Swait(S1, S2, …, Sn)，仅当所有 Si 都满足条件时才分配，否则一个也不分配，从而避免死锁。信号量集机制进一步允许一次申请多个某类资源和设置测试下限：Swait(S1, t1, d1, …, Sn, tn, dn) 表示要求 Si ≥ ti 时方可分配 di 个资源，Ssignal 则一次性释放所有相应资源。这类机制在需要同时获得多种资源的场景（如哲学家同时拿两根筷子、进程同时申请内存与设备）中能有效防止死锁。

## 信号量题目的分析方法
解题一般按四步进行：第一步，确定进程（角色）数量与各自的循环体动作；第二步，找出所有互斥关系，为每个临界资源设一个初值为 1 的互斥信号量；第三步，找出所有同步与前后制约关系，为每条"必须等待"的约束设一个初值为 0（或资源初始数量）的同步信号量，并明确谁执行 P、谁执行 V；第四步，检查 P 操作顺序（资源信号量在前、互斥信号量在后）、检查每个 P 是否都有配对的 V、检查是否存在死锁与饥饿的可能。最后可用信号量取值范围与不变式（如 empty + full = n）验证方案正确性。
