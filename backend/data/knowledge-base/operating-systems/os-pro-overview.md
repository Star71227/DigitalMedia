# 操作系统概述与运行机制

## 操作系统的定义
操作系统是控制和管理整个计算机系统的硬件与软件资源、合理地组织调度作业与用户程序、并向上层提供方便接口和环境的程序集合。从资源管理者的观点看，它负责管理处理机、存储器、设备和文件；从用户观点看，它通过命令接口、程序接口（系统调用）和图形界面提供服务；从虚拟机的观点看，它把裸机改造成功能更强、使用更方便的扩展机器。操作系统是最基本的系统软件，处于硬件与应用程序之间，其他所有软件都建立在它之上。

## 操作系统的基本功能
操作系统的主要功能可归纳为五类管理。处理机管理负责进程控制、同步、通信、调度与死锁处理，使处理机高效运行。存储器管理负责内存分配与回收、地址映射、内存保护与扩充（虚拟内存）。设备管理负责缓冲管理、设备分配、设备驱动与虚拟设备。文件管理负责文件的存储空间管理、目录管理、读写管理与存取控制。作业管理（用户接口管理）负责作业的提交、调度和用户与系统的交互。此外还提供中断异常处理、时钟管理、安全机制等支撑功能。

## 操作系统的特征之一：并发与共享
并发是指两个或多个事件在同一时间间隔内发生，宏观上"同时"、微观上交替；并行则要求同一时刻真正同时执行，通常需要多处理机（或多核）支持。共享即资源共享，分为互斥共享（如打印机，一段时间内只允许一个进程访问）和同时共享（如磁盘文件，多个进程可"同时"读取）。并发与共享互为存在条件：没有并发就谈不上共享，没有共享则并发进程无法协调推进。并发和共享是操作系统最基本的特征。

## 操作系统的特征之二：虚拟与异步
虚拟是指把一个物理实体变成多个逻辑对应物，包括时分复用（如虚拟处理机、虚拟设备）和空分复用（如虚拟存储器）。异步是指进程的执行不是一贯到底的，而是走走停停，以不可预知的速度向前推进；但只要运行环境相同、初始条件相同，结果就应当一致。异步性给操作系统带来了同步与互斥的问题。并发、共享、虚拟、异步四个特征中，并发和共享是最基本的，虚拟和异步由它们派生而来。

## 操作系统的发展：手工操作与批处理
早期计算机采用手工操作方式，用户通过插拔线路或纸带直接控制机器，人机矛盾突出，资源利用率极低。批处理系统把一批作业以脱机方式交给系统自动依次处理，解决了人机矛盾。单道批处理系统内存中只保留一道作业，作业运行期间 CPU 会因等待 I/O 而空闲；多道批处理系统在内存中同时存放多道作业，当一道作业等待 I/O 时 CPU 立即转去执行另一道作业，从而实现处理机与设备、设备与设备之间的并行工作，显著提高资源利用率和系统吞吐量，但平均周转时间长、无交互能力。

## 操作系统的发展：分时系统
分时系统把处理机的运行时间划分成很短的时间片，按时间片轮流把处理机分配给各联机作业使用。其特点是：同时性（多个用户同时使用一台计算机）、独立性（用户彼此不干扰，感觉各自独占主机）、及时性（用户请求能在较短时间内获得响应）、交互性（用户可以通过终端方便地对话与调试程序）。分时系统必须解决及时接收与及时处理两个问题，通常采用多路卡实现多路复用，并借助作业控制、命令处理和系统调用接口为用户服务。

## 操作系统的发展：实时系统
实时系统要求系统能及时响应外部事件的请求，在规定的时间内完成对该事件的处理并控制所有实时任务协调一致地运行。按用途分为实时控制系统（如飞行控制、工业过程控制）和实时信息处理系统（如订票系统）。其最重要的特点是及时性和高可靠性，通常不追求资源利用率，而是留有较大余量并用双机热备等方式保证可靠性。实时任务分为硬实时任务（必须在绝对截止时间前完成，否则造成灾难）和软实时任务（偶尔超时只降低服务质量）。

## 操作系统的其他分类
除批处理、分时、实时三类基本类型外，还有：网络操作系统，在通用操作系统基础上增加网络通信与资源共享功能；分布式操作系统，由多台独立计算机经网络互联，统一调度与分配任务，具有透明性、可靠性和并行性；嵌入式操作系统，运行于嵌入式设备，强调实时性、可裁剪性和低功耗；个人计算机操作系统，强调易用性与图形界面；服务器操作系统，强调可靠性与并发服务能力。现代操作系统往往兼具多种类型的特点。

## 运行机制：内核态与用户态
为了保证系统安全，CPU 至少划分为两种运行状态。内核态（管态、核心态）可以执行包括特权指令在内的全部指令，可访问所有寄存器和存储区；用户态（目态）只能执行非特权指令，访问受限资源。区分两种状态的意义在于把可能危害系统的操作限制在内核态完成。CPU 状态标志位（PSW 中的一位）记录当前状态，用户程序请求操作系统服务时，必须通过系统调用或中断/异常由用户态陷入内核态，处理完毕后再返回用户态。

## 特权指令与非特权指令
特权指令是指不允许用户程序直接使用的指令，如 I/O 指令、置中断屏蔽字、清内存、修改 PSW、停机指令、设置时钟、切换进程等涉及系统资源分配的指令。非特权指令包括算术运算、逻辑运算、取数、寄存器间传送、访存（在受限范围内）、转移等。CPU 在用户态执行到特权指令会产生非法指令异常并陷入内核处理。判断一条指令是否特权指令的关键，是看它是否会破坏系统或其他程序的正常运行。

## 中断与异常
中断（外中断）指来自 CPU 外部、与当前执行的指令无关的事件，如 I/O 完成中断、时钟中断、键盘中断，其中断时机与指令执行异步。异常（内中断）指源自 CPU 内部、与当前执行指令有关的事件，如除零、地址越界、缺页、非法操作码、系统调用（访管指令也称 trap），属于同步事件。中断处理过程一般包括：关中断、保存断点和现场、判优、转入中断服务程序、恢复现场、开中断并返回。中断机制是操作系统实现并发、实现用户态与内核态切换、实现设备驱动的基石。

## 系统调用
系统调用是操作系统提供给应用程序的编程接口，是用户程序请求内核服务的唯一合法途径，运行在内核态。常见的系统调用类别包括：设备管理（如打开、关闭、读写设备）、文件管理（创建、删除、打开、关闭、读、写）、进程控制（创建、撤销、等待、阻塞、唤醒）、进程通信、内存管理（分配、释放）等。系统调用的处理过程为：用户程序传递参数并执行陷入指令（访管指令）→ 硬件保存现场并转入内核态 → 内核根据系统调用号查表执行相应服务例程 → 返回结果并恢复用户态继续执行。

## 系统调用与库函数的区别
库函数是语言或第三方库提供的函数，运行在用户态，其中一部分只是对系统调用的封装（如 C 语言中的 printf 最终调用 write 系统调用），另一些则完全在用户态完成（如 strcpy、数学函数）。因此，库函数不一定是系统调用，系统调用也不一定以库函数的形式出现。用户程序不能直接调用内核例程，必须经过陷入机制，这既保证了安全性，也保证了接口的稳定性。

## 系统调用示例
下面的程序演示了文件类系统调用的典型用法：open 建立或打开文件并返回文件描述符，write 把用户缓冲区中的数据写入文件，close 释放该描述符。这些调用都由 glibc 封装，最终通过陷入指令进入内核态执行；调用失败时内核不抛出异常，而是返回负值并把错误码写入 errno，因此每次系统调用后都应检查返回值。文件描述符是一个小的非负整数，是内核中打开文件表的索引，用户程序只能通过它间接操作文件，不能直接访问内核数据结构。
```c
#include <stdio.h>
#include <unistd.h>
#include <fcntl.h>
#include <sys/types.h>

int main(void) {
    const char *msg = "hello os\n";
    /* open/write/close 均为系统调用，由 glibc 封装后触发陷入指令 */
    int fd = open("demo.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) {          /* 出错时内核通过返回负值报告，errno 给出原因 */
        perror("open");
        return 1;
    }
    ssize_t n = write(fd, msg, 9);
    if (n != 9) {
        perror("write");
    }
    close(fd);
    return 0;
}
```

## 宏内核结构
宏内核（单内核）把进程管理、内存管理、文件系统、设备驱动、网络协议栈等几乎所有系统功能都放在内核态、同一个地址空间内实现，模块之间通过函数调用直接交互，因此执行效率高、调用开销小。缺点是内核庞大、耦合度高，一处缺陷可能危及整个系统；修改或增加功能往往需要重新编译内核并重启；可维护性与可靠性较差。传统 UNIX、Linux 采用宏内核结构，Linux 通过可加载内核模块（LKM）在一定程度上弥补了动态扩展能力。

## 微内核结构
微内核只把最基本的功能（进程与线程管理、低级存储管理、中断与陷入处理、进程间通信 IPC）保留在内核态，把文件系统、设备驱动、网络协议等移到用户态以服务器进程方式实现，服务器之间通过微内核提供的消息传递通信。优点是内核小、结构清晰、可靠性和安全性高、易扩展和移植、支持分布式；缺点是用户态与内核态频繁切换、消息传递带来较大开销，性能低于宏内核。典型代表包括 Mach、QNX、Minix 3 以及采用混合内核的 Windows NT 系列与 macOS（XNU）。

## 其他内核结构与操作系统的引导
除宏内核与微内核外，还有分层结构（把操作系统分为若干层，每层只使用下层提供的服务）、外核结构（内核只负责资源的安全分配，把硬件抽象交由用户态库实现）以及混合内核。操作系统的启动过程为：CPU 复位后执行固化在 ROM 中的引导程序（BIOS/UEFI）完成硬件自检并找到启动设备；读入引导扇区中的引导加载程序（如 GRUB），由其把内核映像装入内存；内核完成初始化（建立页表、初始化时钟与中断、加载驱动）后创建第一个用户态进程并进入正常运行状态。
