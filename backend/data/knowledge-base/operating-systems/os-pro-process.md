# 进程与线程

## 进程的定义与特征
在多道程序环境下，程序不能独立运行，它必须以进程的形式参与并发执行。进程是进程实体的运行过程，是系统进行资源分配和调度的基本单位。进程实体（进程映像）由程序段、数据段和进程控制块 PCB 三部分组成，有时把进程实体简称为进程。进程具有四个基本特征：动态性（进程是程序的一次执行过程，有创建、活动、暂停、终止的生命周期，这是进程最基本的特征）、并发性（多个进程实体同时存在于内存中并可并发执行）、独立性（进程是能独立运行、独立获得资源和独立接受调度的基本单位）、异步性（进程按各自独立、不可预知的速度推进）。

## 进程与程序的区别
程序是静态的指令集合，可以长期保存；进程是动态的执行过程，有生命周期。一个程序可以对应多个进程（如同时打开多个记事本），一个进程也可以调用多个程序（如进程先执行编译程序再执行链接程序）。程序是永久的，进程是暂时的。此外，进程还具有并发性和独立性，而程序本身不具备运行能力，只有被装入内存并建立 PCB 后才成为进程。

## 进程控制块 PCB
PCB 是进程存在的唯一标志，操作系统通过 PCB 感知进程的存在。PCB 中通常包含四类信息。进程描述信息：进程标识符 PID、用户标识符 UID。进程控制和管理信息：进程当前状态、优先级、程序入口地址、已执行时间、时间片剩余、事件（阻塞原因）。资源分配清单：程序段和数据段的指针、内存大小与地址、打开文件列表、使用的 I/O 设备。处理机相关信息（现场保护）：通用寄存器值、指令计数器 PC、程序状态字 PSW、栈指针。进程被创建时申请 PCB，被撤销时回收 PCB，PCB 常驻内存并组成就绪队列、阻塞队列等。

## 进程的基本状态
最基本的三种状态是就绪态、运行态和阻塞态。就绪态指进程已获得除处理机以外的一切所需资源，只要再获得处理机便可立即执行。运行态指进程已获得处理机，其程序正在处理机上执行，单处理机上任一时刻最多只有一个进程处于运行态。阻塞态（等待态）指进程正在等待某一事件发生（如等待 I/O 完成、等待申请的资源、等待其他进程发来的消息）而暂时无法运行。为便于管理，还可增加创建态（正在被创建，尚未就绪）和终止态（正在被撤销，资源待回收），合称五状态模型。

## 进程状态之间的转换
就绪 → 运行：进程被调度程序选中，获得处理机。运行 → 就绪：时间片用完，或出现更高优先级的进程抢占处理机。运行 → 阻塞：进程请求的资源不可用或需等待某事件（如主动调用阻塞式 I/O、等待信号量）。阻塞 → 就绪：等待的事件已经发生（如 I/O 完成中断到来、其他进程释放了资源）。注意运行 → 阻塞是进程自身的主动行为，而阻塞 → 就绪是外部事件触发的被动行为；阻塞态不能直接转为运行态，就绪态也不能直接转为阻塞态。创建 → 就绪、运行 → 终止也是常见的转换。

## 进程控制：创建
进程创建由内核通过原语完成，原语是不可被中断的原子操作，通常用关中断或加锁方式实现。创建过程为：分配唯一 PID 并申请空白 PCB；为新进程分配所需资源（内存、文件、I/O 设备）；初始化 PCB（标识信息、处理机状态信息、优先级等）；若就绪队列能接纳新进程，则将其插入就绪队列，否则置为就绪挂起态。引起进程创建的事件包括用户登录、作业调度、系统提供服务、应用请求（如 fork）。在 UNIX/Linux 中，fork 创建子进程并复制父进程地址空间，exec 族函数用新程序替换当前映像，父进程可调用 wait 等待子进程结束。

## 进程控制：撤销、阻塞与唤醒
撤销原语：先检索该进程的 PCB，若其仍有子进程则先撤销所有子进程，再回收该进程占有的全部资源，最后从所在队列中摘除 PCB。引起撤销的事件有正常结束、异常结束（越界、非法指令、算术错误、I/O 故障）和外界干预（操作员或父进程请求终止）。阻塞原语：运行进程发现无法继续执行时，保存现场并将状态改为阻塞，插入相应事件的等待队列，然后转调度程序。唤醒原语：当事件发生时，把等待该事件的进程从阻塞队列移出并置为就绪，再插入就绪队列。阻塞与唤醒必须成对使用，顺序不能颠倒。

## 进程的挂起与激活
为缓解内存紧张，操作系统可以剥夺某些进程的内存并把它们换出到磁盘，此时进程处于挂起状态。引入挂起后形成七状态模型：就绪挂起、阻塞挂起、就绪、运行、阻塞、创建、终止。挂起原语把进程换出内存并在 PCB 中记录外存地址；激活原语把挂起进程重新换入内存。就绪挂起态进程的激活需要判断内存是否足够，阻塞挂起态进程只有在等待事件发生后才能转为就绪挂起，再被激活为就绪态。

## 进程的组织方式
多个 PCB 需要有效组织以便检索与调度。链接方式把同一状态的 PCB 用链接字串成队列，如就绪队列、若干阻塞队列，就绪队列常按优先级高低排序；优点是插入删除灵活、动态性强，缺点是不便随机查找。索引方式为每种状态建立一张索引表，表项存放指向该状态 PCB 的指针，PCB 在内存中不必连续存放，检索速度快。现代操作系统多用链表加优先队列（堆、红黑树）的组合，如 Linux 的 CFS 用红黑树组织就绪进程，并按优先级组织实时队列。

## 进程切换与上下文
进程切换是指处理机从一个进程转到另一个进程运行，内核需要保存当前进程的现场（寄存器、PC、PSW、栈指针）到其 PCB 中，并从新进程的 PCB 中恢复现场，同时切换页表、地址空间与内核栈。进程切换是有开销的，包括直接开销（保存/恢复寄存器）和间接开销（缓存与 TLB 失效）。进程切换通常发生在时间片用完、进程阻塞、更高优先级进程到来、中断返回等时机，且一般在内核态完成。切换前必须判断是否允许抢占，切换本身与调度决策是两件不同的事：调度决定"选谁"，切换执行"换谁"。

## 线程的引入与定义
进程作为资源拥有者，在创建、撤销、切换时都要涉及资源分配与回收，系统开销较大，而且进程间通信效率低，限制了并发程度的进一步提高。为减少并发执行的时间和空间开销，引入线程。线程是进程内的一个执行单元，是处理机调度和分派的基本单位，它自己不拥有系统资源（仅有一点必不可少的私有资源，如线程 ID、程序计数器、寄存器组和栈），但可以共享所属进程的全部资源。引入线程后，进程只作为除 CPU 之外的系统资源的分配单元。

## 线程与进程的区别
资源拥有方面：进程是资源分配的基本单位，拥有独立的地址空间与资源；线程是调度和分派的基本单位，共享进程的地址空间与资源。并发性方面：同一进程内的多个线程可以并发执行，不同进程的线程也可并发，切换代价更小。系统开销方面：创建或撤销进程需分配或回收资源、切换需换页表与地址空间，开销大；同一进程内线程切换无需切换地址空间，只保存少量寄存器，开销小。通信方面：进程间通信需借助内核机制（共享内存、管道等），线程间可直接读写进程的共享数据，但必须用同步机制保护。此外，进程拥有独立的地址空间，一个进程崩溃通常不影响其他进程，而一个线程崩溃可能导致整个进程终止。

## 进程与线程示例
下面的程序用 fork 演示进程的创建与父子的分工：fork 调用一次返回两次，父进程中返回子进程的 PID，子进程中返回 0，出错时返回负值，因此可以用返回值区分父子进程的执行路径。子进程结束时用 _exit 立即终止并返回状态码，父进程用 wait 阻塞等待子进程结束并回收其 PCB，这一步是避免产生僵尸进程的关键。注意 fork 之后父子进程拥有各自独立的地址空间副本，对变量的修改互不影响，这与后面线程共享地址空间的情形形成鲜明对照。
```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
    pid_t pid = fork();          /* 创建子进程：父子进程复制地址空间 */
    if (pid < 0) {
        perror("fork");
        return 1;
    } else if (pid == 0) {
        /* 子进程：getpid() 取自身 PID，getppid() 取父进程 PID */
        printf("child : pid=%d, ppid=%d\n", (int)getpid(), (int)getppid());
        _exit(0);
    } else {
        /* 父进程：变量 fork 返回值即为子进程 PID */
        printf("parent: pid=%d, child=%d\n", (int)getpid(), (int)pid);
        wait(NULL);              /* 回收子进程，避免产生僵尸进程 */
    }
    return 0;
}
```

## 进程的终止与特殊状态
进程终止的原因分为正常结束和异常结束。进程终止时需释放资源、撤销 PCB，并把退出状态通知父进程。若子进程已终止而父进程尚未调用 wait 回收其 PCB，该子进程称为僵尸进程（zombie），它已不再运行但仍占用 PCB 与部分系统资源。若父进程先于子进程终止，子进程成为孤儿进程，在 Linux 中被 init（PID 为 1）或 subreaper 进程收养，不至于失控。长期运行的服务程序应当及时回收子进程，避免僵尸进程耗尽进程表。
