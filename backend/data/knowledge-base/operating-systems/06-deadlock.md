# 死锁
## 死锁的定义
死锁是一组进程互相等待对方已占有的资源且都不释放，导致全部无法推进。死锁与饥饿不同：饥饿是某些进程长期得不到调度但系统仍在运行，死锁是参与的进程都被永久阻塞。
## 产生死锁的必要条件
互斥、占有并等待、不可剥夺、循环等待四个条件同时成立才会死锁。破坏其中任一条件即可预防死锁，因此四条件是死锁的充要判定基础。
## 死锁预防
破坏互斥通常不现实；破坏占有并等待要求一次性申请全部资源；破坏不可剥夺允许抢占；破坏循环等待给资源编号并只按升序申请。预防策略会降低资源利用率。
## 死锁避免
系统在分配前判断分配后是否仍处于安全状态。安全状态指存在一个进程完成序列，使每个进程都能获得所需资源并释放；不安全状态不一定会死锁，但可能进入死锁。
## 银行家算法
银行家算法维护最大需求、已分配与还需矩阵，分配前用安全性算法检查是否存在安全序列。它假设进程会按时归还资源，是死锁避免的经典算法。
## 死锁检测与解除
允许死锁发生，周期检测资源分配图中是否存在环路，或用类似银行家的方法检测。解除方式包括撤销进程、剥夺资源、回滚或重启，代价较高。
## 资源分配图
进程指向资源表示请求，资源指向进程表示已分配。图中若无环路则无死锁；有环路且每类资源只有一个实例则必死锁，若有多实例则环路是必要而非充分条件。
## 典型问题
判断是否死锁先画资源分配图或检查是否存在安全序列。计算某状态是否安全时，按“还需量不超过当前可用”逐个进程推进，能全部完成即安全。
