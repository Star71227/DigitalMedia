# 进程通信与线程模型

## 进程通信的基本问题
并发进程之间需要交换信息，这种信息交换称为进程通信。通信的根本困难在于进程拥有独立的地址空间，一个进程不能直接访问另一个进程的变量。根据交换信息量的多少，通信分为低级通信和高级通信：低级通信（如信号量机制）交换的只是少量控制信息，效率低且对用户不透明；高级通信以较高的效率传送大量数据，对用户屏蔽实现细节。高级通信主要有共享存储、消息传递和管道通信三类。通信还需要解决进程的同步与互斥，即发送与接收的时序配合问题。

## 共享存储方式
共享存储指在内存中划出一块共享存储区，需要通信的进程把自己的虚地址空间映射到该区域，通过读写其中的数据直接交换信息。这种方式不需要内核在每次通信时介入数据拷贝，速度最快、效率最高，适合传输大量数据。但它要求进程之间自行提供同步互斥机制（如信号量或互斥锁），否则会出现数据竞争。共享存储区可由操作系统统一分配并命名，也可由进程申请后由其他进程按标识符附接（attach）。POSIX 共享内存通过 shm_open、mmap 等接口实现，是最常用的高速 IPC 手段之一。

## 消息传递方式
消息传递以格式化的消息为单位，通过内核提供的发送原语和接收原语交换数据，进程之间无须共享任何地址空间，因而特别适合分布式系统。直接通信方式把消息直接发送给指定进程，发送原语形如 send(接收者, 消息)，接收原语形如 receive(发送者, 消息)。间接通信方式通过信箱（端口）作为中间实体，发送者把消息送入信箱，接收者从信箱取出，因此又称信箱通信，一个信箱可以被多个进程共享。消息队列是典型的间接通信实现，它由内核维护，支持按类型接收、带优先级和阻塞/非阻塞语义，但每次通信都涉及用户态与内核态的数据拷贝，开销大于共享存储。

## 管道通信
管道是连接读写进程的一个共享文件，又称 pipe 文件，用于在相关进程之间按先进先出方式传送字节流。管道通信需要满足三个协调条件：互斥（一个进程读时另一个进程不能写）、同步（写满必须等待读走，读空必须等待写入）、确定对方是否存在（只有写端存在才能读，只有读端存在才能写）。管道分为匿名管道和命名管道：匿名管道由 pipe 系统调用创建，只能用于有亲缘关系的进程；命名管道（FIFO）以文件形式存在于文件系统中，可用于任意进程之间。管道是单向的字节流，没有消息边界，容量通常有限（Linux 默认 64KB）。

## 管道通信示例
下面的程序演示匿名管道的典型用法。pipe 系统调用返回两个文件描述符，fd[0] 为读端、fd[1] 为写端，管道是单向的，因此父子进程必须各自关闭不用的一端才能正确工作。若所有写端都被关闭，读端 read 会返回 0 表示文件结束；若读端全部关闭而仍有进程写入，写进程将收到 SIGPIPE 信号。当管道为空时读操作阻塞，写满时写操作阻塞，这正是管道自带的同步能力。
```c
#include <stdio.h>
#include <string.h>
#include <unistd.h>

int main(void) {
    int fd[2];
    if (pipe(fd) < 0) { perror("pipe"); return 1; }   /* fd[0] 读端, fd[1] 写端 */
    pid_t pid = fork();
    if (pid == 0) {
        close(fd[0]);                      /* 子进程只写：关闭读端 */
        const char *s = "ping from child";
        write(fd[1], s, strlen(s));        /* 写入管道，无读者时会收到 SIGPIPE */
        close(fd[1]);
    } else {
        close(fd[1]);                      /* 父进程只读：关闭写端 */
        char buf[64] = {0};
        ssize_t n = read(fd[0], buf, sizeof(buf) - 1);  /* 阻塞直到有数据或写端全关 */
        if (n > 0) printf("parent read %ld bytes: %s\n", (long)n, buf);
        close(fd[0]);
    }
    return 0;
}
```

## 其他常用 IPC 机制
除三大类之外，实际系统还提供多种 IPC：信号（signal）用于通知进程发生了异步事件，携带信息极少，属于低级通信；信号量用于同步互斥，本身不传递数据；套接字（socket）既可用于本机不同进程，也可跨主机通信，是网络编程的基础，分为流式套接字和用户数据报套接字；内存映射文件把文件映射到地址空间，也可用于共享；Linux 还提供 eventfd、signalfd、epoll 等机制用于事件通知。选择哪种机制取决于数据量、同步需求、是否需要跨主机以及性能要求。

## 用户级线程
用户级线程由用户空间的线程库（如早期的 POSIX threads 的 N:1 实现、GNU Pth）实现与管理，内核并不知道线程的存在，仍以进程为单位进行调度。优点是线程切换不需要陷入内核，开销小、速度快；线程库可以按应用需要选择调度算法；可以在不支持线程的操作系统上实现。缺点是：一个线程发起阻塞式系统调用时，内核会把整个进程阻塞，其他线程也无法运行；内核按进程分配时间片，多线程进程无法获得更多处理机时间，在多处理机上也无法真正并行；线程的调度与管理全在用户态，粒度与内核调度不匹配。

## 内核级线程
内核级线程由操作系统内核直接支持和管理，内核为每个线程维护线程控制块 TCB，并以线程为单位进行调度。优点是：一个线程阻塞时，内核可以调度同进程的其他线程运行；在多处理机上多个线程可以真正并行执行；内核例程本身也可多线程化。缺点是：线程的创建、撤销和切换都需要陷入内核，开销比用户级线程大；同一进程的线程切换虽不需要切换地址空间，但仍需模式切换。现代主流操作系统（Windows、Linux、Solaris）都支持内核级线程。

## 多线程模型
用户级线程与内核级线程的对应关系形成三种多线程模型。多对一模型：多个用户级线程映射到一个内核级线程，管理开销小但一个线程阻塞会导致整个进程阻塞，且不能利用多核。一对一模型：每个用户级线程对应一个内核级线程，并发能力强，但创建线程需创建内核线程，开销大，线程总数受系统限制。多对多模型：m 个用户级线程映射到 n 个内核级线程（m ≥ n），兼顾了两者的优点，既能有较好的并发性又能控制开销，但实现复杂。此外还有两级模型，允许用户把某个用户级线程绑定到一个内核级线程上。

## 线程库与轻量级进程
线程库为程序员提供创建、管理线程的 API，主要有 POSIX Pthreads、Windows 线程库和 Java 线程库。Pthreads 是规范而非实现，既可用作用户级也可用作内核级。轻量级进程（LWP）是内核支持用户级线程的中间层，每个 LWP 对应一个内核级线程，用户级线程通过 LWP 与内核交互，从而实现多对多模型。Linux 中并不严格区分进程与线程：二者都由 task_struct 描述，clone 系统调用通过参数决定共享哪些资源（地址空间、文件表、信号处理等），共享地址空间的一组 task 便构成一个多线程进程。

## 线程的创建示例
下面用 POSIX 线程库演示内核级线程的创建与汇合。pthread_create 建立一个新线程并让它执行指定函数，pthread_join 阻塞等待目标线程结束，二者共同构成线程的创建与回收。四个线程共享同一进程的全局变量 counter，因此自增这种"读—改—写"操作不是原子的，必须用互斥量保护，否则计数结果会小于预期值。这直观说明了线程共享地址空间带来的便利与风险：通信无需内核介入，但同步必须由程序员显式保证。
```c
#include <stdio.h>
#include <pthread.h>

static int counter = 0;                 /* 进程内共享：所有线程可见 */
static pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;

static void *worker(void *arg) {
    long id = (long)arg;
    for (int i = 0; i < 100000; i++) {
        pthread_mutex_lock(&lock);      /* 共享数据必须加锁保护 */
        counter++;
        pthread_mutex_unlock(&lock);
    }
    printf("thread %ld done\n", id);
    return NULL;
}

int main(void) {
    pthread_t t[4];
    for (long i = 0; i < 4; i++) pthread_create(&t[i], NULL, worker, (void *)i);
    for (int i = 0; i < 4; i++) pthread_join(t[i], NULL);   /* 等待线程结束 */
    printf("counter = %d\n", counter);
    return 0;
}
```

## 进程通信中的同步与缓冲
无论采用哪种通信方式，发送方与接收方之间都必须协调速度差异，缓冲是常用手段。零容量（无缓冲）：发送方必须等待接收方就绪，双方严格同步（会合 rendezvous）。有界缓冲：缓冲区满时发送方阻塞，空时接收方阻塞，缓冲区大小决定了流水线程度。无限缓冲：发送方不必等待，实现简单但可能耗尽内存。阻塞式（同步）发送与接收使进程在操作完成前一直等待；非阻塞式（异步）发送把消息复制到内核缓冲后立即返回，接收方无消息时立即返回失败码或空值。

## 三种高级通信方式比较
共享存储：速度最快、数据量大，但需要用户自行实现同步互斥，只适用于同一台机器上的进程。消息传递：不需要共享地址空间，可用于分布式系统，接口统一、安全边界清晰，但每次通信都有数据拷贝与系统调用开销，效率较低。管道：基于文件系统，实现简单、天然有序，但容量有限、只能传送字节流、通常只支持单向通信。实际系统常混合使用，如以共享存储传输大数据、以消息或信号量协调时序，以获得最佳性能与正确性。
