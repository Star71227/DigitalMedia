# 进程状态与转换
## 三态模型
进程最基本的状态包括就绪、运行和阻塞。就绪态进程已具备运行条件只等 CPU；运行态进程正占用处理机；阻塞态进程因等待某事件（如 I/O 完成、信号）而暂时无法推进。
## 状态转换
就绪到运行由调度程序完成；运行到就绪是时间片用完或被抢占；运行到阻塞是主动等待事件；阻塞到就绪是等待的事件发生。阻塞态进程即使有空闲 CPU 也不能直接运行。
## 五态模型
在三态基础上增加新建态和终止态。新建态表示进程已创建但尚未就绪，终止态表示进程结束执行、等待回收资源，使进程生命周期描述更完整。
## 挂起状态
当内存紧张或需要让进程长期不参与调度时，可把进程换出到外存，进入就绪挂起或阻塞挂起状态。挂起把进程从内存移出，与阻塞（等待事件）是正交的两个维度。
## 状态转换图分析
分析状态转换题时先判断触发条件：调度、时间片、I/O 请求、事件完成、进程创建与结束。只有就绪与运行之间是调度关系，其余转换由事件驱动。
## 原语操作
进程创建、撤销、阻塞与唤醒等状态操作由原语完成。原语是执行期间不可被中断的指令序列，保证 PCB 等关键数据结构的修改是原子的，避免状态不一致。
## 典型问题
“运行到阻塞”只能由进程自身发起，“阻塞到就绪”由外部事件引起；没有“阻塞到运行”的直接边。做题时抓住“是否有资格占用 CPU”与“是否在等待事件”两个维度。
