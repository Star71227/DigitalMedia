# 进程同步与互斥
## 临界资源与临界区
临界资源是一次只允许一个进程访问的共享资源，访问临界资源的代码段叫临界区。互斥要求同一时刻至多一个进程在临界区内，否则会因交错执行产生不确定结果。
## 同步与互斥的区别
互斥解决“排他访问”问题，同步解决“先后顺序”问题。生产者与消费者之间既有互斥（共享缓冲区）也有同步（缓冲区空则消费者等待，缓冲区满则生产者等待）。
## 同步机制的准则
好的同步方案应满足：空闲让进（有空位就允许进入）、忙则等待（已占用则等待）、有限等待（不能无限等待）、让权等待（等待时不占 CPU 忙等）。
## 软件方法
Peterson 算法等纯软件方案通过标志位与轮换变量实现两个进程互斥，但在现代乱序执行的硬件上需要内存屏障，且忙等浪费 CPU，实际系统更常用硬件或内核原语。
## 硬件方法
开关中断只适用于单处理机且关中断影响系统响应；Test-and-Set 与 Swap 等原子指令可构建自旋锁，但自旋锁忙等、不满足让权等待，适合临界区极短的场景。
## 管程
管程把共享变量和对其操作封装在一起，任一时刻至多一个进程进入管程，条件变量配合 wait/signal 实现同步。管程把同步责任交给编译器与运行时，降低编程错误率。
## 典型问题
判断一段代码是否安全，看共享变量是否可能被并发交错修改。凡是“读-改-写”未受保护的共享变量操作，都可能因竞态产生丢失更新，需要放入临界区。
