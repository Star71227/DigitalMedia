# 进程同步、互斥与管程

## 进程同步与互斥的概念
进程同步指为完成某项任务而协作的多个进程，需要按照一定的先后次序协调它们的执行，例如"写进程写完数据后读进程才能读"。进程互斥指多个进程在同一段时间内必须排他地访问某个共享资源，即任一时刻只允许一个进程使用该资源。同步是进程间的直接制约关系，源于它们之间的合作；互斥是进程间的间接制约关系，源于对临界资源的竞争。由于进程的异步性，若不加以控制，并发访问共享变量会导致与时间有关的错误，使结果不可再现。

## 临界资源与临界区
一次仅允许一个进程使用的资源称为临界资源，如打印机、共享变量、共享缓冲区。进程中访问临界资源的那段代码称为临界区（临界段）。典型的进程代码结构为：进入区（检查并设置访问标志）、临界区、退出区（清除访问标志）、剩余区。同步机制应遵循的准则正是针对临界区设计的。需要强调的是，一个程序中的多个临界区若访问不同的临界资源，可以分别加锁，以提高并发度。

## 同步机制应遵循的四条原则
空闲让进：当临界区空闲时，应允许一个请求进入临界区的进程立即进入，以提高临界资源利用率。忙则等待：当已有进程在临界区中时，其他试图进入的进程必须等待，以保证互斥访问。有限等待：对请求访问的进程，应保证它能在有限时间内进入临界区，即不能让某进程无限期等待，避免饥饿。让权等待：当进程不能进入临界区时，应立即释放处理机，防止进程陷入忙等待而白白浪费处理机时间。这四条原则是评价一切同步机制（软件方法、硬件方法、信号量、管程）的基本标准。

## 软件方法：单标志法
单标志法设置一个公用整型变量 turn，turn = i 表示允许 Pi 进入临界区。Pi 进入前先判断 turn 是否等于 i，退出时把 turn 置为对方编号。该算法能保证互斥，但强制两个进程交替进入临界区：如果 Pi 不打算进入，而 turn 恰好等于 i，则 Pj 也不能进入，违背了"空闲让进"原则，造成临界资源空闲而进程等待。因此单标志法只适用于两进程严格轮流的场景。

## 软件方法：双标志法
双标志先检查法：设置布尔数组 flag[2]，flag[i] = true 表示 Pi 想进入临界区。Pi 先置自己的 flag 为 true，再检查对方的 flag，若对方也为 true 则等待。该算法解决了"空闲让进"问题，但由于"检查"和"修改"不是原子操作，两进程可能几乎同时完成检查并都发现对方为 false，从而同时进入临界区，违背"忙则等待"。双标志后检查法：先置自己的标志再检查对方，能保证互斥，但可能出现两进程都置位后互相等待的局面，导致"死锁"和饥饿，违背"有限等待"。

## Peterson 算法
Peterson 算法是双标志与单标志的结合，满足互斥并避免饥饿，适用于两个进程互斥。它使用布尔数组 flag[2] 和整型 turn：进入区先置 flag[i] = true，再令 turn = j，然后以 while (flag[j] && turn == j) 循环等待；退出区把 flag[i] 置为 false。若两进程同时想进入，turn 最终只保留一个值，后写者让先写者进入，因此不会同时进入；若对方不想进入，则可见 flag[j] 为 false 而立即进入，满足空闲让进。

```c
/* Peterson 算法：两进程互斥，i 与 j 互为对方编号 (i=0,j=1 或 i=1,j=0) */
static volatile int flag[2] = {0, 0};
static volatile int turn = 0;

void enter_region(int i) {
    int j = 1 - i;
    flag[i] = 1;              /* 声明自己想进入临界区 */
    turn = j;                 /* 但客气地把优先权让给对方 */
    while (flag[j] && turn == j) {
        /* 忙等待：对方想进且优先权在对方，则本进程自旋 */
    }
}

void leave_region(int i) {
    flag[i] = 0;              /* 退出临界区，撤销声明 */
}

/* 使用：enter_region(0); 临界区代码; leave_region(0); */
```

## 硬件方法：中断屏蔽
关中断是实现互斥最简单的方法：进程进入临界区前执行关中断指令，离开临界区时执行开中断指令。由于中断被屏蔽，时钟中断与 I/O 中断都不会发生，进程切换无法进行，因而不会被抢占，互斥自然得到保证。缺点是：关中断的权限属于特权指令，只能在核心态执行，因此不适用于用户程序；关中断时间过长会影响系统对外部事件的响应能力，降低并发度；在多处理机上关中断只能屏蔽本处理机的中断，无法阻止其他处理机上的进程进入同一临界区，因此必须配合自旋锁等多处理机同步手段。

## 硬件方法：TestAndSet 指令
TestAndSet（TS）指令是一条原子指令，其功能是先返回锁变量的旧值，再把锁变量置为 true，读旧值与写新值这两个动作不可分割。进程进入临界区前循环执行 TS(lock)，直到返回 false（表示原来未上锁），从而获得锁；退出时把 lock 置为 false。该算法能保证互斥，实现简单且适用于任意数目的进程和多处理机环境。缺点是不满足"让权等待"原则，未获得锁的进程持续执行 TS 指令进行忙等待（自旋），白白耗费处理机时间，且可能因进程优先级差异引发优先级反转问题。

## 硬件方法：Swap 指令
Swap（Exchange）指令原子地交换两个字（寄存器与内存变量）的内容。为每个临界资源设置全局布尔变量 lock（初值 false），每个进程设有局部变量 key（初值 true）。进入区反复执行 Swap(key, lock)，当 key 变为 false 时表示成功获得锁（此时 lock 已被置为 true）；退出区把 lock 置为 false。该算法同样能实现互斥并适用于多处理机，但同样存在忙等待问题，不满足让权等待。硬件方法的共同优点是适用于任意数目的进程、支持多处理机、实现简单；共同缺点是难以解决复杂同步问题（如生产者消费者）且普遍存在忙等待。

## 管程的引入与定义
信号量机制虽然功能强大，但同步操作分散在各进程中，P、V 操作的使用顺序稍有不当就会造成死锁或同步错误，对程序员要求高且不易调试。为此引入管程：管程是一种高级同步机制，它将共享资源及其上所有操作封装在一起，组成一个模块。管程的组成包括：管程名称、局部于管程的共享数据结构说明、对该数据结构进行操作的一组过程（函数）、对局部数据初始化的语句。其重要特征是：局部数据只能被管程内的过程访问，进程只能通过调用管程中的过程来间接访问共享资源。

## 管程实现同步的机制
管程保证任一时刻至多只有一个进程在管程内执行，从而实现互斥，这一互斥由编译器或语言运行时自动保证，程序员无需显式加锁。为处理同步等待，管程内设置条件变量（condition），仅当某条件不满足时进程才在条件变量上等待。条件变量提供两种操作：wait（阻塞调用进程并释放管程的互斥权，使其进入该条件变量的等待队列）与 signal（唤醒在该条件变量上等待的一个进程；若没有进程在等待则 signal 无效果，这一点与 V 操作不同）。被唤醒进程何时能继续执行取决于管程采用 Hoare 语义（立即移交管程控制权）还是 Mesa 语义（被唤醒进程重新排队竞争管程，需用 while 循环重新判断条件）。

## 管程示例
C 语言没有内建的管程语法，可用互斥量与条件变量手工构造等价的同步模块。下面的有界缓冲区模块把共享数据 buf、head、tail、count 与全部访问过程封装在一起，外部只能通过 put 与 get 操作它，从而实现管程"局部数据不可直接访问"的封装性。注意两个循环判断必须使用 while 而非 if：pthread_cond_wait 返回后条件可能已被其他线程改变，必须重新检查，这正是 Mesa 语义下使用条件变量的基本要求。
```c
#include <pthread.h>

/* 用互斥量与条件变量手工模拟一个管程：有界缓冲区的入队/出队 */
#define N 8
static int buf[N], head = 0, tail = 0, count = 0;
static pthread_mutex_t mtx = PTHREAD_MUTEX_INITIALIZER;
static pthread_cond_t not_full  = PTHREAD_COND_INITIALIZER;
static pthread_cond_t not_empty = PTHREAD_COND_INITIALIZER;

void put(int x) {
    pthread_mutex_lock(&mtx);                    /* 进入管程：获得互斥 */
    while (count == N) {                         /* Mesa 语义必须用 while 重新判断 */
        pthread_cond_wait(&not_full, &mtx);      /* 等待并释放互斥 */
    }
    buf[tail] = x;
    tail = (tail + 1) % N;
    count++;
    pthread_cond_signal(&not_empty);             /* 通知等待取数的进程 */
    pthread_mutex_unlock(&mtx);                  /* 离开管程 */
}

int get(void) {
    pthread_mutex_lock(&mtx);
    while (count == 0) {
        pthread_cond_wait(&not_empty, &mtx);
    }
    int x = buf[head];
    head = (head + 1) % N;
    count--;
    pthread_cond_signal(&not_full);
    pthread_mutex_unlock(&mtx);
    return x;
}
```

## 管程与信号量的比较
管程把互斥与同步机制集中封装在模块内部，由编译器保证互斥，程序员只需关心条件变量上的等待与唤醒，因此更安全、更易读、更易验证；信号量的 P、V 操作分散在各个进程中，正确性完全依赖程序员，容易出现死锁（如 P 操作顺序不当）或同步错误（如漏写 V 操作）。管程的主要缺点是需要语言支持（如 Java 的 synchronized、Pascal 的 monitor 原语），对不支持的 C 语言只能通过库函数模拟；此外管程是单处理机共享数据结构的抽象，在多处理机上仍需底层自旋锁配合实现。

## 自旋锁与忙等待
互斥机制的等待策略分为忙等待与阻塞等待。自旋锁下未获得锁的进程反复检测锁变量，适用于临界区很短、且在多处理机上等待时间可能小于线程切换开销的场景，因为进程保持在就绪状态可以快速获得处理机，避免了上下文切换的开销，这在多核系统中被广泛用于内核短临界区保护。缺点是临界区较长时会浪费大量处理机时间，并且需要硬件原子指令（TS、Swap、CAS）支持。相比之下，信号量与管程采用阻塞等待，满足让权等待原则，适用于临界区较长或单处理机场景。实际系统常采用自适应策略，先短暂自旋再挂起等待。
