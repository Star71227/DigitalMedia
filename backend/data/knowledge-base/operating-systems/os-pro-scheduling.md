# 处理机调度

## 调度的层次：三级调度
处理机调度是对处理机资源进行分配，按层次分为三级。高级调度（作业调度、长程调度）决定把外存上处于后备队列的哪些作业调入内存并为它们创建进程、分配资源，只存在于批处理系统中，调入频率最低。中级调度（内存调度、中程调度）决定把内存中暂时不能运行的进程换出到外存（挂起），或把具备运行条件的挂起进程重新调入内存，目的是提高内存利用率和系统吞吐量。低级调度（进程调度、短程调度）决定从就绪队列中按某种算法选出一个进程把处理机分配给它，是三种调度中最频繁、最核心的一级，任何操作系统都必须具备。

## 处理机调度的时机
进程调度发生在下列时机：正在运行的进程执行完毕或发生异常终止；正在运行的进程因请求 I/O、申请资源或等待事件而主动放弃处理机；时间片用完；有更高优先级的进程进入就绪队列；中断处理结束后返回。需要注意的是，不能进行进程调度的情况包括：在处理中断的过程中；进程处于操作系统内核临界区中；在原子操作过程中。若在这些时刻强行调度可能导致内核数据结构不一致，因此需要设置调度标志，等到退出临界区后再触发调度。

## 抢占方式与非抢占方式
非抢占方式（非剥夺方式）：进程一旦获得处理机就一直运行下去，直到它完成或主动阻塞，才把处理机让给其他进程。实现简单、系统开销小，但难以满足实时任务的紧急需求，也不利于交互式用户的及时响应。抢占方式（剥夺方式）：允许调度程序根据某种原则剥夺当前进程的处理机，重新分配给另一个进程，抢占原则包括优先级原则、短进程优先原则和时间片原则。抢占方式响应及时，能防止长进程长期垄断处理机，但频繁切换会增加系统开销，且对共享数据的访问需要更严格的同步保护。

## 调度算法的评价指标
常用的评价指标包括：CPU 利用率，指处理机处于忙碌状态的时间比例，应尽可能高。系统吞吐量，指单位时间内完成的作业数量，长作业与短作业混合作业时吞吐量与调度策略密切相关。周转时间，指作业从提交到完成所经历的时间，等于完成时间减提交时间，也等于等待时间加运行时间。带权周转时间，等于周转时间除以实际运行时间，恒大于等于 1，越接近 1 表示作业在系统中的等待越少。等待时间，指进程在就绪队列中等待处理机的时间之和，不包含 I/O 等待。响应时间，指从用户提交请求到系统首次产生响应所用的时间，是分时系统的重要指标。

## 响应比与调度目标
响应比（响应比高者优先算法中的 R）定义为：R =（等待时间 + 要求服务时间）/ 要求服务时间 = 周转时间 / 要求服务时间。该比值综合了作业等待时间的长短和运行时间的长短：等待时间越长 R 越大，运行时间越短 R 也越大。当等待时间相同时，短作业的 R 较大，体现短作业优先；当运行时间相同时，等待时间长的 R 较大，体现先来先服务，因此它是对 FCFS 与 SJF 的折中。调度设计的一般目标是：面向批处理系统追求吞吐量大、周转时间短、处理机利用率高；面向分时系统追求响应时间快、均衡性好；面向实时系统追求截止时间得到满足、可预测性强。

## 先来先服务调度算法 FCFS
FCFS 按作业或进程到达的先后顺序进行调度，是最简单的调度算法，既可用于作业调度也可用于进程调度，属于非抢占算法。优点是公平、实现简单、不会导致进程饥饿。缺点是对长作业有利而对短作业不利：若一个长作业先到达，后面的短作业都要长时间等待，因此带权周转时间可能很大，平均周转时间往往不是最优。FCFS 对 CPU 繁忙型作业有利，对 I/O 繁忙型作业不利，因为后者频繁让出处理机后排到队尾又要重新等待。FCFS 还容易与短进程优先算法结合形成混合策略。

## 最短作业优先与最短剩余时间优先
短作业优先（SJF，进程调度中称 SPF 短进程优先）选择运行时间最短的作业或进程投入运行，可以证明在作业同时到达的情况下它能获得最小的平均等待时间和最小的平均周转时间。缺点是必须预知运行时间（往往只能估计），对长作业不利，可能导致长作业长期得不到调度（饥饿）。SJF 分为非抢占式与抢占式：抢占式又称最短剩余时间优先（SRTN），当新到达进程的剩余运行时间比当前进程的剩余时间更短时抢占处理机。举例如四个作业都在 0 时刻到达，运行时间分别为 7、4、1、4：FCFS 平均周转时间为 11.5，而 SJF 为 7.75，SJF 明显更优。

## 调度算法计算示例
四个作业都在 0 时刻到达，运行时间分别为 7、4、1、4。按 FCFS 顺序执行时完成时刻为 7、11、12、16，平均周转时间 11.5，平均带权周转时间 4.938；按 SJF 顺序 P3、P2、P4、P1 执行时完成时刻为 1、5、9、16，平均周转时间 7.75，平均带权周转时间约 1.696。可见 SJF 在作业同时到达时确实取得更小的平均周转时间。

```c
/* 计算 FCFS 与 SJF 的平均周转时间与平均带权周转时间
 * 四个作业均在 0 时刻到达，运行时间分别为 7、4、1、4 */
#include <stdio.h>

#define N 4
static int burst[N] = {7, 4, 1, 4};

static void report(const char *name, const int order[]) {
    int t = 0, sum_turn = 0;
    double sum_w = 0.0;
    printf("%s: ", name);
    for (int i = 0; i < N; i++) {
        int p = order[i];
        t += burst[p];                       /* 完成时刻 = 前面作业时间之和 */
        int turn = t;                        /* 周转时间 = 完成时间 - 到达时间(0) */
        sum_turn += turn;
        sum_w += (double)turn / burst[p];    /* 带权周转时间 = 周转时间 / 运行时间 */
        printf("P%d(完成%d,周转%d) ", p + 1, t, turn);
    }
    printf("| 平均周转=%.2f 平均带权=%.3f\n", (double)sum_turn / N, sum_w / N);
}

int main(void) {
    int fcfs[N] = {0, 1, 2, 3};              /* 到达顺序 P1 P2 P3 P4 */
    int sjf[N], used[N] = {0};
    for (int k = 0; k < N; k++) {            /* 按运行时间递增选作业，即 SJF 顺序 */
        int best = -1;
        for (int i = 0; i < N; i++) {
            if (used[i]) continue;
            if (best < 0 || burst[i] < burst[best]) best = i;
        }
        sjf[k] = best;
        used[best] = 1;
    }
    report("FCFS", fcfs);   /* 平均周转 11.50，平均带权 4.938 */
    report("SJF ", sjf);    /* 平均周转 7.75，平均带权 1.696 */
    return 0;
}
```

## 高响应比优先调度算法 HRRN
HRRN 在每个作业调度时计算后备队列中所有作业的响应比 R =（等待时间 + 要求服务时间）/ 要求服务时间，选择 R 最大的作业投入运行。它是非抢占算法，只在当前作业完成或阻塞后才重新计算。其优点是兼顾了等待时间与服务时间：短作业因分母小而优先，长作业随着等待时间增加，R 不断增大，最终也能获得运行机会，从而避免了 SJF 中长作业饥饿的问题。缺点是需要不断计算响应比，增加了系统开销，且仍需要预知要求的服务时间。

## 时间片轮转调度算法 RR
RR 专为分时系统设计：就绪队列中的进程按 FCFS 顺序排队，每次把处理机分给队首进程并令其运行一个时间片，时间片用完时产生时钟中断，调度程序把它送至队尾，再取新队首运行。时间片的大小对性能影响很大：时间片过小，进程切换过于频繁，开销所占比例上升；时间片过大，RR 退化为 FCFS，无法满足响应时间要求。时间片通常取略大于一次典型交互所需时间（如 10~100ms）。例如三个进程 P1、P2、P3 都在 0 时刻到达，运行时间分别为 5、4、2，取时间片 2 时完成时刻为 12、10、6，平均周转时间约 9.33，而 FCFS 为 8.33，但 RR 的响应时间明显更好。

## 优先级调度算法
优先级调度为每个作业或进程设置优先级，调度时选择优先级最高的进程运行，新的更高优先级进程到来时是否抢占取决于算法是抢占式还是非抢占式。优先级分为静态优先级（创建时确定、运行期间不变，实现简单但不够灵活）和动态优先级（随进程推进而变化，例如随等待时间增长而提高，可防止饥饿）。通常系统进程优先于用户进程，交互型进程优先于批处理进程，I/O 繁忙型进程优先于 CPU 繁忙型进程。优先级调度同样可能导致低优先级进程饥饿，可用老化技术解决。

## 多级队列调度
多级队列把就绪队列划分为多个独立队列，如系统进程队列、交互进程队列、批处理队列，每个队列可设置不同的优先级和不同的调度算法（如交互队列用 RR，批处理队列用 FCFS），队列之间可采用固定优先级（可能导致低优先级队列饥饿）或按比例划分处理机时间的方式调度。进程创建时被固定分配到某个队列，一般不允许在队列之间移动。多级队列的主要缺点是进程一旦进入某队列就难以适应其行为变化的需求。

## 多级反馈队列调度
多级反馈队列是最通用的调度算法之一，兼顾了短进程优先与响应时间。其思想是：设置多个优先级递减的就绪队列，各级队列的时间片随优先级降低而成倍增大；新进程进入最高优先级队列末尾；进程在某一级队列用完时间片仍未完成则降到下一级队列末尾；只有较高优先级队列为空时才调度较低优先级队列；若进程被 I/O 阻塞后返回，则回到较高优先级（通常是最初的）队列。这样短进程可在高优先级队列用较小时间片迅速完成，长进程逐级下降获得越来越大的时间片，从而减少切换次数，同时兼顾了 I/O 繁忙型进程。

## 实时调度算法
实时调度按任务的周期性分为时钟驱动与非时钟驱动，常见算法有：最早截止时间优先（EDF），动态选择当前截止时间最早的任务运行，属于动态优先级算法，在任务可抢占且可忽略切换开销时是单处理机上最优的调度算法，处理机利用率理论上可达 100%。最低松弛度优先（LLF）：松弛度 = 必须完成时刻 − 本身还需运行时间 − 当前时刻，选择松弛度最小的任务运行。速率单调调度（RMS）：周期越短优先级越高，是静态优先级算法，对周期性任务在固定优先级中是最优的，可调度条件为总利用率不超过 n(2^(1/n) − 1)。

## 调度算法比较与选择
FCFS 公平但平均周转时间不优，且不利于短作业；SJF/SRTN 平均周转时间最优但需预知运行时间且可能饥饿，适合批处理；HRRN 兼顾等待与服务时间但计算开销大；RR 响应及时、公平，适合分时系统；优先级调度灵活但需解决饥饿；多级反馈队列综合性能最好，被通用操作系统广泛采用。选择算法时需权衡响应时间、周转时间、吞吐量、公平性与实现开销，实际系统多采用多种算法的组合。此外，由于真实进程的 CPU 脉冲与 I/O 脉冲交替出现，调度器常在进程从 I/O 返回时给予一定优先级补偿。
