# 查找

## 查找的基本概念
查找是在数据集合中找出关键字等于给定值的记录。查找表是由同一类型数据元素构成的集合。若查找的同时还进行插入删除操作，称为动态查找表；只查找不修改，称为静态查找表。关键字是数据元素中能唯一标识该元素的数据项。

## 平均查找长度 ASL
平均查找长度是衡量查找算法效率的主要指标，定义为 ASL = Σ(p_i × c_i)，其中 p_i 是查找第 i 个记录的概率（通常设为等概率 1/n），c_i 是找到第 i 个记录所需的比较次数。ASL 分查找成功与查找失败两种。

## 顺序查找
顺序查找从表的一端开始逐个比较关键字。对无序的顺序表或链表都适用。查找成功时平均查找长度 ASL成功 = (n+1)/2；查找失败时需比较 n 次（若使用哨兵则为 n+1 次）。时间复杂度 O(n)。

## 顺序查找的哨兵优化
把待查关键字放在数组下标 0 处作为哨兵，从表尾向前查找，循环条件只判断 a[i] != key，省去每次的边界判断，把比较次数从 2n 降为 n+1 次。这是常数级优化，不改变渐近复杂度。

## 折半查找（二分查找）
折半查找要求表**顺序存储且按关键字有序**。每次取中间位置 mid = ⌊(low+high)/2⌋ 与目标比较，相等则成功，目标较小则在高半区继续，较大则在低半区继续。查找成功时比较次数不超过 ⌊log2 n⌋ + 1，平均查找长度约为 log2(n+1) − 1。时间复杂度 O(log n)。

## 折半查找的判定树
把折半查找的比较过程画成一棵二叉判定树，树中每个结点对应一次比较。判定树是一棵平衡二叉树，高度为 ⌊log2 n⌋ + 1，因此最坏比较次数等于树高。判定树中第 k 层结点数为 2^(k−1)，可用于计算 ASL。

## 分块查找（索引顺序查找）
分块查找把表分成若干块，块内元素无序但块间有序（第 i 块的所有关键字都小于第 i+1 块）。建立索引表，每项记录该块的最大关键字与起始地址。查找时先在索引表中确定块（可用折半查找），再在块内顺序查找。平均查找长度优于纯顺序查找，插入删除比有序顺序表方便。

## 完整代码：顺序查找与折半查找
```c
#include <stdio.h>

// 顺序查找（带哨兵），返回下标，失败返回 0
int SeqSearch(int a[], int n, int key) {
    a[0] = key;                       // 下标 0 作哨兵
    int i = n;
    while (a[i] != key) i--;
    return i;                         // 返回 0 表示失败
}

// 折半查找（迭代），数组下标 0..n-1 且递增有序
int BinSearch(int a[], int n, int key) {
    int low = 0, high = n - 1;
    while (low <= high) {
        int mid = (low + high) / 2;
        if (a[mid] == key) return mid;
        else if (a[mid] < key) low = mid + 1;
        else high = mid - 1;
    }
    return -1;
}

// 折半查找（递归）
int BinSearchRec(int a[], int low, int high, int key) {
    if (low > high) return -1;
    int mid = (low + high) / 2;
    if (a[mid] == key) return mid;
    if (a[mid] < key) return BinSearchRec(a, mid + 1, high, key);
    return BinSearchRec(a, low, mid - 1, key);
}
```

## 分块查找的实现要点
索引表中的最大关键字必须按块顺序递增，才能对索引表做折半查找。块内元素无序，因此块内只能顺序查找。若块长为 s、块数为 b = n/s，则平均查找长度为 (s+1)/2 + (b+1)/2，当 s = √n 时取最小值 √n + 1。

## 查找方法的比较
| 查找方法 | 存储要求 | 平均 ASL | 适用场景 |
|---|---|---|---|
| 顺序查找 | 顺序或链式，有序无序均可 | (n+1)/2 | 表小、无序、频繁插入删除 |
| 折半查找 | 顺序存储且有序 | ≈log2(n+1)−1 | 表大、静态、查询频繁 |
| 分块查找 | 分块有序 | ≈√n | 需要兼顾查找与插入删除 |

## 常见易错点
折半查找不能用于链表，因为链表无法 O(1) 随机访问中间元素。循环条件写成 low < high 会漏查最后一个元素。mid 的计算在 low+high 可能溢出时应写成 low + (high − low)/2。把"有序"当成折半查找的充分条件——还必须支持随机访问。ASL 计算时要区分成功与失败、等概率与非等概率。

## 本节小结
查找效率取决于数据的组织方式。顺序查找实现最简单但效率最低；折半查找以 O(log n) 的效率换取"必须有序且顺序存储"的限制；分块查找在两者之间折中。真实系统中，哈希表提供平均 O(1) 的查找，而平衡树提供 O(log n) 且支持有序遍历，二者分别适用于不同需求。
