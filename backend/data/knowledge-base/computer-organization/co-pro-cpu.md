# CPU 结构与指令周期

## CPU 的功能
中央处理器（CPU）是计算机的运算与控制核心，其功能可以概括为四个方面。第一是指令控制，即按程序规定的顺序逐条取出并执行指令，并处理转移、调用与中断导致的顺序改变。第二是操作控制，即把一条指令分解为若干操作信号，送往相应的部件并控制其动作的先后次序。第三是时间控制，即为各种操作提供统一的时序基准（时钟信号与节拍），规定每个操作的开始与结束时刻。第四是数据加工，即对数据进行算术运算与逻辑运算。此外，现代 CPU 还必须具备中断处理能力，以响应 I/O 请求与异常事件。

## CPU 的组成：运算器与控制器
CPU 由运算器和控制器两大部分组成。运算器包含算术逻辑单元（ALU）、通用寄存器组、暂存器、移位电路与标志寄存器，负责数据的加工与状态的产生。控制器包含程序计数器 PC、指令寄存器 IR、指令译码器 ID、时序电路与微操作信号发生器，负责取指令、分析指令并按时序发出控制信号。除这两部分外，现代 CPU 还集成了高速缓存（Cache）、总线接口单元、存储管理单元（MMU）以及各类协处理部件，但这些部件在逻辑上仍服务于"取指令、分析指令、执行指令"这一基本循环。

## 程序计数器 PC
程序计数器（PC）存放将要执行的下一条指令在主存中的地址，因此又称指令指针。它具有自动增量功能：每取出一条指令（或一个指令字），PC 就自动加上该指令的字节数，从而指向后续指令。转移类指令通过修改 PC 的内容改变执行顺序，子程序调用与返回则依靠保存和恢复 PC 的值实现。PC 的位数必须足以覆盖整个主存地址空间，通常等于地址总线的位数或主存地址寄存器的位数。由于程序顺序执行是默认行为，PC 的自增逻辑是 CPU 中最基本、最频繁使用的功能之一。

## 指令寄存器 IR
指令寄存器（IR）用于存放当前正在执行的那条指令。取指周期结束时，从主存读出的指令被送入 IR，此后由指令译码器对其操作码字段进行译码，产生相应的控制信号；地址码字段则在整个执行过程中被反复读取，用于参与有效地址的计算。IR 的位数必须等于指令字长，若指令字长大于存储字长，则一条指令需要多个存储字，IR 要能容纳完整的指令，或者采用"取一部分、边执行边取下一部分"的流式处理。IR 对程序员是不可见的，其内容不能由指令直接访问，属于典型的透明寄存器。

## 主存地址寄存器与数据寄存器
主存地址寄存器（MAR）存放将要访问的主存单元地址，其位数等于地址总线位数，也就等于 log2(存储单元总数)。主存数据寄存器（MDR）存放与主存交换的数据，其位数等于存储字长，通常与数据总线宽度一致。以 4M×32 位的主存为例，存储单元数为 2^22，故 MAR 需 22 位；每个存储单元 32 位，故 MDR 需 32 位。MAR 与 MDR 是 CPU 与主存之间的唯一接口：任何访存操作都必须先把地址送 MAR、再由 MDR 完成数据的中转，因此它们的位数直接决定了机器的寻址范围与一次访存的吞吐量。

## 程序状态字与通用寄存器
程序状态字寄存器（PSW）保存程序运行的状态信息，包括算术逻辑运算产生的标志位（ZF 零标志、SF 符号标志、OF 溢出标志、CF 进位标志等）、中断允许位、CPU 工作模式位（用户态/核心态）以及优先级等。条件转移指令正是依据 PSW 中的标志决定是否转移，中断处理时也必须保存与恢复 PSW。通用寄存器组用于存放操作数、运算中间结果、变址值、堆栈指针与基址等，其数量与位数是衡量机器性能的重要指标：寄存器越多，编译器越容易把变量留在寄存器中，访存次数越少，程序执行越快。

## 用户可见与不可见寄存器
按程序员能否用指令直接访问，CPU 寄存器可分为两类。用户可见寄存器包括通用寄存器、程序计数器 PC、程序状态字 PSW、堆栈指针与基址/变址寄存器，它们是指令系统的组成部分，汇编程序员与编译器可以直接操作。用户不可见（透明）寄存器包括指令寄存器 IR、主存地址寄存器 MAR、主存数据寄存器 MDR、各类暂存器与流水线寄存器，它们由硬件自动使用，指令系统中没有访问它们的指令。理解这一区分有助于判断某条指令执行时数据通路需要经过哪些环节，也有助于分析一条指令的时钟周期数。

## 指令周期概述
指令周期是指 CPU 取出并执行一条指令所需的全部时间。一个完整的指令周期通常由若干个机器周期（CPU 周期）组成，依次是取指周期、间址周期、执行周期和中断周期。其中取指周期与执行周期是每条指令都必须经历的，间址周期只在采用间接寻址的指令中出现，中断周期只在本次指令执行结束且检测到中断请求时出现。指令周期的流程图可以概括为：取指 → 判间址 → 执行 → 判中断 → 取下一条指令，硬件通过四个触发器（FE、IND、EX、INT）标志当前处于哪个阶段。

## 取指周期
取指周期的任务是把 PC 所指的指令取出并送入 IR，其数据流为：PC 的内容送 MAR，控制器向主存发出读命令，主存按地址读出指令字送入 MDR，MDR 的内容送 IR，同时 PC 自增指向下一条指令。取指周期的全部操作由硬件自动完成，不需要程序干预，也不受指令类型影响，因此所有指令共享同一段取指流程。正因为取指周期完全一致，流水线才能把"取指"作为独立的一级与其他指令的操作重叠执行。取指周期的长短取决于主存的存取速度与指令字长。

## 间址周期
间址周期的任务是取出操作数的有效地址。当指令采用间接寻址时，IR 中地址码字段给出的是"操作数地址的地址"，因此需要额外访存一次：把 IR 中的地址码送 MAR，发出读命令，主存读出的内容经 MDR 送回 IR 的地址码字段（或送入暂存器），此时该内容才是真正的有效地址。若采用多级间接寻址，则要重复上述过程多次，每次间址周期都要访问一次主存，执行时间成倍增长。间址周期的存在是间接寻址速度慢的直接原因，也是它逐渐被寄存器间接寻址取代的原因。

## 执行周期
执行周期完成指令规定的实际操作，不同指令的数据流差别很大，这是执行周期无法统一的原因。以几个典型指令为例：取数指令 LDA X 需要把 X 的有效地址送 MAR、读主存、经 MDR 与暂存器把数据送累加器；加法指令 ADD X 需要先取出 X 送暂存器，再把累加器内容与暂存器内容送 ALU 相加，结果送回累加器并更新标志位；存数指令 STA X 需要把地址送 MAR、累加器内容送 MDR、发出写命令；无条件转移指令 JMP X 则只需把有效地址直接送 PC。执行周期的最后一步通常是修改状态标志，为后续的条件转移提供依据。

## 中断周期
中断周期在一条指令执行结束、且 CPU 检测到未被屏蔽的中断请求时进入，用于保存断点并转去执行中断服务程序，其数据流一般是：把堆栈指针 SP 减 1（假定堆栈向低地址生长），把 PC 的内容（断点，即下一条指令的地址）经 MDR 写入主存保存，然后把中断服务程序的入口地址送入 PC，同时关闭中断允许标志。保存断点、关中断、取入口地址这三步由硬件自动完成，不依赖任何指令，因此称为中断隐指令。中断周期的引入使 CPU 具备了响应外部事件的能力。

## 机器周期与时钟周期
时钟周期（又称节拍、T 周期）是 CPU 中最小的时间单位，由主时钟产生，频率为 f 的时钟其周期为 T = 1/f。机器周期（CPU 周期）由若干时钟周期组成，是完成一个基本操作所需的时间，通常以一次访存所需的时间作为基准。如果所有机器周期都取相同的时钟周期数，称为定长机器周期，时序设计简单但时间利用率低；如果不同机器周期使用不同的时钟周期数，称为不定长机器周期，能让快的操作少占时间、提高效率，代价是时序控制更复杂。指令周期由若干机器周期组成，机器周期由若干时钟周期组成，三者呈层层包含的时序层次关系。

## 指令周期的数据流举例
把取数指令 LDA X（直接寻址）的完整过程串起来：取指周期中 PC→MAR、读主存、主存→MDR、MDR→IR、PC+1→PC；由于是直接寻址，无间址周期；执行周期中 IR 的地址码 X→MAR、读主存、主存→MDR、MDR→暂存器→累加器（若为间接寻址，则先进入一个间址周期把 (X) 取出送回 IR 的地址码字段）。若此时有中断请求且中断允许，则再进入中断周期保存断点。可见一条指令的机器周期数为 2（直接寻址）或 3（间接寻址），再加上可能的中断周期，这正是多周期 CPU 计算 CPI 的依据。

## 指令执行方案：单周期与多周期
单周期 CPU 让每条指令在一个时钟周期内完成，CPI 恒为 1，但时钟周期必须按最慢的指令设计，快的指令也要白白等满一个周期；同时取指令与执行指令可能同时用到主存，必须把指令存储器与数据存储器分开，硬件资源冗余大、时钟频率低，实际效率很差。多周期 CPU 把一条指令划分为若干机器周期，每个机器周期占一个（或几个）时钟周期，不同指令允许占用不同的机器周期数，部件可以复用，时钟周期只需按最慢的机器周期设计，因此时钟频率可以做得更高。多周期方案用"CPI 大于 1"换取了"时钟周期更短"，总体性能更好，也是流水线方案的基础。

## CPU 内部总线与数据通路
数据通路指 CPU 内部各部件之间传送数据的路径，它决定了完成一条指令需要几个节拍。单总线结构把所有寄存器都挂在一组公共的内部总线上，任一时刻只能有一个数据在总线上传送，因此一次运算需要"送操作数、送另一个操作数、送结果"等多个节拍，成本低但速度慢。双总线和三总线结构增加总线数量，可同时送出两个操作数并直接写回结果，一条运算指令可在一个节拍内完成。专用数据通路在寄存器之间设置专用的连线与多路选择器，速度最快但控制复杂、硬件量大，是现代流水线 CPU 的常见做法。

## 常见易错点与小结
常见错误包括：混淆 MAR 与 MDR 的位数依据（MAR 由存储单元数决定，MDR 由存储字长决定）；把 PC 的自增时机放到执行周期之后（实际在取指周期内完成）；认为所有指令都有间址周期或中断周期；把机器周期与时钟周期混为一谈；以及在数据流分析中遗漏"经暂存器中转"这一步（因为寄存器之间直接通过总线传送可能产生冲突）。本章的总线索是：CPU 的一切动作都可以用"寄存器之间的数据传送"来描述，指令周期就是把这种传送按取指、间址、执行、中断四个阶段组织起来，为下一章讨论控制器如何产生控制信号做好准备。
