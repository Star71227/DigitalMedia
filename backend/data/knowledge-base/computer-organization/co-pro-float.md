# 浮点数表示与浮点运算

## 浮点数的表示形式
浮点数把数表示为"阶码 + 尾数"两部分，其一般形式为 N = M × r^E，其中 M 为尾数（有效数字），E 为阶码（指数），r 为阶的基数（通常取 2）。这个形式与科学计数法完全一致：尾数给出有效数字，阶码指出小数点应该移动的位置。阶码是带符号的整数，用移码表示；尾数是带符号的定点小数，用原码或补码表示。阶码决定数值的表示范围，尾数决定数值的精度，两者在固定的字长内此消彼长：阶码位数越多范围越大而精度越低，尾数位数越多精度越高而范围越小。

## 阶码与尾数的作用
阶码 E 的位数决定了浮点数能表示的指数跨度，也就决定了最大数与最小数。若阶码为 k 位移码，则指数范围为 −2^(k−1) ~ +(2^(k−1)−1)，数值范围约为 r^(−2^(k−1)) ~ r^(+(2^(k−1)−1))。尾数 M 的位数决定了有效数字的位数，若尾数为 n 位，则相对精度约为 2^−n，也就是能区分的最小的相对差异。同一个字长下，定点数只能表示一个小范围但精度均匀的数集，浮点数则以牺牲整体精度均匀性为代价换取极大的表示范围，这正是科学计算需要浮点数的原因。

## 规格化与左右规
规格化要求尾数的绝对值落在规定区间内，使同一数值的表示唯一，并让尾数有效位不被浪费。以原码尾数为例，规格化条件是 1/2 ≤ |M| < 1，即最高数值位必须为 1。若运算结果的尾数不满足该条件（出现前导零），需要左规：尾数每左移一位、阶码减 1，直到满足条件。若尾数绝对值 ≥ 1（出现"尾数溢出"），需要右规：尾数右移一位、阶码加 1，右规最多做一次即可恢复正常区间。左规可能使阶码下溢到最小值以下，此时按机器零或非规格化数处理；右规可能使阶码上溢，此时按溢出（无穷大）处理。

## 补码规格化的判别
尾数用补码表示时，规格化的判别条件变为"符号位与最高数值位不同"。具体地说，正数应形如 0.1xxxx…，负数应形如 1.0xxxx…，即 1/2 ≤ M < 1 或 −1 ≤ M < −1/2。当尾数出现 0.0xxxx… 或 1.1xxxx… 时说明未规格化，需要左规；当出现 0.1 之外的溢出形态如 01.xxx 或 10.xxx（双符号位）时说明尾数溢出，需要右规。用补码表示尾数可以省去符号位与尾数分别处理的麻烦，并让加减法直接复用整数加法器，因此补码规格化是实际机器中更常见的做法。

## 偏置值与移码阶码
浮点数的阶码是有符号整数，为了便于硬件比较大小，通常用移码（偏置表示）存放：存放值 E = 真实指数 e + 偏置值 bias，因此真实指数 e = E − bias。传统教材中的移码偏置值取 2^(k−1)，例如 8 位移码偏置值为 128；而 IEEE 754 标准采用不同的偏置约定，单精度取 127、双精度取 1023。偏置值取 2^(k−1) − 1 的好处是让规格化数的阶码字段既不出现全 0 也不出现全 1，从而把全 0 与全 1 两个编码空出来表示零、非规格化数、无穷大与 NaN 等特殊值。

## IEEE 754 单精度格式
IEEE 754 单精度（binary32）共 32 位，从高位到低位依次为：1 位符号位 S、8 位阶码 E、23 位尾数 M。对于规格化数（1 ≤ E ≤ 254），真值为 N = (−1)^S × 1.M × 2^(E−127)，其中 1.M 表示隐含了整数位 1 的二进制小数，因此实际有效位数为 24 位。真实指数范围为 −126 ~ +127，对应的存储阶码为 1 ~ 254。规格化数的绝对值范围为 2^−126 ≈ 1.18 × 10^−38 到 (2 − 2^−23) × 2^127 ≈ 3.40 × 10^38，十进制约有 7 位有效数字。隐含位的存在是 IEEE 754 用有限位数据高精度的关键技巧。

## IEEE 754 双精度格式
IEEE 754 双精度（binary64）共 64 位，依次为 1 位符号位 S、11 位阶码 E、52 位尾数 M。规格化数（1 ≤ E ≤ 2046）的真值为 N = (−1)^S × 1.M × 2^(E−1023)，偏置值为 1023，真实指数范围为 −1022 ~ +1023，有效位数共 53 位，十进制约有 15~16 位有效数字。双精度的绝对值范围约为 2.2 × 10^−308 到 1.8 × 10^308。与单精度相比，双精度把增加的 32 位中的 3 位给了阶码、29 位给了尾数，因此既扩大了范围又显著提高了精度，是科学计算与 C 语言 double 类型的默认格式。

## 单精度与双精度的对比
两者的结构完全同构，只是字段宽度不同：单精度 1+8+23、偏置 127、指数范围 −126~127、精度约 7 位十进制；双精度 1+11+52、偏置 1023、指数范围 −1022~1023、精度约 15~16 位十进制。两者都采用隐含最高位 1 的规格化表示，也都用阶码全 0 与全 1 表示特殊值。由于字段宽度不同，同一个数学值在两种格式下的位模式完全不同，进行混合运算时必须先把单精度转换为双精度（转换是精确的，因为双精度的指数范围与尾数位数都能覆盖单精度），而双精度转单精度可能发生溢出与精度丢失。

## IEEE 754 的特殊值
阶码字段的两个边界编码留给了特殊值。当 E = 0 且 M = 0 时表示 ±0，符号位决定是 +0 还是 −0，两者在比较时相等。当 E = 0 且 M ≠ 0 时表示非规格化数，真值为 (−1)^S × 0.M × 2^(−126)（单精度）或 × 2^(−1022)（双精度），用来平滑地过渡到零，其最小正值为 2^−149（单精度）。当 E 全 1（单精度 255）、M = 0 时表示 ±∞，用于表示溢出与除以零的结果。当 E 全 1 且 M ≠ 0 时表示 NaN（非数），用于表示 0/0、∞−∞ 等非法运算，其中 M 最高位为 1 的称安静 NaN，为 0 的称信号 NaN。

## IEEE 754 编码与解码示例
掌握编码过程的关键是把真值写成 1.xxx × 2^e 的规格化形式，再令 E = e + bias、M 取小数点后的 23 位。例如 10.0 = 1.01 × 2^3，S=0、E = 3 + 127 = 130 = 10000010、M = 0100000…0，拼起来即 0 10000010 0100000…0 = 0x41200000。再如 −0.75 = −1.1 × 2^−1，S=1、E = −1 + 127 = 126 = 01111110、M = 100…0，位模式为 0xBF400000。解码时反向操作：把 E 减 127 得真实指数，尾数前补隐含的 1，再按位权展开乘以 2^e。

```c
#include <stdio.h>
#include <string.h>

void dump(float f) {
    unsigned int u;
    memcpy(&u, &f, 4);                 /* 按位复制，避免类型转换 */
    unsigned s = u >> 31, e = (u >> 23) & 0xFF, m = u & 0x7FFFFF;
    printf("%-6g 0x%08X  S=%u E=%u(真指数 %d) M=0x%06X\n",
           f, u, s, e, (int)e - 127, m);
}
int main(void) { dump(10.0f); dump(4.5f); dump(-0.75f); dump(100.0f); }
/* 输出：10 -> 0x41200000  E=130(真指数 3) M=0x200000
        4.5 -> 0x40900000 E=129(真指数 2) M=0x100000
       -0.75 -> 0xBF400000 S=1 E=126(真指数 -1) M=0x400000 */
```

## 浮点加减运算：对阶
浮点加减的第一步是对阶：求两数的阶差 ΔE = E_x − E_y。若 ΔE > 0 说明 x 的阶大，则把 y 的尾数右移 ΔE 位、其阶码加到 E_x；若 ΔE < 0 则把 x 的尾数右移 |ΔE| 位。选择"小阶向大阶看齐"而不是反过来，是因为尾数右移只丢失低位、误差相对较小，而大阶尾数左移会丢失高位甚至造成真正的数值错误；而且若让大阶向小阶看齐，尾数左移后可能直接溢出。右移时被移出的位不能简单丢弃，应保留为保护位、舍入位与粘位，供后续舍入使用，否则结果精度会明显下降。

## 浮点加减运算：尾数运算与规格化
对阶完成后两数阶码相同，即可对尾数做加减：尾数用补码表示时直接按定点补码加减法运算，符号位参加运算，并把结果表示为双符号位以便判断。尾数运算的结果可能出现三种情况，需要分别处理。第一种是尾数溢出（绝对值 ≥ 1，双符号位为 01 或 10），此时做一次右规：尾数右移一位、阶码加 1。第二种是结果未规格化（出现前导零或符号位与最高数值位相同），此时做左规：尾数逐位左移、阶码逐次减 1，直到满足规格化条件；左规可能执行多次。第三种是结果为零，此时应直接把阶码置为最小值并把尾数清零，按机器零处理。

## 浮点加减运算：舍入与溢出判断
规格化之后要对移出的多余位做舍入。IEEE 754 定义了四种舍入方式：就近舍入到偶数（默认方式）、朝零舍入（截断）、朝正无穷舍入、朝负无穷舍入。就近舍入到偶数在"恰好为半个单位"时把结果末位凑成 0，可避免统计上的偏差累积。舍入本身可能使尾数再次溢出，因此舍入后若尾数超出规格化范围，还需要再做一次右规。最后做阶码的溢出判断：阶码超过最大值称为上溢（overflow），结果按 ±∞ 处理；阶码小于最小值称为下溢（underflow），结果按 0 或非规格化数处理。若参与运算的某个操作数为 0，则结果直接取另一个操作数，无需走完整流程。

## 浮点乘除运算
浮点乘法的步骤是：阶码相加，尾数相乘，结果规格化与舍入。由于两个操作数的阶码都含有偏置值，相加后偏置被计入两次，因此阶码相加后必须再减去一个偏置值才能得到正确的存储阶码，即 E_r = E_1 + E_2 − bias。浮点除法的步骤是：阶码相减，尾数相除，规格化与舍入，阶码相减时偏置被抵消，因此需加上一个偏置值：E_r = E_1 − E_2 + bias。乘除法的尾数运算复用定点乘法与除法部件，尾数乘的结果为 2n 位，需要保留足够的附加位后再舍入。符号位始终由两个操作数符号位异或得到。

## 舍入模式与浮点精度问题
以单精度为例，0.1 的二进制展开是无限循环小数，只能截取 24 位有效位保存，因此 0.1 的实际存储值略大于或小于 1/10。这直接导致 0.1f + 0.2f 在单精度下不等于 0.3f，也是"浮点比较不能用 =="这一工程惯例的根源。此外，浮点加法不满足结合律：(a + b) + c 与 a + (b + c) 可能因中间结果的舍入而不同；大数加小数时小数可能被完全"吃掉"，例如 10^8 加 1 在单精度下仍等于 10^8。这些性质并非实现缺陷，而是有限位长表示的必然结果，编程时应通过误差容限比较、Kahan 求和等技巧缓解。

## 浮点数的表示范围与精度取舍
在字长固定时，阶码位与尾数位之间存在直接的取舍关系。加大阶码字段可以扩展表示范围，但尾数变短、精度下降；加大尾数字段可以提高精度，但表示范围缩小。IEEE 754 单精度给阶码 8 位、尾数 23 位，双精度给阶码 11 位、尾数 52 位，是经过大量数值实验后在"范围够用"与"精度够用"之间取得的折中。扩展精度格式（如 x86 的 80 位扩展双精度，1+15+64）则同时扩大了两者，代价是占用更多存储与电路资源。

## 常见易错点与小结
常见错误包括：把 IEEE 754 阶码的偏置值误写为 128 或 1024；忘记规格化数隐含的整数位 1，导致解码结果差 2 倍；把对阶方向搞反成"大阶向小阶看齐"；做乘法时忘记阶码相加后要减去一个偏置值；把尾数溢出与阶码上溢混淆（前者需右规，后者才真正溢出）。浮点运算的总流程可以概括为五步：对阶、尾数运算、规格化、舍入、判溢出。把这五步与定点加减、移位、乘除法的硬件实现对应起来，就构成了完整的浮点运算器数据通路。
