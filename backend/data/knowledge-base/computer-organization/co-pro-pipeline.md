# 指令流水线

## 流水线的基本概念
流水线技术借用工业生产装配线的思想：把一条指令的执行过程分解为若干子过程（称为"段"或"级"），每一段由独立的功能部件完成，各段之间用锁存器（流水寄存器）隔开。当第 i 条指令在第二段执行时，第 i+1 条指令已进入第一段，第 i−1 条指令则进入第三段，于是多条指令在同一时刻处于不同段中并行工作。流水线并不缩短单条指令的执行时间（甚至因锁存器开销而略有延长），但它通过重叠执行大幅提高了单位时间内完成的指令条数，也就是提高了吞吐率。经典的 RISC 五段流水线划分为：IF 取指、ID 译码与取寄存器、EX 执行或地址计算、MEM 访存、WB 写回。

## 流水线的分类
按级别分，流水线可分为部件级流水线（运算器内部的流水，如浮点加法器分四段）、处理机级流水线（指令流水线，即指令各阶段的流水）和处理机间流水线（多处理机之间的宏流水，各处理机完成同一程序的不同部分）。按功能分，可分为单功能流水线（只能完成一种固定功能）与多功能流水线（各段可重新组合完成不同运算）。按连接方式分，可分为静态流水线（同一时刻各段只能按同一种功能连接，需等排空后才能切换功能）与动态流水线（同一时刻允许多种功能连接同时工作，效率更高但控制复杂）。按是否有反馈回路分，又可分为线性流水线与非线性流水线。

## 流水线时空图
时空图是分析流水线性能的基本工具：横轴表示时间（以时钟周期为单位），纵轴表示流水线各段，图中每一小格代表一条指令在某一时间段内占用某一段。理想情况下，若流水线有 k 段、每段耗时均为 Δt，则第 1 条指令需要 k 个 Δt 走完全程，此后每隔 Δt 完成一条新指令。因此连续执行 n 条指令所需的总时间为 T = (k + n − 1)·Δt：其中前 (k−1)·Δt 是流水线的"装入时间"，用于填满各段，最后 (k−1)·Δt 是"排空时间"，只有中间 n·Δt 是有效工作时间。这条公式是后面吞吐率、加速比与效率计算的基础。

## 流水线性能：吞吐率
吞吐率（TP）指单位时间内流水线完成的指令条数，是衡量流水线效率最直接的指标。在理想情况下，连续执行 n 条指令的总时间为 T = (k + n − 1)Δt，故实际吞吐率 TP = n / T = n / [(k + n − 1)Δt]。当 n 趋于无穷大时，TP 趋近于最大值 TP_max = 1/Δt，即流水线满负荷时每个时钟周期完成一条指令。可见 Δt 越小（时钟频率越高）、装入与排空所占比例越小，吞吐率越高。当指令条数较少时，装入与排空的开销占比很大，流水线的优势难以体现，这也是循环体内只有很少指令时流水线收益有限的原因。

## 流水线性能：加速比
加速比（S）指不使用流水线时的串行执行时间与使用流水线后的执行时间之比，衡量流水线相对于非流水线的相对收益。串行执行 n 条指令需 n·k·Δt，流水线执行需 (k + n − 1)Δt，因此 S = n·k·Δt / [(k + n − 1)Δt] = n·k / (k + n − 1)。当 n 趋于无穷大时，S 趋近于流水线的段数 k，也就是说流水线的加速比上限等于流水线的级数。这个上限的存在说明：单纯增加流水线级数并不能无限提升性能，因为级数增多会使锁存器开销占比上升、冒险增多。实际加速比还受数据相关、分支、访存延迟等因素影响，通常远低于理论值。

## 流水线性能：效率
效率（E）指流水线中各部件的实际使用时间与整个运行时间之比，也可以理解为时空图中被有效利用的格子占总格子的比例。由于 E = S / k，把加速比公式代入可得 E = n / (k + n − 1)。对固定的 n，段数 k 越多效率越低（装入排空开销占比越大）；对固定的 k，n 越大效率越高，当 n 趋于无穷时 E 趋近于 1。理想情况下效率的上限是 1，即所有部件在整个运行期间都在工作。效率过低说明存在大量空闲段或流水线频繁停顿，通常由结构冒险、数据冒险或控制冒险引起。

## 流水线性能计算示例
设某流水线分 5 段，每段耗时 Δt = 2ns，连续执行 n = 100 条指令。串行执行时间 = 100 × 5 × 2ns = 1000ns；流水线执行时间 T = (5 + 100 − 1) × 2ns = 208ns；实际吞吐率 TP = 100 条 / 208ns ≈ 0.4808 条/ns，即约 4.81 × 10^8 条/秒；加速比 S = 1000 / 208 ≈ 4.81；效率 E = S / k = 4.81 / 5 ≈ 96.2%。可见在指令流足够长时，5 段流水线能获得接近 5 倍的加速。

```c
#include <stdio.h>

/* 计算流水线的吞吐率、加速比与效率 */
void pipe_perf(int k, double dt_ns, int n) {
    double T_pipe  = (k + n - 1) * dt_ns;      /* 流水线总时间 */
    double T_serial = (double)n * k * dt_ns;   /* 串行总时间   */
    printf("T=%.1fns TP=%.4f 条/ns S=%.3f E=%.1f%%\n",
           T_pipe, n / T_pipe, T_serial / T_pipe, 100.0 * n / (k + n - 1));
}
/* pipe_perf(5, 2.0, 100) → T=208.0ns TP=0.4808 S=4.808 E=96.2% */
```

## 流水线各段不等长与瓶颈段
实际流水线各段的延迟往往不相等，此时必须以最慢的那一段（称为瓶颈段）的耗时作为 Δt，其余较快的段在完成工作后必须插入缓冲或锁存器等待，造成空闲。这就使得实际加速比比"段数"小得多。提高性能的主要手段是设法消除瓶颈：把瓶颈段进一步细分为若干子段，使其单段延迟与其他段相当；或者在同一段内设置多套重复的部件（如两个乘法器交替工作），使该段能同时处理多条指令。若某段耗时是其他段的两倍，把它一分为二即可把瓶颈转移到别处，从而缩短整条流水线的时钟周期。

## 结构冒险
结构冒险（资源冲突）指多条指令在同一时刻争用同一硬件资源，导致部分指令无法按时进入某一段。典型例子有两个：一是取指令与取数据共用同一个存储器，当一条访存指令在 MEM 段访问数据时，IF 段也要访问同一个存储器取指令，二者冲突；二是写回阶段写寄存器堆与译码阶段读寄存器堆在同一周期内争夺寄存器堆的端口。解决方法包括：把指令存储器与数据存储器分开（即分离的指令 Cache 与数据 Cache）、采用双端口存储器、在寄存器堆中设置独立的读写端口、或者让流水线停顿一个周期以回避冲突。结构冒险是硬件资源不足造成的，属于最容易通过增加资源来缓解的一类冒险。

## 数据冒险
数据冒险指后面的指令需要用到前面指令尚未产生（尚未写回寄存器）的结果，导致读到错误的旧值。按访问顺序可分为三类：写后读（RAW）指后一条指令读的寄存器正是前一条指令将要写的，这是真正的数据相关，也是按序流水线中唯一会出现的一类；读后写（WAR）指后一条指令写、前一条指令读，属于反相关；写后写（WAW）指两条指令写同一寄存器，属于输出相关。在按序发射、按序完成的五段流水线中，指令的读写顺序与程序顺序一致，因此不会出现 WAR 与 WAW；只有在乱序执行的处理器中才需要专门处理这两类冒险。

## 数据冒险的解决：转发与停顿
转发（旁路）技术把尚未写回寄存器堆的运算结果直接从流水寄存器（EX/MEM 或 MEM/WB）送到后续指令的 ALU 输入端，从而让后续指令不必等待写回。例如 add r1, r2, r3 紧接着 sub r4, r1, r5，r1 的结果在 EX 段末已产生，处于 EX/MEM 寄存器中，sub 指令在 EX 段开始前即可通过旁路取到它，无需插入停顿。但有一类情况转发也无法完全消除延迟：load 指令的数据要到 MEM 段末才从主存取回，紧随其后的使用该数据的指令即使采用转发也必须停顿一个周期，这称为 load-use 冒险，解决方法是插入一个空操作（气泡）或由编译器重新安排指令顺序。此外，寄存器重命名可以消除 WAR 与 WAW 相关。

## 控制冒险
控制冒险由转移类指令引起：分支指令尚未确定是否转移、转移目标地址尚未算出时，流水线已经按顺序取入了后续指令，一旦分支成立，这些预取的指令就全部作废，必须从正确目标重新取指，造成流水线断流。分支在流水线中越晚确定，损失的周期数越多：若在 EX 段确定，通常损失 2~3 个周期。常见解决方法包括：在分支指令后插入足够多的空操作或让流水线停顿（简单但开销大）；把分支判断提前到 ID 段并同时计算目标地址（需要额外的比较器与加法器）；采用延迟分支，在分支指令后填入若干条无论分支是否成立都要执行的指令（由编译器负责填充）。

## 静态分支预测与延迟分支
静态分支预测在编译时固定预测方向，不依赖运行历史。最简单的两种策略是"预测总是不转移"（预测准确率对循环结构通常约 30%~50%，需等分支指令执行完才知道预测错误）和"预测总是转移"（对循环结构准确率较高）。改进方案是由编译器为每条分支指令设置一个方向位（如指出该分支通常是循环回边，应预测转移；通常是错误处理分支，应预测不转移）。延迟分支则把分支延迟槽中的指令规定为"必然执行"，由编译器填入有用指令（从分支前搬移）或空操作，这样即使分支方向未定，流水线也不会浪费取指带宽。

## 动态分支预测
动态分支预测在程序运行时依据历史信息预测分支方向，能自适应程序的行为。最简单的实现是分支历史表（BHT）：用分支指令地址的低位索引一张表，表中存放该分支最近一次的跳转方向，据此预测。更好的是两位饱和计数器：计数器有 4 个状态——11 强转移、10 弱转移、01 弱不转移、00 强不转移；每次分支实际发生则向 11 方向加，不发生则向 00 方向减，只有跨越中间状态才翻转预测方向。这样对循环最后一次退出这类偶发反向只会计数减半而不立即改判，明显降低了错误率。分支目标缓冲（BTB）则在 IF 段就把分支指令地址映射到预测的目标地址，使取指不必等目标地址计算完成，进一步减少了断流损失。

## 超标量与超流水线
超标量（Superscalar）指在一个时钟周期内并发发射多条指令，处理机内部设置多套功能部件（多个 ALU、多个访存部件），使 CPI 可以小于 1。例如四路超标量理论上每周期可完成 4 条指令，实际受相关性、资源与分支的限制远达不到。超标量需要解决指令的动态调度问题，方法包括按序发射按序完成、按序发射乱序完成、乱序发射乱序完成（配合保留站与重排序缓冲）。超流水线（Superpipelining）则把流水线的每一段进一步细分，使时钟周期更短、时钟频率更高，每周期仍发射一条指令，但指令的总延迟（以周期数计）增加。两者可以结合使用，称为超标量超流水线。VLIW（超长指令字）把并行性完全交给编译器，由编译器把若干可并行的操作打包成一条超长指令，硬件简单但代码兼容性差。

## 流水线寄存器与指令级并行
段与段之间必须设置流水寄存器（锁存器），用来保存在本段产生的、下一段需要的数据与控制信息，例如 IF/ID 段间寄存器保存取到的指令与 PC 值，ID/EX 段间寄存器保存译码结果、寄存器读出的操作数与控制信号，EX/MEM 段间寄存器保存运算结果与写回目标寄存器的编号。流水寄存器不仅要传递数据，还要传递"这条指令是什么、要做什么"的控制信息，因此它的位宽往往远大于数据本身。指令级并行（ILP）指指令之间隐含的可并行性，流水线、超标量、乱序执行、循环展开与软件流水都是开发 ILP 的手段；当 ILP 不足时，还可通过同时多线程（SMT）从多个线程中取指以填满流水线。

## 流水线冒险综合示例
考虑一段代码：lw r1, 0(r2)；add r4, r1, r5；beq r4, r6, L1。lw 的结果在 MEM 段末可用，add 需要它作为 ALU 输入，因此必须在两者之间插入一个气泡（停顿 1 个周期），或者由编译器把无关指令调到中间。add 的结果 r4 被 beq 使用，若 beq 的判断在 EX 段进行，可以通过转发解决；若判断在 ID 段进行，则需要再插入一个气泡。可见同一段代码的停顿数与"分支判断放在哪一级""是否支持转发"密切相关。实际处理器通过"转发 + 提前分支判断 + 动态预测 + 编译器调度"的组合把停顿降到很低，再配合乱序执行隐藏访存延迟。

## 常见易错点与小结
常见错误包括：把流水线加速比的上限误认为可以无限增大（实际上限就是段数 k）；在不等长流水线中忘记以最长段耗时作为 Δt；把结构冒险与数据冒险混淆；认为转发可以消除所有数据冒险（load-use 冒险仍需停顿）；以及忽略装入与排空时间，用 n·Δt 作为总时间。流水线的核心结论可以归纳为三条公式：T = (k + n − 1)Δt、S = nk/(k+n−1)、E = n/(k+n−1)，以及一个上限 S ≤ k。三类冒险（结构、数据、控制）及其解决手段（增加资源、转发与停顿、预测与延迟分支）构成了流水线设计的全部技术主线。
