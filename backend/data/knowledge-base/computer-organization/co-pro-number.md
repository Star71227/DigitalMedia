# 数据的表示

## 进位计数制
在进位计数制中，数用一组固定数字符号按位权展开表示。任意 R 进制数可写成 N = Σ d_i × R^i，其中 R 为基数，d_i 为第 i 位的数字（取值 0 ~ R-1），R^i 为该位的位权。二进制 R=2，只用 0 和 1 两个符号，运算规则简单、易于用双稳态电路实现，是计算机内部唯一直接使用的数制。八进制 R=8 与十六进制 R=16 是二进制的压缩书写形式：因为 8=2³、16=2⁴，一位八进制对应三位二进制，一位十六进制对应四位二进制。十六进制用 0~9 与 A~F 共 16 个符号，书写时常加后缀 H 或前缀 0x，例如 0x2F 即 00101111B。

## 进制转换
十进制转 R 进制时，整数部分用"除 R 取余、逆序排列"，小数部分用"乘 R 取整、顺序排列"。例如十进制 45 转二进制：逐次除以 2 得余数 1、0、1、1、0、1，逆序读即 101101B。二进制转八进制时以小数点为界向两侧每三位并作一组、不足补零；转十六进制则每四位一组，因此三种进制之间的转换可以借助分组直接完成，不必经过十进制。需要注意的是十进制小数 0.1 的二进制展开是无限循环小数，只能近似截取保存，这正是浮点运算产生表示误差的根源之一。

## 无符号数与有符号数
无符号数把全部数位都当作数值位，n 位无符号整数的表示范围是 0 ~ 2^n − 1，例如 8 位为 0~255，16 位为 0~65535。有符号数则必须从数位中划出一位作为符号位，通常规定最高位为符号位：0 表示正、1 表示负，其余位为数值位。计算机中的加减法电路本身并不区分逻辑上的正负，它只是对二进制位做加法并丢弃最高位进位，因此有符号数必须选择一种机器数编码（原码、反码、补码、移码）来规定位模式与真值的对应关系；编码方式不同，同一组位模式所代表的真值就不同。

## 真值与机器数
真值是数在数学意义上的实际值，带正负号，例如 −1011B、+0.1011。机器数是真值在计算机中的二进制编码，符号被"数字化"为 0 或 1，字长固定。同一个真值在不同编码下对应不同的机器数：8 位下 −5 的原码为 10000101、反码为 11111010、补码为 11111011。反过来，同一个机器数在不同编码下也代表不同的真值：10000001 在原码中是 −1，在补码中却是 −127。因此讨论"某个二进制串等于多少"时，必须先说明字长与编码方式，二者的乘积才构成完整的表示语义。

## 原码表示法
原码的编码规则是：最高位为符号位（正数取 0、负数取 1），其余数值位直接写出绝对值的二进制。若字长为 n，原码整数可表示 −(2^(n−1)−1) ~ +(2^(n−1)−1)，8 位为 −127~+127。原码的优点是直观、与真值换算简单，并且符号位与数值位分离，乘除法用原码实现最方便；缺点是加减运算不能统一处理，需要先比较符号与绝对值大小再决定做加法还是减法，还要单独确定结果的符号，并且存在 +0（00000000）与 −0（10000000）两种零表示，给判零逻辑带来额外麻烦。

## 反码表示法
反码通常只作为求补码的中间形式：正数的反码与原码相同；负数的反码是原码除符号位外各位取反。8 位下 −5 的原码为 10000101，反码为 11111010。反码同样有两个零（00000000 与 11111111），可表示的整数范围与原码一致，为 −(2^(n−1)−1) ~ +(2^(n−1)−1)。由于零的表示不唯一，现代计算机不把反码作为最终的存储形式；但在"循环进位"（把最高位进位加到最低位）的规则下，反码的加减法也能得到正确结果，这一性质在早期机器中曾被采用。

## 补码表示法
补码是计算机中整数的事实标准编码：正数的补码与原码相同；负数的补码等于其反码末位加 1，也等于 2^n − |x|（n 为字长）。8 位下 −5 的补码是 11111011。补码的零只有一种表示 00000000，因此负数端可以多表示一个数：n 位补码整数的范围是 −2^(n−1) ~ +(2^(n−1)−1)，8 位为 −128~+127。补码把减法统一成加法，[x−y]补 = [x]补 + [−y]补，硬件上只需一个加法器即可同时完成加减，这是补码被普遍采用的根本原因。由补码求真值既可"符号位不变、数值位取反后末位加 1"，也可按位权展开、把最高位的权取负。

## 移码表示法
移码把真值加上一个固定偏置后再按无符号二进制书写：[x]移 = 2^(n−1) + x，其中 −2^(n−1) ≤ x ≤ 2^(n−1)−1。移码与补码的关系非常简单：把补码的符号位取反即得移码。例如 8 位下 +5 的补码为 00000101、移码为 10000101（十进制 133）；−5 的补码为 11111011、移码为 01111011（十进制 123）。移码最大的特点是机器数的大小顺序与真值的大小顺序一致，便于硬件直接比较大小，因此常用于表示浮点数的阶码。需要特别注意，IEEE 754 单精度阶码采用的是偏置值 127 的移码，而不是上面公式给出的 128。

## 四种码制的比较
以 8 位为例：原码、反码的表示范围为 −127~+127，补码与移码为 −128~+127；原码、反码有两个零，补码、移码的零表示唯一。补码最适合加减运算，原码最适合乘除运算（符号位单独处理），移码最适合阶码的大小比较。同一真值 −5 的四组机器数分别是原码 10000101、反码 11111010、补码 11111011、移码 01111011。判断一个位串对应的真值时，顺序应当是：先确定编码方式，再确定字长，最后才做位权展开计算。

## 补码的运算
补码加减法的核心公式是 [x+y]补 = [x]补 + [y]补 (mod 2^n)、[x−y]补 = [x]补 + [−y]补 (mod 2^n)，其中 [−y]补 由 [y]补 连同符号位一起取反、末位加 1 得到。加法器只需按无符号二进制相加，超出字长的进位自然丢弃，恰好实现了模 2^n 的运算。例如 8 位下计算 5 − 7：00000101 + 11111001 = 11111110，即 −2。必须强调，"进位被丢弃"并不等于"结果溢出"：溢出是指运算结果超出了补码可表示的范围，需要另行用专门规则判断，两者的判断依据完全不同。

## 符号扩展
把短字长的数放入长字长时要做符号扩展，否则真值会被改变。补码的符号扩展最简单：在左边补足与原符号位相同的位即可，例如 8 位 11111011（−5）扩展为 16 位是 1111111111111011。原码的扩展是在符号位与数值位之间补 0，例如 8 位 10000101 扩展为 16 位是 1000000000000101。反码的扩展规则与补码相同，也是在左边补与原符号位相同的位。无符号数扩展一律在左边补 0，称为零扩展。反过来做截断时只能丢弃高位，补码截断后保留的低位仍按补码解释，真值可能已经改变。

## 定点数表示范围
定点数约定小数点的位置固定不变。定点小数把小数点固定在符号位之后，n 位补码定点小数的范围是 −1 ~ +(1 − 2^−(n−1))；定点整数把小数点固定在最低位之后，n 位补码定点整数的范围是 −2^(n−1) ~ +(2^(n−1)−1)。以 16 位补码定点整数为例，范围为 −32768 ~ +32767；32 位为 −2147483648 ~ +2147483647。定点数表示范围小且固定，一旦运算结果超出范围就会溢出。当需要表示的数值范围很大或对精度有动态要求时，必须改用浮点数表示。

## BCD 码与字符编码
BCD 码用 4 位二进制表示一位十进制数，最常用的是 8421 码，其中 1010~1111 为非法编码。压缩 BCD 码一个字节存放两位十进制数，非压缩 BCD 码一个字节只放一位（高 4 位通常为 0）。ASCII 用 7 位编码表示 128 个字符，其中 '0' 为 0110000（0x30）、'A' 为 1000001（0x41）、'a' 为 1100001（0x61）；数字字符与字母字符的低 4 位恰好等于其数值或序号，便于程序做换算。汉字常用国标码、区位码与机内码表示，机内码把国标码两个字节的最高位都置 1 以与 ASCII 区分。

## 数据的存储顺序与对齐
多字节数据在主存中按字节编址存放时存在两种顺序：大端方式把高位字节放在低地址，小端方式把低位字节放在低地址。32 位数 0x12345678 在大端机器中从低地址到高地址依次是 12、34、56、78，在小端机器中则是 78、56、34、12。边界对齐要求数据的起始地址是其自身长度的整数倍，例如 4 字节整数的起始地址必须是 4 的倍数。对齐会浪费少量存储空间，但能保证一次访存取完整个数据；未对齐的访问可能需要两次总线传送，甚至触发硬件异常。

## 常见易错点与小结
常见错误包括：把"最高位进位被丢弃"误认为溢出；把 8 位补码的最小值写成 −127 而漏掉 −128；混淆负数的反码与补码（忘记末位加 1）；符号扩展时补 0 而不是补符号位；以及忽略字长直接对位串做位权展开。判断溢出必须使用专门的规则（进位判别、双符号位判别或符号位判别），不能用"是否有进位"代替。本章是整门课程的基础：编码方式决定了数据的表示范围，也决定了运算器需要配置哪些运算部件与判断电路。

## 位运算示例
下面的 C 代码演示如何在程序中观察补码的性质。第一段把 −5 按位取反后末位加 1，得到 +5，这正是硬件求相反数的做法，也说明了 [−y]补 的由来；第二段用 0x80 构造 8 位补码的最小值 −128，说明补码比原码、反码多表示一个负数；第三段把 int8_t 赋给 int16_t，编译器自动做符号扩展，高位补符号位 1，位模式由 0xFB 变为 0xFFFB；第四段把同一个位模式 0xFB 分别按无符号数与有符号数解释，得到 251 与 −5，直观展示了"位模式相同、编码解释不同则真值不同"这一基本结论。

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    int8_t  a = -5;
    int8_t  b = (int8_t)(~a + 1);          /* 取相反数：按位取反末位加 1 */
    printf("a=%d  ~a+1=%d\n", a, b);       /* -5, 5 */

    int8_t  mn = (int8_t)0x80;             /* 1000 0000 即补码最小值 */
    printf("min(int8_t) = %d\n", mn);      /* -128 */

    int16_t wide = (int16_t)a;             /* 符号扩展：高位补符号位 1 */
    /* 只取低 16 位打印，否则被提升为 32 位无符号数会显示 0xFFFFFFFB */
    printf("sign-extended = 0x%04X\n", (unsigned)(uint16_t)wide);  /* 0xFFFB */

    uint8_t raw = 0xFB;                    /* 与 -5 的补码位模式相同 */
    printf("unsigned view = %u, signed view = %d\n", raw, (int8_t)raw); /* 251, -5 */
    return 0;
}
```

## 本章小结
数据的表示要回答三个问题：用多少位（字长）、如何划分符号位与数值位（编码）、以及小数点在哪里（定点或浮点）。原码、反码、补码、移码是同一真值的四种位模式约定，只有补码能同时满足"零唯一"和"加减统一"两个工程要求，因此成为整数运算的基础；移码因保序性成为阶码的当然选择。掌握这些约定之后，才能进一步理解运算器的溢出判断电路、浮点数的规格化与舍入规则，以及乘除法中移位与加减的迭代过程。
