# Cache 与虚拟存储器

## Cache 的作用与工作原理
Cache（高速缓冲存储器）位于 CPU 与主存之间，容量小、速度接近 CPU，用来缓解 CPU 与主存之间的速度差距。其工作原理建立在程序访问的局部性之上：把主存划分成若干块，把当前活跃的块复制一份到 Cache 中；CPU 访存时先查 Cache，若所需数据所在块已在 Cache 中（命中）就直接读出，无需访问主存；若不在（缺失）则从主存把整块调入 Cache，再供 CPU 使用。由于命中率通常可达 90% 以上，平均访问时间接近 Cache 的访问时间。Cache 的全部工作由硬件自动完成，对程序员完全透明。

## 命中率与平均访问时间
命中率 h 指 CPU 访存时在 Cache 中找到所需数据的次数占总访问次数的比例，缺失率则为 1 − h。平均访问时间取决于访问模型：若采用"并行访问"模型，即同时启动 Cache 与主存的访问、命中时终止主存访问，则 Ta = h·tc + (1 − h)·tm，其中 tc 为 Cache 访问时间、tm 为缺失时访问主存并把块调入 Cache 所需的时间；若采用"串行访问"模型，即先访问 Cache 失败后才访问主存，则 Ta = tc + (1 − h)·tm。用效率 e = tc / Ta 衡量 Cache 的加速效果，e 越接近 1 说明性能越接近理想值。

## 命中率计算示例
设 Cache 访问时间 tc = 1ns，缺失时访问主存并调入一块的时间 tm = 100ns。若命中率 h = 0.95，按并行访问模型计算：Ta = 0.95 × 1ns + 0.05 × 100ns = 0.95ns + 5ns = 5.95ns，效率 e = 1 / 5.95 ≈ 16.8%；若把命中率提高到 0.99，则 Ta = 0.99 × 1 + 0.01 × 100 = 1.99ns，e ≈ 50.3%。可见命中率的小幅提升会带来平均访问时间的显著下降，这是因为缺失代价比命中代价大两个数量级。由此得到 Cache 优化的两条主线：提高命中率（更大的容量、更好的映射与替换算法）与降低缺失代价（多级 Cache、提前调块、关键子块优先返回）。

```c
/* 平均访问时间与效率计算（并行访问模型） */
double avg_time(double h, double tc, double tm) { return h * tc + (1 - h) * tm; }
/* avg_time(0.95, 1.0, 100.0) = 5.95 ns  → e = 16.8%
   avg_time(0.99, 1.0, 100.0) = 1.99 ns  → e = 50.3% */
```

## 主存与 Cache 的块划分与地址结构
主存与 Cache 之间的数据交换以"块"（Cache 中称为行）为单位，块的大小通常为 16B、32B、64B，取块长等于或略大于一次突发传输的数据量。地址被划分为三个部分：块内偏移（offset）用于在块内定位具体字节，位数等于 log2(块大小)；行号或组号（index）用于在 Cache 中定位候选行或组，位数由 Cache 的行数或组数决定；标记（tag）是剩余的高位部分，用于与候选行的标记比较以确认是否命中。三部分位数之和等于主存地址位数，这个划分关系是分析一切 Cache 问题的基础。

## 直接映射
直接映射规定主存中的每一块只能放入 Cache 中唯一确定的一行：行号 = 主存块号 mod Cache 行数，当 Cache 行数是 2 的幂时该运算等价于取主存块号的低位。地址划分为"标记 + 行号 + 块内偏移"，查表时只需按行号选中一行，再用该行的标记与地址中的标记比较（只需一个比较器），命中判断最快、硬件最省。缺点是冲突缺失严重：若程序反复交替访问映射到同一行的两个不同主存块，就会不断发生缺失（称为抖动），即使 Cache 中还有大量空行也无济于事。

## 全相联映射
全相联映射允许主存中的任意一块放入 Cache 中的任意一行，地址只划分为"标记 + 块内偏移"两部分，没有行号字段。查表时必须把地址中的标记与 Cache 中所有行的标记并行比较，因此需要相联存储器（按内容访问）与大量比较器，硬件成本高、查表速度受比较器级联延迟影响，容量较大时难以实现。优点是冲突缺失最少、命中率最高。它通常只用于容量很小的场合，例如 TLB、全相联的小型指令 Cache 或 Cache 中的牺牲缓存（victim cache）。

## 组相联映射
组相联映射是直接映射与全相联的折中：把 Cache 分成若干组，组间采用直接映射（主存块只能放入唯一确定的组，组号 = 主存块号 mod 组数），组内采用全相联（块可放入该组的任意一行）。N 路组相联表示每组有 N 行，查表时需同时比较 N 行的标记，因此需要 N 个比较器与 N 路选择器。地址划分为"标记 + 组号 + 块内偏移"。路数增加会提高命中率但增加硬件与访问延迟：8 路组相联的命中率通常已接近全相联，因此现代处理器的 L1、L2 Cache 普遍采用 4 路或 8 路组相联。

## 地址划分与位数计算示例
设主存地址 32 位，Cache 数据容量为 32KB，块大小 64B，采用 4 路组相联。第一步求块内偏移位数：log2(64) = 6 位。第二步求 Cache 总行数：32KB / 64B = 512 行。第三步求组数：512 / 4 = 128 组，故组号位数 = log2(128) = 7 位。第四步求标记位数：32 − 7 − 6 = 19 位。如果改为直接映射，则行号位数 = log2(512) = 9 位、标记位数 = 32 − 9 − 6 = 17 位；如果改为全相联，则没有组号字段，标记位数 = 32 − 6 = 26 位。可见路数越多，标记字段越长、所需的比较器越多。

## 标记阵列容量与辅助位
Cache 除存放数据外，还要为每一行保存标记与若干状态位，这部分存储称为标记阵列。以 32 位地址、32KB 数据、64B 块、4 路组相联为例：共 512 行，每行需 19 位标记 + 1 位有效位（valid，标识该行内容是否有效）+ 1 位脏位（dirty，用于写回策略）= 21 位，标记阵列总容量 = 512 × 21 位 = 10752 位 = 1344 字节。若采用组相联或全相联，还需为每行设置替换算法所需的位，例如 LRU 需为每组保存 N 个计数或一个状态编码；采用多位预测或其他策略时，辅助位会进一步增加。计算 Cache 总开销时必须把数据阵列与标记阵列一并计入。

## 替换算法
当 Cache 已满而需要调入新块时，必须选择一行淘汰，这就是替换算法要解决的问题。直接映射无需替换算法（位置唯一），全相联与组相联则需要。最近最少使用（LRU）算法淘汰最久未被访问的行，最符合局部性原理、命中率最高，但需要为每行维护访问计数或年龄栈，硬件开销随路数增长（N 路需 log2(N!) ≈ N·log2 N 位状态）。先进先出（FIFO）按调入顺序淘汰最早进入的行，实现简单（只需一个循环指针），但可能淘汰掉仍被频繁使用的行，甚至在某些访问序列下出现命中率随容量增大反而下降的异常现象。随机算法（RAND）用计数器或伪随机数选择淘汰行，硬件最省、性能平均，大量实验表明它与 LRU 的命中率差距并不大，因此实际处理器常采用随机或近 LRU（如伪 LRU）策略。

## 写策略
Cache 的写策略需要回答两个问题：写命中时是否同步更新主存，写缺失时是否把块调入 Cache。写直达（write-through）在每次写命中时同时更新 Cache 与主存，一致性好、实现简单，但每次写都要访问主存，开销大，通常配合写缓冲（write buffer）把写操作排队以隐藏主存延迟。写回（write-back）只在 Cache 中修改并置脏位，等到该行被替换时才把整块写回主存，可大幅减少访存次数，但会出现 Cache 与主存暂时不一致的情况（多核系统中需靠一致性协议处理）。写分配（write-allocate）在写缺失时先把块调入 Cache 再修改，使后续访问可能命中，通常与写回配合使用。非写分配（no-write-allocate）在写缺失时直接写主存、不调入块，通常与写直达配合使用。两种典型组合是"写回 + 写分配"和"写直达 + 非写分配"。

## 多级 Cache
为了在容量、速度与成本之间取得更好的平衡，现代处理器采用多级 Cache。L1 最靠近 CPU，容量最小（通常 32KB~64KB）、速度最快（访问延迟 1~4 个周期），通常分为指令 Cache 与数据 Cache 两部分以适应流水线的取指与访存需求；L2 容量较大（256KB~数 MB）、延迟十余个周期，一般为统一 Cache；L3 容量更大（数 MB~数十 MB）、延迟更高，通常由多个核心共享。多级 Cache 的缺失代价是逐级计算的：在串行访问模型下，平均访问时间 = t_L1 + (1 − h1)·t_L2 + (1 − h1)(1 − h2)·t_mem。多级设计的意义在于把 L2 作为 L1 缺失的"缓冲"，使绝大多数 L1 缺失只付出 L2 的延迟，而不是主存的延迟。

## 虚拟存储器的基本概念
虚拟存储器是主存-辅存层次的实现方式：借助操作系统与硬件的配合，把辅存（磁盘或 SSD）当作主存的"后援"，使程序员看到一个远大于实际主存容量的地址空间。程序使用虚拟地址（逻辑地址）编写与编译，运行时由硬件与操作系统把它转换为物理地址（实地址）。虚拟存储器的主要作用有三个：扩大可用的地址空间、支持多道程序之间的地址隔离与保护、以及实现程序的重定位与共享。它与 Cache 在原理上高度相似，都是利用局部性把活跃数据放在快速层，但管理主体、交换单位与缺失代价差异很大。

## 页式虚拟存储器与页表
页式虚拟存储把虚拟地址空间与物理地址空间都划分为固定大小的页（如 4KB），以页为单位在主存与辅存之间交换。页表是记录虚页到实页映射关系的数据结构，每个进程一张，由页表基址寄存器指向其起始地址；每个页表项包含实页号以及若干标志位：有效位（该虚页是否已调入主存）、修改位（是否被写过，决定换出时是否需要写回辅存）、访问位（供替换算法参考）、保护位（读/写/执行权限）。页表的容量可能很大，例如 32 位虚地址、4KB 页、每项 4 字节时，单级页表就有 2^20 项共 4MB，因此多采用二级或多级页表，只把用到的部分装入主存。

## 地址转换过程
页式虚拟存储的地址转换步骤是：把虚拟地址拆成"虚页号 + 页内偏移"两部分，偏移位数等于 log2(页大小)；用虚页号查页表得到实页号；把实页号与页内偏移拼接，即得物理地址。整个过程由 MMU（存储管理单元）用硬件完成。若页表中该页的有效位为 0，说明缺页，硬件产生缺页异常，由操作系统的缺页处理程序把该页从辅存调入主存（主存满时按替换算法选一页换出，若该页被修改过还要写回辅存），更新页表后重新执行引起缺页的指令。因此一次访存可能出现三种情况：页表命中且数据命中（最快）、页表命中但 Cache 缺失（需访问主存）、缺页（需磁盘 I/O，代价极高）。

## TLB 与多级页表
由于每次访存都要先查页表，页表本身又存放在主存中，一次数据访问可能变成两次甚至更多次访存，效率无法接受。解决办法是设置快表（TLB）：把最近使用的页表项放在一个小容量的高速相联存储器中，通常只有几十到几百项，采用全相联或组相联映射。地址转换时先查 TLB，命中则直接得到实页号，无需访问主存中的页表；TLB 缺失时才去查页表，并把结果填入 TLB。TLB 的命中率通常高达 99% 以上，因此平均转换开销很小。多级页表则用虚拟地址的高位分段逐级索引，使每级页表都可以按需分配，从而减少页表本身占用的主存空间；代价是一次 TLB 缺失可能需要多次访存才能取到页表项。

## Cache 与虚拟存储器的对比
两者都是基于局部性的层次化存储技术，但存在系统性差异。目的上，Cache 解决 CPU 与主存的速度匹配问题，虚拟存储器解决主存容量不足的问题。交换单位上，Cache 以块为单位（几十字节），虚拟存储器以页为单位（几 KB）。映射方式上，Cache 有直接、全相联、组相联三种，虚拟存储器因缺失代价极高而采用全相联（任一虚页可映射到任一实页）。未命中代价上，Cache 缺失只需几十个时钟周期，缺页处理要访问磁盘、代价达百万个时钟周期，因此替换算法宁可选得简单也要避免频繁换页。管理主体上，Cache 完全由硬件自动管理、对程序员透明，虚拟存储器由硬件与操作系统共同管理。地址上，Cache 工作在物理地址空间，虚拟存储器工作在虚拟地址空间。

| 对比项 | Cache—主存 | 主存—辅存（虚拟存储器） |
| --- | --- | --- |
| 目的 | 解决速度匹配 | 解决容量不足 |
| 交换单位 | 块（16~64B） | 页（4KB 左右） |
| 映射方式 | 直接、全相联、组相联 | 全互连（全相联） |
| 未命中代价 | 几十个时钟周期 | 缺页处理，约百万个时钟周期 |
| 管理方 | 硬件自动完成 | 硬件与操作系统共同完成 |
| 地址空间 | 物理地址 | 虚拟地址 |

## 常见易错点与小结
常见错误包括：计算地址划分时把组号与行号混淆（组相联用组数取对数，直接映射用行数取对数）；忘记有效位与脏位占用标记阵列空间；认为"Cache 容量"等于芯片总面积（标记载荷通常使实际面积比数据阵列大几个百分点到十几个百分点）；把 Cache 缺失与缺页混为一谈；以及在多级 Cache 平均访问时间公式中漏掉逐级缺失率的乘积关系。本章总结出一条统一主线：层次化存储的性能取决于命中率与缺失代价的乘积，提高命中率要靠容量、映射方式与替换算法，降低缺失代价要靠多级结构与提前调块；Cache 与虚拟存储器正是这条主线在"速度"与"容量"两个方向上的具体实现。
