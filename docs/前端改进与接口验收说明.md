## 模型接入

课程问答原先只整理本地摘录，现调用现有 aiService.generateJson。实际模型取自服务端 LLM_TUTOR_MODEL / LLM_MODEL 和 LLM_API_URL；使用已有 Qwen 本地配置时即调用该服务。证据不足不调用模型；模型失败、引用不存在或不支持回答时，返回课程摘录并标记 deterministic_fallback。模型内容通过现有引用检查后标记 rag_model。

引用检查属于结构和文本支持度检查，不等于教学正确率保证。新问答入口检索公共课程库；个人资料与错题融合继续使用“助手”的已有链路。

## 本机检查

检查脚本现已改为先检查依赖，完整时跳过安装；缺失时停止加载该前端目录依赖的 Node 进程，再用 npm install 修复。不会无条件执行 npm ci 删除整个依赖目录。npm 缓存设在项目的 .ai-cache/npm。检查过程中若停止了前端，完成后需重新启动全套服务。

1. 双击“检查前后端并构建.bat”；成功后最后显示 PASS，失败时看第一条错误。
2. 双击“启动LearnMate本地AI全套.bat”，等待模型 API 与后端完成启动。
3. 学生端 http://localhost:5173；教师端 http://localhost:5174。登录自己的账号。
4. 切换课程提问：有资料显示引用，无资料提示证据不足。资源生成后检查来源与复核状态。
5. 教师按“班级 → 成员 → 查看学情 → 资源干预”进入，核对学生和路径版本。

## 共享方式

共享包包含完整源码和最终 LoRA 适配器，不是免安装软件。不含 .env、node_modules、数据库、个人上传文件、日志、下载缓存、基座权重、中间 checkpoint 或旧 dist。接收者需安装 Node.js 24、MySQL 并配置自己的 .env；模型需已有 Qwen 基座与兼容推理环境，或另配可访问的模型 API。同学电脑的 localhost 不会连接到你的电脑。

GitHub Desktop 提交源码和 lockfile；压缩包用于文件交接，已加入忽略规则。不要提交本机 .env；无需重新 git init 或丢弃他人的修改。
