## 二、本次修正了什么

### 1. 知识点标注错位（主要修正）

原题库的 `knowledge_point` / `chapter` 标注**大面积错误**，典型错位：

| 题号 | 题面真正考的 | 原标注 |
|---|---|---|
| `OS_BASE_005` | 临界区 | 内存管理 |
| `OS_BASE_008` | 银行家算法 | 内存管理 |
| `OS_BASE_011` | 请求分页 | 同步与互斥 |
| `OS_BASE_015` | 文件目录 | 信号量与死锁 |
| `OS_BASE_063` | 文件的物理结构 | 进程状态 |
| `CN_BASE_014` | 拥塞控制 | DNS与HTTP |
| `CN_BASE_008` | 子网划分 | TCP连接管理 |
| `DS_BASE_010` | 图的遍历 | 二叉搜索树 |
| `CO_BASE_014` | 总线仲裁 | 输入输出系统 |

成因是**按批次模板批量套标签**：例如 `OS_BASE_056~070` 共 15 题里有 11 题被统一标成「进程状态」，
而内容依次是页表、抖动、Clock 置换、文件物理结构、SPOOLing、时间片轮转、内部碎片、生产者消费者、死锁条件、中断、UNIX 文件系统 —— 单点覆盖了 8 个不同知识点。

**修正方式**：由各学科教研人员按题干与选项内容**逐题重新判定**，全部改成 `knowledge_points` 表里的**规范知识点名**，
`chapter` 同步改成该知识点在图谱中的章节。

| 学科 | 总题数 | 需修正 |
|---|---|---|
| 操作系统 | 54 | 54（100%） |
| 计算机网络 | 54 | 54（100%） |
| 计算机组成原理 | 70 | 66（94%） |
| 数据结构 | 54 | 53（98%） |
| C 语言程序设计 | 40 | 35（88%） |
| **合计** | **272** | **262** |

同时同步修正了 **246 处解析文本、114 处提示、21 处标签**里嵌入的旧标注名
（因为解析模板里写着「本题围绕&lt;知识点&gt;，判断时应先…」，标注一改就必须跟着改），
以及 **13 处解析中引用的选项原文被截断**的问题。

### 2. 答案键复核与错误修正

对全部 273 道题做了**逐题独立重解**（不看库里的答案，自己算完再比对），五学科审计结果：

| 学科 | 题数 | 答案键错误 | 定义歧义 | 结论 |
|---|---|---|---|---|
| 计算机组成原理 | 70 | **0** | 0 | 18 道计算题全部脚本复算通过（补码/符号扩展/IEEE754/小端/Cache 映射与 AMAT/变址寻址/流水线时钟/总线带宽/平均CPI） |
| 计算机网络 | 54 | **0** | 0 | RIP 15、以太网帧 1518、TCP 确认号 ±1 等易错点均写对 |
| 操作系统 | 54 | **0** | 2 | 2 处口径问题见下 |
| C 语言程序设计 | 40 | **0** | 1 | `C_BASE_032` 双正确答案，见下 |
| 数据结构 | 54 | **1** | 3 | 1 处答案键写错 + 3 处口径/题干问题，见下 |
| **合计** | **272** | **1** | **6** | |

**结论**：题库**答案层质量明显好于标注层**（标注 96% 需改，答案键只有 1 处确凿错误）。共修正 **2 处答案键** + **5 处题干/选项**：

| 题号 | 题干 | 原答案键 | 修正为 | 说明 |
|---|---|---|---|---|
| `DS_BASE_048` | `a+b*c` 的后缀表达式 | B（`ab+c*`） | **A（`abc*+`）** | 确凿错误。`ab+c*` 是 `(a+b)*c` 的后缀式。**原解析自己的推理已得出 `abc*+`，却把答案键写成 B**，解析与答案键直接矛盾 |
| `DS_BASE_049` | n 个节点的完全二叉树高度 | C（`⌊log₂n⌋`） | **D（`⌈log₂(n+1)⌉`）** | 口径问题。国内教材主流按**层数**定义高度（严蔚敏《数据结构》、王道 408），高度 = `⌊log₂n⌋+1 ≡ ⌈log₂(n+1)⌉`（选项 D）；`⌊log₂n⌋`（选项 C）是「按边数计」的 CLRS 口径 |
| `DS_BASE_041`、`DS_BASE_042`、`C_BASE_032`、`OS_BASE_066`、`OS_BASE_070` | 见下方第 3 节 | 不变 | 不变 | 题干/选项不严密导致两个答案都成立，通过补足题干限定或替换干扰项修正 |

答案键修正时，解析里的选项字母引用也一并跟着改（`再把C项与定义…` → `再把D项与定义…`）。

## 五、仍需教研侧定夺的问题（本次未擅自改动）

### 1. 答案分布严重偏向 A（最影响测评效度）

| 选项 | 题数 | 占比 |
|---|---|---|
| A | 156 | **57.1%** |
| B | 73 | 26.7% |
| C | 37 | 13.6% |
| D | 7 | **2.6%** |

分学科看更极端：计算机网络 54 题无一答案为 D；数据结构 54 题里 A=35、D=1。

**影响**：学生「一律选 A」即可得约 57 分，题库失去测评区分度。

**可行的修法**（机械可验证，但工作量不小）：打乱每题选项顺序，同步重算 `answer` 与解析里的选项字母引用
（解析模板句「再把&lt;X&gt;项…核对」与「&lt;Y&gt;项"&lt;选项原文&gt;"忽略了…」都引用了字母），
并同步重映射 `option_error_types`。因影响面覆盖全部 273 题，建议单独排期。

### 2. 模板化题目没有区分度

`*_BASE_002~020`、`CO_BASE_*` 等约 80 道题是「关于 X 下列说法正确的是」的模板题，
四个选项固定为「需要结合定义、适用条件和典型场景理解 / 只需记住名称 / 在所有题目中都没有边界情况 / 与其他知识点没有关联」，
**答案仅凭选项措辞即可判定，不考查任何学科知识**。建议重写或下架。

### 3. 题干不严密导致多解（5 道，已修正）

原题干缺少限定条件，导致**两个选项在标准教材语境下都成立**。已按「补足题干限定 / 替换干扰项」的方式修正：

| 题号 | 原问题 | 修正方式 |
|---|---|---|
| `DS_BASE_041` | 「单链表中删除已知节点」——「已知」未限定是否已知前驱：仅知待删结点指针 → O(n)；已知前驱或采用「复制后继再删后继」技巧 → O(1) | 题干补充限定：「**若只已知该结点的指针、不知道它的前驱结点**」 |
| `DS_BASE_042` | 「栈可以用来实现？」——答案键 B(递归)，但 A(队列) 同样成立（两个栈实现队列是标准构造） | 题干收窄为「**下列哪种机制的直接实现依赖栈？**」，并把干扰项 A 由「队列」换成「**按下标随机访问任意元素**」（栈做不到，是数组的能力） |
| `C_BASE_032` | 「C 语言函数参数传递方式是？」——A「只有值传递」字面也为真，与答案 C 构成两个正确答案 | 题干改为「**下列说法最准确完整的是？**」，并在解析里说明 A 正确但不完整、C 才点明了「可用指针修改实参指向的内存」 |
| `OS_BASE_066` | 「内部碎片发生在？」——答案键 D(固定分区)，但 A(页式管理) 的页内碎片同样是内部碎片 | 题干限定「**在分区式存储管理中**」，并在解析里说明「页式管理的页内碎片虽也属内部碎片，但不在本题讨论范围」 |
| `OS_BASE_070` | 「UNIX 文件系统采用？」——答案键 D(混合分配)，但按连续/链接/索引三分类口径 C(索引分配) 也成立 | 题干点明结构：「**索引结点把直接块与一级、二级、三级间接块结合使用，这种分配方式属于？**」，并在解析里同时说明两种口径的关系 |

修正后全部通过自检：答案键所指选项与解析里引用的选项字母一致，四选项互不重复，导入 273 题 0 失败。

### 4. 规范知识点清单的缺口（待定夺）

评测过程中发现有几类题在图谱 10 个规范知识点里没有归属，只能就近归类：

- 计算机网络：缺**物理层**（信道带宽、传输速率、光纤等 6 题并入「数据链路层」）、缺**网络安全**（防火墙类题并入「网际协议与子网」）
- 操作系统：缺**中断与系统调用**（2 题分别并入「磁盘与I/O管理」「进程与线程」）
- 数据结构：缺 **B 树 / B+ 树**、**二叉树遍历**、**图的存储结构**（这几题退到父类概念）
- 计算机组成原理：缺**性能指标**（平均 CPI、主频与执行时间 2 题无归属）

**建议**：在 `catalog.json` 里补上这些知识点，否则同类题会持续被强行就近归档。
补完知识点后重跑 `npm run seed:knowledge-graph` 与本命令即可。
