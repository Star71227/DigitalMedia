# AI 助手流式回复与联网组卷

## 页面效果

- “AI 学习助手”通过 `POST /api/chat` 的 NDJSON 流逐步显示模型正文。生成中的内容会标记为“引用尚待最终核验”，通过后端审核并保存后才成为正式回答。
- 模型重试时页面会清空未通过的草稿，并显示“正在修正回答并重新核验引用”。用户可点击“停止生成”。
- 失败消息会区分模型不可用、回答质量未通过和连接中断，不再只显示统一的“回答没有完成”。
- “智能测验”增加联网搜题组卷。后端按学习路径、待复习错题、最近提问、课程资料构造搜索主题，取得网页搜索摘要后让本地模型逐题改编、校验、去重并入库。
- 测验页展示组卷依据、生成题数和联网来源链接。页面明确说明这是依据搜索摘要生成的改编题，不冒充原版真题。

## 运行方式

双击项目根目录的 `启动LearnMate本地AI全套.bat`。应同时保持以下端口可用：

- 学生端：5173
- 教师端：5174
- Node 后端：5800
- 本地 Qwen 模型：8000

代码或 `.env` 修改后需要重新启动整套服务。只刷新网页不会让已经运行的 Node 后端加载新代码。

当前默认联网检索使用 `baidu-html`，不需要搜索 API 密钥；它对中文计算机课程关键词的召回比原来的 Bing RSS 更稳定。搜索摘要只用于选题相关性排序，题干、答案和解析均来自已审核题库。共享部署也可以把 `WEB_SEARCH_PROVIDER` 改为 `generic-json`，并配置 `WEB_SEARCH_API_URL`、`WEB_SEARCH_API_KEY`，接入团队自建的 SearXNG 或其他返回 JSON 的搜索服务。

## 真实性边界

搜索结果只作为命题证据和来源线索。系统不会把摘要改编题宣称为原版真题，也不会把未实际访问、未验证全文的来源标记为已核验真题。最终答案仍应由教师或课程资料复核。

## 验证

新增测试覆盖 UTF-8 分片解码、流中断、短回答、变式题题量、题源编号、完整流式响应和结构化错误。前端 TypeScript 检查和相关后端测试均通过。
