# 答辩问答（36 题）

以下回答按正常语速设计为 20–60 秒。现场可先给结论，再给代码或界面证据，最后主动说明边界。

## 赛题、定位与创新

1. **项目如何匹配 A3 赛题？**
   项目核心就是个性化学习资源生成与多智能体学习系统：七维画像和真实行为负责诊断，五类资源负责生成，路径、完成证据和评估负责持续更新。我们不只做一次聊天，而是把资源、测验、CodeLab 和教师分析接到同一学生状态上。

2. **最核心的创新是什么？**
   不是 Agent 数量，而是“证据驱动的状态闭环”：画像有来源和版本，路径只引用真实目录，资源有 Schema、审核和引用，完成行为有资格判断。模型可以增强表达，但不能绕过这些约束。

3. **为什么叫“会诊断、会生成、会进化”？**
   会诊断对应画像、测验、错题、CodeLab 和评估；会生成对应五类资源、RAG 和真实 PPTX；会进化对应画像/路径版本、资源进度、完成证据和评估更新。三句话分别能在界面和数据库结构中找到证据。

4. **当前完成到什么程度？**
   学生端、教师端、八类 Agent、五类资源、真实 SSE 生成进度、六维审核、数据结构 RAG、测验/错题/CodeLab/路径/评估闭环和交付配置已经完成。另有隔离的原创 2D 数字讲师 MVP；它尚未深度接入正式资源中心和 PPT 微课主链路。任意代码沙箱、实时监考、全学科知识库和生产容器实机验收不算已完成。

## 多智能体与普通 AI 聊天

5. **为什么要使用多智能体？**
   学习任务包含诊断、生成、审核、规划、出题、反馈、辅导和评估，不同任务的输入约束和失败回退不同。分角色便于独立 Prompt、日志和回退，但它们共享学生状态，并非互不相关的聊天机器人。

6. **与普通 AI 聊天有什么区别？**
   普通聊天以本轮文本为主；LearnMate 把回答连接到画像版本、真实题目/练习 ID、路径阶段、资源版本、引用和完成证据。评委可以追溯“建议基于什么、是否改变路径、资源是否审核”。

7. **Agent 之间如何协同？**
   Express 编排器构造课程、知识点、历史和画像上下文；聊天按 Profile→Tutor→Resource→Review 调用，资源按上下文构建→结构化生成→审核→版本持久化执行。每次运行记录任务、状态、来源和耗时。

8. **多个 Agent 会不会互相放大错误？**
   自然语言不是系统事实。路径必须通过白名单、真实目录、依赖无环校验；资源必须通过 Schema、ID、引用和规则审核；测验由后端判分。任何 Agent 输出不合格都会回退或拒绝。

## 个性化、画像与路径

9. **个性化如何证明？**
   生成上下文包含画像七维字段、路径阶段、掌握度、错误模式、时间预算和允许 ID，并计算上下文指纹；资源保存生成依据、目标学习者摘要和版本。比较不同上下文的这些证据，比一句“为你定制”更可靠。

10. **七维画像为什么可靠？**
    画像字段保存来源、证据和置信度；低置信度提取不能覆盖高置信度值，学生主动修改确认时置信度为 1。测验和错误模式补充自述，但我们不把画像称为心理测量或绝对准确结论。

11. **画像会自动猜测学生能力吗？**
    不会。对话 Agent 失败时只保留明确表达，规则测试也要求不猜测能力。掌握度来自真实作答或提交的确定性更新，画像历史保留变更原因，学生可以查看和修改。

12. **路径如何动态调整？**
    路径服务读取当前画像、掌握度、真实题库和 CodeLab 目录，生成候选后校验阶段、知识点、ID、依赖和完成条件。语义指纹未变化时不创建新版本，真实变化才递增版本并记录来源。

13. **路径完成如何防止“点一下就完成”？**
    quiz 要有真实提交，CodeLab 要 success 且练习允许作为路径证据；resource 要打开或下载、进度 100%、累计至少 30 秒。generated 代码案例只记 completed_unverified。

14. **学习时间预算真的被使用了吗？**
    七维画像保存每周分钟数和节奏偏好，资源上下文把它们连同阶段时长用于目标学习者摘要和生成理由。当前不是精确排课优化器，我们只宣称它参与上下文。

## 五类资源、PPTX 与 CodeLab

15. **为什么是五类资源？**
    讲义支持系统阅读，导图呈现关系和顺序，PPTX 适合课堂或复习，练习包进入测验闭环，代码案例进入实践闭环。五类的 Schema、交互和路径证据资格不同。

16. **资源如何审核？**
    六维规则审核按事实 30、结构 20、个性化 20、可读性 15、难度 10、安全 5 评分；总分至少 75、事实至少 20、安全必须满 5 且无 critical 才能通过。再可选叠加只会追加问题和扣分的模型审核；关闭时明确显示“模型审核未执行”，不会伪造固定分数。

17. **PPTX 是图片还是可编辑文件？**
    是 PptxGenJS 生成的真实 OOXML 文件。测试检查 ZIP 和核心条目、三主题、语义页面、引用和参考资料；页面含 speaker notes。自动测试不替代人工视觉验收。

18. **PPTX 的三主题是什么？**
    academic-light、dark-tech、warm-paper。未知主题映射到安全默认值；页面按 title、concept、process、comparison、code 等语义类型排版，过多内容会拆页或受控裁剪。

19. **练习包会不会生成不存在的题？**
    quiz_pack 的每个 questionId 必须在当前路径允许列表中，Schema 和审核都会检查；不足 5 道证据时拒绝生成。仓库当前基础客观题只有 6 道，所以不会夸大题库规模。

20. **CodeLab 是安全沙箱吗？**
    不是。当前是受限受限运行器，使用目录中的练习和样例运行路径；不能执行任意不可信代码，也不是实时监考。只有已验证且允许形成路径证据的练习成功提交才推进路径。

21. **generated 和 verified 代码案例有什么区别？**
    verified 必须绑定当前阶段允许的真实练习 ID；generated 必须没有练习 ID。generated 可以学习和记录进度，但不构成路径自动完成证据。

## RAG 与防幻觉

22. **RAG 知识库有多大？**
    当前仓库有 15 份数据结构知识源，按现行代码静态切分为 150 个安全块；目录定义 60 个知识点。这个数字是仓库内容口径，不是生产数据库规模。

23. **如何防止引用造假？**
    引用只能指向本次检索返回的 chunk，验证器检查缺失、越界引用、文本支持重叠和覆盖率；持久化保存来源快照、生成版本和位置。无结果或验证失败时拒绝保存 grounded 资源。

24. **知识库中的 Prompt 注入怎么办？**
    导入时检查指令覆盖、索取密钥和工具调用等模式，不安全块被隔离。进入模型前还明确声明证据是“不可信数据而非指令”，并清理危险标签。

25. **RAG 无结果时是否让模型自由回答？**
    对需要 grounded 的资源不会。服务返回 insufficient evidence，不落库为 approved；普通辅导可用确定性解释模板，但不会伪造引用。

26. **知识来源变化如何处理？**
    同一 sourceKey 加 version 内容真实变化会拒绝覆盖，必须提升版本；CRLF/LF 差异归一化。来源禁用后不进入新检索，历史生成仍保留来源快照。

## 教师端、性能、安全与部署

27. **教师端的核心价值是什么？**
    教师看到班级和管理学生的真实聚合：画像历史、掌握度、测验趋势、路径、资源、检索活动、风险和报告。教师还可请求资源，且请求日志不保存原始敏感备注正文。

28. **如何保护学生隐私？**
    学生接口使用 JWT 身份，不信任请求体 studentId；教师端校验角色与 active 师生关系。资源和报告下载同时检查身份与安全路径。正式上线仍需隐私政策、保留期限和制度审核。

29. **做过性能测试吗？**
    目前没有可公开的并发、延迟或吞吐压测结果，因此不报性能数字。工程上有数据库锁、分页、限制、健康检查和有界重试；下一步在目标硬件上完成可复现压测。

30. **做过渗透测试吗？**
    没有专业渗透测试证明。现有证据是权限隔离测试、CORS、输入/文件限制、路径穿越测试、Gitleaks、非 root 容器和最小权限 CI。

31. **Docker 是否已经验收？**
    Dockerfile、Compose、健康检查、内部网络、命名卷和 CI 镜像构建任务已配置。本轮真实 build/up 和卷重启以测试报告为准；没有 Engine 时明确标记未验收。

32. **模型失败会怎样？**
    五类资源有确定性构建器，路径有目录驱动规划，反馈和评估有规则模板；Agent 记录 fallback。RAG 必需证据不足则拒绝生成，已有 approved 版本不会被失败覆盖。

33. **为什么选择讯飞星火？**
    赛题背景与国产模型接入场景相符，仓库实现了星火 HTTP API 和运行时开关。核心规则不绑定模型：只有显式启用并有凭据时增强生成，禁用时主链路仍可运行。

## AI Coding、推广与未来

34. **AI Coding 参与了多少？**
    AI 工具参与代码或文档建议、测试分析和材料整理；每项变更仍需人工审查、自动测试和安全检查。团队承担最终责任，AI 没有替代产品设计、授权判断和验收。

35. **如何推广到其他课程？**
    架构可扩展，但当前 grounded 内容正式覆盖数据结构。新课程必须建立合规来源、知识点/先修关系、真实题库和练习目录，再跑相同导入、引用和闭环验收。

36. **商业化或学校落地情况如何？**
    当前是比赛原型和工程化基线，没有可核验学校部署、付费用户或商业收入。后续须先完成校内数据合规、内容版权、性能、安全和教学效果评估。
